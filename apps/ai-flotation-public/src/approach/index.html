How it works

Six stages. The order is the product.

Each stage produces something the next one needs. Nothing skips ahead because a build happened to finish.

01 · Discover
We watch the workflow as it is, including the exceptions people have stopped mentioning because they became normal. The output is a description you recognise. If you do not recognise it, we have not finished.
02 · Design
Requirements and acceptance criteria, plus the decisions that shape them. Each decision records the question, the options, the recommendation and the reasoning, so a choice made in week two is still legible in month six.
03 · Build
Agents build against the contract from stage two, inside declared limits. Every run is recorded: what it touched, what it produced, and under whose authority.
04 · Prove
Evidence is recorded against the requirement it proves. A check that was not run is recorded as not run. It never quietly becomes a pass.
05 · Release
The gate assembles what is required for this kind of project and refuses until it is satisfied. A regulated project carries the full set; an internal tool carries less. Requirements can be waived — on the record, with a written reason, and shown to you as waived rather than passed.
06 · Operate
Once live, the system watches itself: errors, latency, cost, usage, data quality. A signal can propose a defect, an optimisation or a new requirement. It cannot make one. A system that changes production in response to its own telemetry has nobody to ask when the telemetry is wrong.

Where this differs from most AI delivery. The gates are real code that returns a refusal, not a policy in a document. That is also why they occasionally stop us.
