## What "zero" means here

`run_count` is incremented only by `instrumentCronJob` or by a runner that updates its own row. `aiOpsScheduler.ts:485-489` wraps a runner in `instrumentCronJob` only when its name is in `UNINSTRUMENTED_AGENTS`; the two Director entries are not in that set and `directorActions.ts:70-76` (`runDomainFlag`) never touches the `AiAgent` row. They run every morning at 06:10 and 06:30 Chicago and leave no trace on success (the dead-letter wrapper records failures only). So for those two rows, zero is **zero evidence**, not zero runs. For the remaining five, zero is zero: no scheduler entry or dispatcher calls them.

## Consequence for the coverage contract

The Curriculum domain's *live* legacy behaviour today is two silent daily crons and one disabled architect. There is no external side effect anywhere in the set (no email, DM, Basecamp, GitHub or payment path; the discovery report confirms per file). The regression contract for this employee is therefore small: nothing a student or staff member receives today would stop, because nothing in this set sends anything.
