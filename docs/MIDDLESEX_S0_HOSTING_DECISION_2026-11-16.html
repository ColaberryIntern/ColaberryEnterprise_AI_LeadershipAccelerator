Why this has to be decided now, and why not the box we already have

The December pilot has two project managers and Jamie writing to the same requisition from three machines. Today's prototype is one HTML file that keeps its state in the browser, so it cannot run the pilot no matter how good it looks. A shared database and a hosted app are December dependencies, not January ones, and nothing from S1 to S7 can start until S0 is settled.

Not the Hetzner server. That box runs the Accelerator, every agent, and a Postgres cluster holding everything else we have. A client's contract values would sit beside all of it. Two deploys there have already raced into a Cloudflare 521, and a client security review would have to answer for a shared host. A managed platform gives the pilot its own database, its own backups and its own deploys.

Its own repository, controlled from Enterprise

All of the product lives in its own repo (for example ColaberryIntern/aia-billing): code, schema, tests and deploy config. Enterprise is the control panel, not the container:

  • Deploys: a merge to its main auto-deploys on Render. Enterprise can trigger a deploy and read its status through Render's API.
  • Health: the product exposes /health, which Enterprise polls and shows alongside everything else.
  • Work: tickets stay on this Basecamp board, with each PR paired to its ticket.
  • Data: any exchange goes through a small token-protected API. The product's database is never shared.

This is the training.colaberry.com pattern we already run. It keeps deploys out of the Accelerator merge queue, and a client security review covers one small codebase, not ours.

Colaberry owns it. This is the reframe still owed to Jamie (she was told on 26 Oct that she would own a repo). She should hear it from Ali, separately from any pricing talk.
