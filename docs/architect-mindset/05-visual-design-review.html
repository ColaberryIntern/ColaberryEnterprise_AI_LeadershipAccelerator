00What this reviews

Three surfaces, one experience. These are not three interchangeable mockups; they are the three distinct places the curriculum type appears in the live platform, each with its own responsibility.

1 · Thumbnail

The classroom-feed tile poster. Job: be recognizable at small size and signal architecture + time + reflection without robots or sci-fi.

2 · Right-side pop-up panel

The ~440px expanded card drawer. Job: orient, enter, show progress, resume, and confirm completion. It never tries to fit the full simulation.

3 · Full Workspace

The full-page runtime. Job: host the entire cinematic experience, interview, consequence reveal, re-architecture, receipt, decision record, and backend-validated completion.

How they relate

Tile → opens the Panel → "Enter the Time Machine" opens the Workspace. The Panel and Workspace read/write the same backend state, so progress and resume are consistent across both.

Full specifications: Product · Curriculum (Wk 0-12) · Experience design · Technical architecture · Compression & scoring · Implementation & approval plan · Test plan · Decision log · Canonical decisions.

01Design 1 — Thumbnail

Shown at true timeline-card size on both feed themes, at mobile size, as a full-bleed hero, and as the deterministic template fallback. The production asset is a real gpt-image-2 image (the scene prompt is included in the prototype); this is the art-directed reference.

Design 1 — live prototypeprototypes/thumbnail.htmlOpen ↗

Art direction

  • Blueprint-ring aperture (a time-machine portal) receding into depth, single coral point of light at the decision moment.
  • Faint isometric system map + drafting grid = "system", not "robot".
  • Horizontal time dial: BEFORE · AFTER · FUTURE.
  • Design-E only; one coral accent; no neon/glitch/game-UI/AI-brain.

Accessibility

  • Text is not load-bearing (title/label live in the tile chrome as real DOM text); the poster carries only a descriptive alt.
  • Wordmark > 12:1 contrast; coral never the sole meaning carrier.
  • Baked dark background reads on light and dark feeds; verified legible at 190px.

Its responsibility is orientation, entry, progress, resume, summary, and completion confirmation, not the full simulation inside a narrow column.

03Design 3 — Full Workspace

The complete experience. Walk it with Continue, or use the dashed buttons in the top bar to jump straight to the four states the gate requires: required-unanswered, custom-answer, consequence-reveal, and completed. The Reduced motion and Dark toggles are in the top bar; Exit demonstrates the unsaved-progress guard.

Design 3 — live prototypeprototypes/workspace.htmlOpen ↗ (best full-screen)

Regions

  • Top bar: series, week, progress, save status, reduced-motion, theme, exit.
  • Left rail: the 10 stages with done/active/locked states.
  • Center stage: the dark cinematic "dream" (tunnel, blueprint drift, time dial) that changes per stage.
  • Right insight rail: the Architect Interviewer, the Mindset Ledger, the Architect Radar.

Contains

  • Request → First Decision → System Zoom-Out → Interview (MC + custom + required validation).
  • Consequence Simulator (lighting shift + Consequence Horizon chart).
  • Interview Part Two + Before-vs-After comparison.
  • Re-Architecture, Experience Receipt, Architect Decision Record, Project Transfer.
  • Backend-validated completion (14 gates) + the shared .ss-complete-btn.

Design decision: dark stage inside light chrome

The central stage is always the dark cinematic dream; the surrounding chrome follows the platform light/dark theme. This delivers the cinematic impact the brief asks for while honoring "default to the platform's light theme" and keeping the portal consistent for an executive audience (DL-013).

06State model

24 backend-authoritative states (canonical §4). The prototype's stage nav is the visible projection of these. Draft states autosave; only the final gate flips to completed.

not_started → arrival → request_viewed → first_decision_draft → first_decision_submitted → zoom_out_* → interview_part_1_* → architecture_selected → consequence_* → interview_part_2_* → rearchitecture_* → receipt_unlocked → adr_generated → project_transfer_* → evaluation_pending → evaluation_complete → completion_eligible → completed  (↘ evaluation_failed_retryable → retry)

The three panel states (empty / in-progress / completed) and the four demonstrated workspace states (required-unanswered / custom-answer / consequence-reveal / completed) are all slices of this machine.

07Responsive, accessibility & motion

Responsive

  • Thumbnail verified at 190px (mobile) to full-bleed hero.
  • Panel: desktop ~440px, tablet ~380px, mobile full-width (toggles in-prototype).
  • Workspace: 3-column desktop → collapsed icon-rail + hidden insight rail on tablet → single-column stacked on mobile.

Accessibility (WCAG 2.1 AA target)

  • Keyboard nav + visible focus rings on every control.
  • Required-state announced (not color-only): banner + text + invalid outline.
  • Charts have text equivalents; state never conveyed by color alone.
  • Exit dialog traps + restores focus; Escape closes.

Motion

  • Tunnel + blueprint drift are subtle and never obscure reading.
  • Honors prefers-reduced-motion and a manual "Reduced motion" toggle.
  • No flashing; lighting shifts are slow.

Theming

  • Light default; optional dark supported across all three surfaces.
  • Cinematic stage stays dark by design (DL-013); chrome follows the theme.

08Data dependencies

  • Scenario — timeline_cards.metadata.architect_scenario (Week 0 hand-authored; Weeks 1-12 generated against WEEK CONTEXT). Drives every screen.
  • Experience state — timeline_card_progress.student_progress (the 24-state machine + interview answers + decisions + drafts). Powers resume, progress, before-vs-after.
  • Mindset Ledger — derived from the enrollment's architect_mindset progress rows (right-rail ledger + Experience Mountain).
  • ADR — PortfolioArtifact kind:'architecture_decision'. Portfolio-eligible.
  • Readiness — existing runtime readiness snapshot (workspace footer, unchanged).

No new database table and no schema migration for Week 0 (canonical §6.1; technical architecture §3).

09Open questions for approval

  1. Thumbnail identity — approve bi-hourglass-split + the portal-aperture scene, or steer the art direction (DL-004).
  2. Distinct tile visual — approve a new kind:'timemachine' gradient/icon, or reuse an existing reading visual.
  3. Cinematic-stage / light-theme balance — confirm the dark-stage-inside-light-chrome resolution reads on-brand (DL-013).
  4. Radar vs score axes — accept the 10-axis comprehension radar over the 8 graded dimensions (DL-012), or align to one taxonomy.
  5. Instructor review — confirm AI-only for Week 0/1 (DL-011), revisit at the Weeks 2-12 gate.

10Recommended design decision

Adopt all three surfaces as shown, as one cohesive visual system.

The recommendation is a single design language: the Design-E palette, the blueprint-aperture + time-dial motif, and Roboto/Roboto Mono, applied consistently across tile, drawer, and workspace, with the cinematic dream contained to the workspace's central stage. This delivers the memorable, professional, slightly surreal experience the brief asks for while staying inside the platform's existing look, runtime contracts, and light-theme default. The thumbnail ships as a real generated image after approval; the two frontend surfaces ship as one self-styled renderer wired into the existing drawer and workspace.
