Tables in the aia_billing schema (agreed)

TableHolds
contractsOne per subcontract (the "job" Jamie bills). Links to the platform project id.
sov_linesThe schedule of values: one row per line item, with the scheduled value.
change_ordersApproved changes that add lines or change values.
pay_applicationsOne per contract per billing period: the G702 header. Shown on screen as "Requisition".
pay_application_linesThe G703 rows: % complete, this period, stored materials.
approval_stepsPer-client chain configuration: the seats and their order.
approvalsEach approve or return action, by whom and when.
contract_membersWhich users (PMs) may see each contract. Checked alongside require(): RLS separates clients, this separates PMs.
exportsEvery generated .xlsx and PDF, pointing to the stored file. One approved pay app can be exported many times.
client_settingsRetainage %, the SOV format and other per-client choices.
audit_eventsAppend-only record of every change.
The platform owns clients, users, roles and projects. These tables refer to them by id and never copy them.

Column rules

id uuid primary key; client_id uuid NOT NULL on every table, enforced by row-level securityPLATFORM
The client comes from the signed-in token, never from the browser or the request bodyPLATFORM
Money is numeric(14,2), never a float. Percentages are numeric(5,2), from 0 to 100AGREED
Timestamps end in _at (timestamptz, UTC); dates end in _on; foreign keys are <singular>_id; booleans start with is_ or has_AGREED
Every table has created_at, updated_at and created_by (the user id from the token)AGREED
A submitted value is never overwritten. A revision inserts a new row with revision_no and supersedes_id, so the original stays on recordAGREED
Status is text with a CHECK list: draft, submitted, approved, returned, finalized. No exported status: exports are rows in exportsSAI 23 NOV
Rounding: round half-up to cents per line, then sum. Tested against a real Middlesex requisition so totals match the paper G702/G703 exactlySAI 23 NOV
