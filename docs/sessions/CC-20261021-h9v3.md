    the loser then indexes a column that is not there. `--runInBand` does not help, because the
    conflict is over persistent state. Three lock suites that failed that way pass unchanged with
    their own database. **DATABASE NAMES START WITH `test_` ON PURPOSE:** `multiProjectIsolation`
    refuses to run unless the name carries a `test`/`scratch`/`throwaway` segment — a guard
    against pointing destructive tests at something real — and an earlier `itier_…` name tripped
    it, so the suite failed to run rather than running somewhere it should not. The guard is
    right. **THREE SUITES ARE EXCLUDED BY NAME, WITH EVIDENCE**, mirroring
    `backend/jest.ci.config.ts`'s contract (the list may only shrink, and the runner refuses to
    start if an excluded path no longer exists — observed): `multiProjectIsolation` does not
    terminate when its `SBP_INTEGRATION_DB` opt-in is set (420s on `postgres:16-alpine`, 480s on
    the `pgvector/pgvector:pg16` image its own docblock asks for, alone, where every other suite
    finishes inside 26s); `ensurePublishingSchema` does not terminate against an empty database —
    and on the shared database it *failed in 5.7s*, so the old failure was hiding this; and one
    test of `lifecyclePlanReads` writes a second `published` build_plans row to recreate a legacy
    state the real schema now rejects, which is arguably the point it was making. **A SKIP IS A
    FAILURE** in this job: every suite in the set self-skips when its environment is missing, and
    this job is the environment, so a green run over skipped suites is the thing it was built to
    stop. The runner also caps each suite's wall clock, because jest's own timeout only covers
    work inside a test or hook body — two of these suites block elsewhere and would otherwise
    take the whole job's budget.
  - Notes (what this does NOT do): the job **reports**; it does not gate merges unless branch
    protection is configured to require it, which is the DRI's click. It covers the 25
    `*.integration.test.ts` suites only. A **second** population of about 25 database-backed
