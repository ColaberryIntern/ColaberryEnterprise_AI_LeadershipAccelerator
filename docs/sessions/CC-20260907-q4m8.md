## Unresolved risks

1. **The redirect is committed, not in effect.** refactored.ai's DNS still points at the
   AWS NLB. Nothing changes for a visitor until those two Route 53 records move.
2. **Nobody has confirmed AWS access.** This blocks the DNS move entirely, and it is the
   first thing to resolve. The account is almost certainly Colaberry's, but that is an
   inference, not a login.
3. **The cutover retires ~1,900 pages and a student sign-in.** `/signin`, `/dashboard/`,
   193 `/course/` and 1,715 `/learn/` pages answer 200 today and will 301 away. This is
   the intended outcome; whether anyone still depends on it was not measured and could
   not be from outside the legacy platform.
4. **`login.refactored.ai` (Auth0) is untouched** and keeps running. It simply stops being
   reachable through a link on the redirected hostname.

## Deployment status

**Not deployed.** No DNS moved, no container rebuilt, no production change. Deploying the
nginx image would make `refactored-preview.colaberry.ai` start redirecting; `refactored.ai`
would be unaffected until its DNS moves.
