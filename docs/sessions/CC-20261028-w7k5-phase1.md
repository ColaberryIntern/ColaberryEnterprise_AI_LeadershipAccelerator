## The finding: the identity seeder was not missing, it was refusing

Phase 1 item 2 was written on the assumption that the identity seeder had never run. It runs on
every boot, and it had been refusing all nine agents on every boot for twelve days:

```
[AI Ops] domain agent identity seed failed for MarketingDomainAgent:
  AiAgent.tools_granted is missing or empty — every ticket-creating agent must declare its
  real capabilities in AGENT_REGISTRY before seedAgentIdentity() will register it
  (Agent Ticket Standard Step 4).
```

Nine such lines per restart, measured in the production container.

**Two correct designs deadlocked each other.** `agentRegistry/domainAgents.ts` ships all ten agents
at the Release Zero floor with `tools_granted: []` deliberately — its own header says "no
capability. Granting one is AF7.1 and requires a manager" — and the identity gate refuses any agent
whose tool list is empty. Neither author saw the other.

The seeder is fail-open, so nothing broke loudly. `liveAgentsService` selects `AdminUser` where
`is_ai_operated = true AND agent_id IS NOT NULL`, so an agent with no identity renders an **empty**
console rather than a broken one. Seven interns opened their agent and saw nothing, with no
indication that anything had refused anything.

**The fix was not to grant a tool.** Granting one would also lift the `no_tool_grants` cap in
`effectiveAuthority()`, which forces any capability above `autonomy:R2` back down while grants are
empty — so a cosmetic fix would have quietly raised nine agents' authority ceiling. Tool grants are
the owner's lever by design and by explicit instruction, and a boot-time seeder must never pull it.

So the gate keeps its scope and gains the words its own error message already used: it protects
**ticket-creating** agents.

## Two process notes worth keeping

**A control character got into a regex and no visual check could see it.** A `python` patch wrote a
literal `0x08` BACKSPACE byte where `\b` was intended, so `/^\s*(INSERT|UPDATE|DELETE)\x08/` could
never match and an assertion that should have failed loudly instead reported zero write statements.
`grep` could not show it and the terminal rendered it invisibly; `od -c` found it in one line. Every
file this session touched was then swept for control characters, all clean.

**`includes('UPDATE')` matches `FOR UPDATE`.** A test asserting "this issues no UPDATE" failed
against correct code because the anchor SELECT ends in `FOR UPDATE`. A substring test for a SQL
keyword has to anchor on the statement.

## Verification environment caveat

The declared TypeScript is 5.7.3 and the only install on this machine is **4.9.5**, which this
repo has already been bitten by once: a draft typechecked clean locally on 4.9.5 and failed CI on
5.7.3. The local typecheck here is therefore a weaker gate than CI, and **CI is the authoritative
one** — it also compiles the branch merged with `main`, which a local run cannot.
