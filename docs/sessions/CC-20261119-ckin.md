# Class QR check-in takes name + email on any class

Session: CC-20261119-ckin · Branch: `workstream/class-checkin-name-email` · Base: `origin/main` @ `94f902382`

Ali opened the Session 3 check-in (`/portal/class-checkin/5b8a95b7-1a88-42d5-b257-fd786d071f6e`,
Cohort - November 2026, Tue 2026-11-24 6:30 PM CST, status `scheduled`) and got "We couldn't
check you in". His requirement: "This doesn't work. They should get name and email here for

## Root cause (evidence, read-only)

`accelerator-nginx` access log, 2026-11-19 16:48:31 UTC (10:48 AM CST):

```
GET  /api/portal/sessions/5b8a95b7-…/checkin-info  200 204
POST /api/portal/sessions/5b8a95b7-…/join          404 45
```

45 bytes is exactly `{"error":"Session not found or not joinable"}`, which only
`participantController.ts:403` sends: `joinLiveSession` returned null. The status is fine
(`scheduled` is in `JOINABLE_STATUSES`); the cohort check is what refused. Read-only prod query:
the browser was signed in as `ali@colaberry.com`, whose active enrollment is in Cohort - July
2026, while the session belongs to Cohort - November 2026 and is not an Open House. So
`maySelfJoin` (`liveSessionAttendanceService.ts:64-72`) was false → null → 404 → the page's
generic "join_error" card. A signed-out visitor would instead have been sent to log in, and the
Nov cohort's 83 enrollments are not a real roster, so neither path could track a phone attendee.

The session also had `guest_access` NULL, so the existing Open House guest join (name + email)
refused it too: that door is gated on `guest_access === true` (D4).

## What changed

- **Check-in door for guests on ANY class.** `joinAsGuest(…, { via: 'checkin' })` admits every
  session that exists and is not explicitly closed to guests (`guest_access === false` still
  refuses, per D4). The Open House door (no `via`) is unchanged and still needs `guest_access`.
- **Class window** (`classCheckinWindow.ts`, pure): open from 60 min before start to 30 min after
  end (or whenever `status = live`); `before` earlier; `ended` after, or when completed/cancelled.
  Before: the guest row is captured with `awaiting_class = true` (not counted as present). Open:
  the flag clears (and never sets back). Ended: 410.
- **Attendance tracking.** In the window, an email that matches an enrollment in the session's
  cohort also gets that enrollment's `attendance_records` row via the extracted
  `recordAttendanceRow` (create-only, no downgrade, **no points** — typing an email is a claim, not
  a sign-in). Everyone else is a `session_guests` row, as Open House guests are.
- **Guest pass now carries the whole live loop**: `guest-state` gained `phase`, `prompt`,
  `broadcast_prompts`, `my_pulse`, question `kind`/`theater` (additive; the Open House HTML page
  reads only `question`/`title`); new `POST guest-pulse` and `POST guest-ask` (rate-limited 60/min
  per IP, generous because a room shares one venue IP). The deck's `getLiveState` folds guest
  pulses, questions and participation in.
- **Schema** (`ensureLiveSessionSchema.ts`): `session_guests.awaiting_class BOOLEAN NOT NULL
  DEFAULT FALSE`, `session_guests.pulse_state` (+ CHECK), table `session_guest_questions`.
  Proven in `accelerator_dev1` inside `BEGIN … ROLLBACK`.
- **checkin-info** returns `program_name` (from `canonicalCourse.ts`), `class_window`,
  `start_label` ("6:30 PM CST"), `accepts_guests`.
- **Frontend**: `ClassCheckinPage` orchestrates; the live view moved to
  `CheckinLiveController` (driven by a `LiveClient`, so student and guest share one view);
  `CheckinGuestForm` is the name + email form; `guestCheckinApi` uses its own axios instance so an
  expired guest pass never trips `portalApi`'s 401 sign-out of a real portal session. Footer reads
  `Colaberry {program_name}`.

## Outbound messages

None. The guest join, pulse, ask and vote paths are SQL only: no email, SMS or notification
anywhere in `sessionGuestService`, `sessionGuestStore`, `sessionGuestController`, or the new
frontend files. The raffle remains deck-triggered (Open House decks only), unchanged.

## Open decisions / follow-ups

- An email typed on the form marks that enrollment present (no points). Same trust model as the
  Open House ("take their word for it", 2026-10-29); flagging it rather than adding verification.
- The signed-in join endpoint itself still records attendance for a `scheduled` session at any
  time; the page now simply does not call it before the window. Not changed server-side here.
- Needs merge + deploy; the schema runs at boot via `ensureLiveSessionSchema`.
