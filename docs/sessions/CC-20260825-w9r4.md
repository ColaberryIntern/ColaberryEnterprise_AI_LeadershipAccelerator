### Watcher: Mandrill replaces Gmail as the reply transport, and escalation dedup becomes per-window (2026-08-25)
- [x] **Reversed two watcher behaviours on Ali's explicit ruling: replies now go out through Mandrill rather than the Gmail API, and the "one escalation per thread, ever" guard is now scoped to the current window.**
  - Date: 2026-08-25
  - Session: CC-20260825-w9r4
  - What changed: **`scripts/runInboxWatcher30h.ts`** - `sendReply` no longer calls `sendGmail`. It builds through `buildCampaignMessage` and sends via `createMandrillTransport`/`sendCampaignMessage`, so a watcher reply now carries the same true envelope BCC to Ali, the same `assertSendSafety` gate, and the same tracking suppression as every other student send. The Gmail path was tempting and was explicitly ruled out by Ali on 2026-07-29 and again on 2026-08-25; it is not exempt here just because it was already wired up. New `watcherReplyHtml()` builds the HTML part (required, since `X-MC-AutoHtml: false` means Mandrill will not generate one) and HTML-escapes before converting newlines, because the reply body is composed from live student data. **A reply with no `inReplyTo` is now REFUSED rather than sent.** Gmail threaded for free; Mandrill does not thread on subject at all. **`services/email/campaignTransport.ts`** - `CampaignMessageInput` gains optional `inReplyTo`, `references` and `tag`; `In-Reply-To` and `References` headers are emitted only when replying, so a first-contact campaign message is byte-identical to before. **`services/inbox/watcher/watcherLog.ts`** - `replayWatcherLog(stateDir, escalationsSinceIso?)`. Only `escalatedThreads` is scoped; `sentReplies`, `answeredThreads` and `ownReplyIds` stay cumulative. The asymmetry is the point: an escalation goes to Ali, who is watching the window and wants to hear when a student writes again, while a reply goes to a student, for whom a second copy is a defect. An unparseable bound falls back to the suppressive reading, and an event with an undated `ts` counts, because an escalation that cannot be dated cannot be proven to belong to an earlier window. **`services/inbox/watcher/watcherRun.ts`** - passes `window.state?.started_at` into the replay.
