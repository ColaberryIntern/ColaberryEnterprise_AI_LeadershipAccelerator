  - What changed: the "Read and reply" button in the DM notification email now carries a
    one-click sign-in and lands on the conversation itself. Four parts. (1) A new
    `portal_link_tokens` table (`ensurePortalLinkTokenSchema.ts`, ensured at boot in
    `server.ts`) holding single-use, SHA-256-hashed, 24-hour tokens — separate from
    `enrollments.portal_token`, which is a single column that a notification would have
    clobbered on every message. (2) `portalLinkTokenService.ts` mints and claims them;
    the claim is one `UPDATE ... RETURNING` so the test and the write cannot race.
    (3) `verifyMagicLink` falls back to a link token only when the login token misses,
    so the sign-in path above it is byte-for-byte unchanged and no ordinary login ever
    spends a token. (4) `dmNotificationService.ts` mints one and builds
    `/portal/verify?token=…&next=/portal/messages/<roomId>`, falling back to the bare
    thread path when the mint fails. Frontend: `PortalProtectedRoute.tsx` now carries the
    destination through sign-in via the existing `loginHrefPreserving`, and a new route
    `/portal/messages/:roomId` (`MessagesPage.tsx`, `messages.css`) gives a conversation
    an address for the first time.
  - Verification: frontend `tsc --noEmit` **exit 0**. Backend `tsc --noEmit` reports two
    errors, both `Cannot find module '@anthropic-ai/sdk'`, which is declared in

  - Notes: three facts drove the design and are each worth keeping. The existing portal
    magic link is deliberately REUSABLE for 24 hours ("lets users bookmark their portal
    link"), so a sign-in link in email is not a new posture here — but a notification is
    unsolicited and repeated, which is why these are single use. The single-use check
    carries a 120-second replay grace because the verify page claims from a React effect
    under `<React.StrictMode>`, which double-invokes in development, and a refresh does the
    same in production; without it a sign-in that had just succeeded would show "Invalid or
    expired link". And the destination must be a PATH: `safeNextPath()` rejects any query
    string, so `/portal/today?dm=<id>` would have been silently dropped — hence a real
    route rather than a parameter. The thread renders inline rather than through the chat
    dock because `TodayShell.css` hides `.te-dmdock` under 820px, and an email button that
    does nothing on a phone is not a fix.
    One bug caught in self-review before it shipped: `$grace * INTERVAL '1 second'` is
    ambiguous in Postgres ("operator is not unique"), which would have thrown, been caught,
    and made every one-click link fail silently — invisible to a mocked test. Cast to
    `$grace::int`.
