### Curriculum video health: scrape -> YouTube Data API v3 (2026-08-23)

  - Date: 2026-08-23
  - Session: CC-20260823-w9t5
  - What changed: new `videoLinkApiClient.ts` is the only I/O boundary to `videos.list` (50 ids/call, 1 quota unit/call, IPv4-pinned dispatcher because the prod key is IP-restricted to the host's IPv4 while the host egresses IPv6). `videoLinkClassifier.ts` now decides on `status.privacyStatus`, `status.embeddable`, `status.uploadStatus` and `contentDetails.regionRestriction` instead of a scraped `ytInitialPlayerResponse`. `videoLinkProbe.ts` carries the control video *inside* each request rather than bracketing the batch with two extra calls. - [x] **Make "absent from the API response" a failure, never a pass**
  - Date: 2026-08-23
  - Session: CC-20260823-w9t5
  - What changed: `videos.list` omits ids it cannot return rather than erroring on them, so 47 items back from 50 ids means three videos are broken. `observeBatch` iterates the REQUEST, not the response, and every missing id goes through `classifyAbsent()`, which has no code path to `HEALTHY`. An oEmbed follow-up (quota-free, and a different service from the challenged watch page) refines absence into PRIVATE / REMOVED / UPLOADER_CLOSED; when it cannot answer, the verdict stays actionable as `UNAVAILABLE` rather than silently downgrading to "unknown".
  - Verification: mutation-tested. Rewriting the loop to iterate `res.found` - the naive implementation - makes both headline tests go red with the exact bug signature: `failures` becomes `[]` where `["vid000001"]` was expected, while `healthy` still reads 2. Reverted; both tests green.
  - Notes: This is the 146-false-positive bug with the sign flipped. False positives were loud and caught in a day; a false negative here is silent forever.
