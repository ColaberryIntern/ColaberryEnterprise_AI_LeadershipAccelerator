Teaching guide: a plain-English, slide-by-slide pre-class read for every session

2026-09-03
What changedNew `renderTeachingGuide(spec)` turns the KitSpec an instructor already presents from into a long-form document: every slide in order with what is on screen, what that kind of moment asks of them, their own direction split out of the authored script, the prompt with its expected result / stop condition / rescue, the diagram, and the vocabulary the slide uses. Four new modules under `backend/src/services/classKit/` — `teachingGuideHtml.ts` (composer), `teachingGuideSlides.ts` (one card per slide), `teachingGuideStyles.ts` (CSS + browser runtime), `teachingGuideTerms.ts` (the programme's vocabulary). Wired through `renderSessionTeachingGuide` in `sessionKitDocService.ts`, `handleGetSessionTeachingGuide`, `GET /api/admin/accelerator/sessions/:id/teaching-guide`, and a "📖 Teaching guide (download)" item in the Present split-button menu on `AdminAcceleratorPage.tsx`.
Verification42 new tests green, including a parametrised render of **all 25 sessions** (Orientation + 12 weeks × 2 days). Full backend CI config green. `tsc --noEmit` clean on backend and frontend. Rendered five real sessions and **looked at them in a headless browser**: 43 cards / 19 diagrams for Session 13, 0 mermaid parse errors, 0 page errors.
Notes**It is a projection, not a second copy.** Every line is derived from fields the deck already authors, so a guide cannot drift away from the class it describes, and it picks up any Customize override saved for that session. **Two defects were caught by looking rather than by the suite.** (1) The first workload badge was slides ÷ minutes, which called Week 6's 50-minute guided build "roomy" and its 5-minute opening "dense" — the exact inverse of where a build day runs long; it now counts prompts the room has to get working, and Session 13 correctly reads "8 prompts · crunch" on the guided build. (2) Collapsed cards used `display:none`, so mermaid sized every hidden diagram to zero and a **printed** guide — where the CSS forces all cards open — would have shown raw mermaid source on every page; collapse is now `height:0` + `visibility:hidden` so all 19 diagrams render on load without opening anything. **Why a term dictionary rather than reading the deck:** `KitSlide.definitions` exists and is preferred where present, but only Week 5 authors any (30 entries, every other week zero), so a glossary built from the deck alone would appear on one week and vanish everywhere else.
