### Today: an unpublished card must not reach a student (2026-08-24)

- [x] **One shared servability predicate, consulted by the read side and the write side**
  - Date: 2026-08-24
  - Session: CC-20260824-t8w4
  - What changed: items 1, 2 and 5 of Swati Raman's report share one cause. The Today feed is an append-only snapshot — `today_feed_impressions` freezes a copy of each item and replays it forever, never re-consulting the live row — while `generatedContentRetention.pruneGeneratedContent` flips cards from `published` to `archived` on an 18-day cycle. Its own header comment states the assumption that broke: *"getFeed only returns visibility='published' … so flipping visibility -> 'archived' is the discard."* True of the Classroom, which reads through `getFeed`. Never true of Today, which does not. New `isCardServable()` / `servableCardWhere()` / `SERVABLE_CARD_VISIBILITY` in `services/timeline/curriculumScope.ts` — the leaf module that already exists for exactly this reason and already ships the WHERE/predicate pair idiom (`globalCurriculumWhere` / `isSharedCurriculumProgram`). `globalCurriculumWhere()` is now **built from** `servableCardWhere()` so the two cannot drift. New `unservableCardIds()` in `todayFeedComposer` adds a fourth filter to `buildServed` alongside the three that were already there, batched and fail-soft. `ensureFreshContent` — the one reader on the runtime path that checked existence but **not** visibility, which is why `/content` returned 200 while `dwell` 404'd on the same id in the same second — now applies the same rule. And the **ten** hand-copied `visibility !== 'published'` checks across `runtimeService`, `cardDwellService`, `watchProgressService`, `buildArtifactService`, `fieldGuideService`, `assessmentService` (x2), `architectMindsetService`, `capeCardSkillMappingService` and `workspacePreviewService` now all call the one predicate.
  - Verification: new `todayFeedComposer.unpublishedCards.test.ts` (7 cases) and `curriculumScope.servable.test.ts` (5 cases), **both watched failing first against unmodified `origin/main`** in the control worktree. The headline failure is the bug itself, verbatim: `Array [ "card:card-published-a", + "card:card-archived", "card:card-published-b" ]` — the archived card reaching the student. Draft and scheduled leaked identically (`+ "card:card-draft", + "card:card-scheduled"`), as did a card whose row had vanished. The predicate suite failed with `TypeError: (0 , curriculumScope_1.isCardServable) is not a function`. After the fix: **12 passed / 12 total, 2 suites**. Backend `tsc --noEmit` on pinned TypeScript **5.7.3**: 2 errors, both `Cannot find module '@anthropic-ai/sdk'` in files this change never touches — proven pre-existing by running the identical tsc in the control worktree and getting **byte-identical output**; the package is declared in `backend/package.json` but absent from the junctioned `node_modules` (`zod` present as the control). Frontend `tsc --noEmit`: 10 errors, all `@dnd-kit/*` in two admin files, same control, same result.
  - Notes: **A regression I caused, caught by an existing test, and worth recording because the first design was the tempting one.** `unservableCardIds` originally inferred "row missing from the lookup ⇒ unservable", reasoning that `findByPk` in the action handlers would 404 on it anyway. `todayFeedComposer.suppressionSharedPath` went red: `Expected ["card:kept"] / Received []`. Cause: `Model.findAll` routes through `sequelize.query`, so any test or runtime condition that intercepts or perturbs that layer returns an empty result set, and the inference silently reads that as "every card is dead". Rewritten to **positive identification only** — a card is dropped when a row came back and that row states a non-published visibility; an absent row is UNKNOWN and is KEPT. The asymmetry settles it: keeping a vanished card costs the student a 404 they already get today, while dropping a live one costs them real content for nothing. Two tests now pin the safe direction (absent row kept, empty result set drops nothing). The existing suite passes unchanged, which is the signal that the second design is the right one.
  - Notes: **Read-side only. Nothing is deleted, nothing is unpublished, no impression row is rewritten, and no student progress or points row is touched** — one of the seven tests asserts the append-only log is byte-identical after a page load, precisely so a future change cannot quietly start mutating it. A card that is re-published reappears by itself on the next load. The composer's existing backfill loop replaces each dropped card with a live one, so a student with 20 dead items gets 20 real ones rather than a shorter feed. `unservableCardIds` fails soft **in the safe direction** — on a database error nothing is dropped, so a blip degrades to the old behaviour instead of blanking the student's landing page; that is its own test. **Not fixed, and a separate defect:** the sampled dead items also included `podcast:` / `testimonial:` / `project:` / `community:` refs that 500 rather than 404, because `card_id` is null and `openCard` calls `findByPk` on a non-UUID ref. That is a different cause from visibility and is left for a separate change. Also deliberately not touched: `rehydrateCardItems` still refreshes content without a visibility gate, because the path it serves (`readOnly` "view as") composes through `getFeed` and is already filtered at compose time; adding a second differently-shaped gate there would recreate the drift this change removes.
