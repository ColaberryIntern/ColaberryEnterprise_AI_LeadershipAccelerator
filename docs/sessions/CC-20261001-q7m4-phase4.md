  - Notes: **This module validates a declared mapping; it does not derive one.** `deriveAllocation`
    can read execution class off a task's own attributes because judgment level and data

  - Notes: **`SURFACE_NO_HUMAN_PATH` is the walking-skeleton lesson made enforceable, and it is a
    PROJECT-level rule because no per-task rule can catch it.** A student finished 20 of 20
    stories, platform-verified, and could not run her own product — twelve services unreachable,
    nothing chaining them. Every one of those tasks could have been legitimately headless, so every
    per-task check would have passed. An all-headless project now fails, and a paired control
    asserts one human surface clears it, because otherwise a rule that refused everything would
    pass the first test too.
  - Notes: **The mirror check was deliberate, not incidental.** `SURFACE_TASK_UNKNOWN` refuses a
    binding for a task the graph does not declare. Phase 3's T6 proved the unchecked direction is

    blueprint from a measured 0% to 97.9% automated. A binding for a ghost task would likewise make
    coverage look complete.
  - Notes: **The audience rule has a counterpart that stops it overreaching.** One workspace
    declared both `internal` and `customer` is refused as a collapsed trust boundary, but a project
    with a customer portal *and* an internal queue passes. A test pins that, because a rule
    forbidding it would reject every product with an admin view.
  - Notes: **Recorded, not targeted.** `consolidationAssessment` reports the workspace count and
    never caps it; a test asserts six workspaces are reported rather than refused.
    `reference-fixtures.md` already ruled count is "recorded, not targeted", and a cap would
    silently drop a surface — the source-truncation failure the spec forbids elsewhere.
  - Notes: **Upstream `proposed_surfaces` are reported, never auto-bound.** They are free-text
    model output, so matching one to a workspace is a human judgement. Auto-binding on a string
    match would manufacture the traceability this phase exists to establish honestly, and treating
    an unmatched proposal as an error would push a generator to invent a screen to clear the gate.
    A test asserts an unbound proposal never appears in the issue list.
  - Notes: **Honest limit, stated rather than discovered later.** A workspace binding proves a
    human interacts *somewhere*; it does not prove the task produces user-visible output chained to
    the rest of the workflow. An ingestion task bound to an "Imports" admin screen satisfies every
    rule here. Stronger than the measured-unworkable regex, weaker than "proves a workflow" — the
    stronger guarantee needs Phase 6's release-level view and is open in the register.
