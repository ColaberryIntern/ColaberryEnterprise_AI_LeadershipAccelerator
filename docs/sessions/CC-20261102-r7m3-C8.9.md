## The ticket's premise is false, and the correction changes what the work is

C8.9 opens: *"`org_cohorts` holds zero rows, so a cohort cannot be attached to an
institution."*

Measured read-only against production on 2026-11-02:

- **`org_cohorts` holds 4 rows**, not zero.
- It carries a **unique index** `idx_org_cohorts_unique` on `(org_id, cohort_id)`, declared in
  both the model and the boot DDL, so the link is already idempotent. (`findOrCreate` in
  `adminOrgService.addCohortToOrganization` returns `created: false` on a re-link, and there is
  a test for it.)
- `organizations` holds 10 rows; `org_members` holds 37.
- `POST /api/admin/organizations/:id/cohorts` already exists, is tenant-scoped, and has a
  working admin UI behind it (`AdminBusinessAccountDetailPage`).

So the three acceptance criteria stand as follows.

**1. "A cohort can be attached to an institution and the join is queryable" — already met.**
Demonstrated, not asserted:

| organization | cohort | enrollments reachable | active |
|---|---|---|---|
| Colaberry | Cohort - November 2026 | 63 | 62 |
| Colaberry | Cohort - July 2026 | 56 | 47 |
| Colaberry | Cohort — April 2026 | 14 | 1 |
| Colaberry | AI Internship | 0 | 0 |

**2. "`org_cohorts` holds real rows for at least one real institution" — met only technically,
and this is worth your attention.** All four rows belong to the organization **"Colaberry"** —
our own org — linked by ali@colaberry.com on 2026-10-20. There is no external institution in
that table. The table is not empty, but it is self-referential, which is a softer version of
the very trap the ticket warns about.

**3. "An institutional licence holder can see only their own learners" — NOT met, and not one
query away.** This is the real work, and it is what this change starts.

## Why criterion 3 was harder than it reads

Three findings, in order of severity:

1. **Nothing in the codebase read `org_cohorts` for anything except admin reporting counts.**
   The whole manager-facing surface — `/api/portal/org/{overview,members,members/:id,feed}` —
   scopes through `org_members`, never through the cohort link. So the institution that bought
   the seats could not see them. That is the licence-delivery hole.
2. **There is no "institutional licence holder" principal.** The participant JWT carries
   `cohort_id` but **no `org_id`**. The only org principal is "manager", resolved per request by
   `requireOrgManager` from `organizations.owner_enrollment_id` or an `org_members` row with
   `role = 'manager'`.
3. **Routing learner VISIBILITY through `org_cohorts` would be actively wrong.** `OrgCohort`'s
   own header says a link does not move anyone into the cohort. The largest cohort in
   production, "Explorer - Prospects", holds 425 active enrollments and is a prospect pool —
   scoping by cohort link would assert that 425 strangers belong to an institution.

## What shipped

A manager-facing, org-scoped read of what the institution was actually sold:

**`GET /api/portal/org/cohorts`** → `{ cohorts: [...] }`, guarded by
`requireParticipant, requireOrgManager`, the same as the rest of that block.

New module `backend/src/services/orgSponsoredCohorts.ts` (a sibling, not an addition to
`orgService.ts` — that file is 823 lines, past the 500-line hard ceiling, so per CLAUDE.md the
next change to it must split before adding).

Each row reports `seats_sponsored` (what was sold), `members_placed`, `seats_unfilled`,
plus cohort name, status and start date.

**`members_placed` is the intersection** — people on *this* organization's `org_members` roster
who are enrolled in *that* cohort. It is never the cohort's own enrollment count. That is the
single most important line in the module, and the test suite asserts it both positively and
negatively.

### Security shape, deliberately copied rather than invented

The org is taken from `req.org`, which `requireOrgManager` derives from the **authenticated
enrollment** — never from a route parameter. `orgAuth.ts`'s own header explains why that needs
no tenant filter: *"there is no id for a caller to substitute."* There is deliberately no
`:orgId` variant of this route. Note also that the CI route-auth lint only covers
`backend/src/routes/admin/*`, so it gives this surface no safety net at all; the test is the
net.

### Failure-first

A failed placement read returns `members_placed: null`, not `0`, and logs a structured
`org_sponsored_cohorts_placement_read_failed` with an `error_class`. An institution reading
"0 of your people are enrolled" would act on it; "unknown" is the only honest answer when the
query did not complete. `seats_unfilled` is null whenever either side is unknown — and all four
production links have `seats_sponsored` NULL today, so that is the live case, not a hypothetical.

The arithmetic is in an exported pure function (`composeSponsoredCohorts`) separated from its
queries, so the cases that must return `null` rather than a confident `0` are provable without
a database. The suite includes a CONTROL that a fully-known pair really does produce a number —
without it, a function returning null for everything would pass every other assertion.

One correction against my own earlier reading, recorded because the method matters: I first
reported that `org_cohorts` had no unique constraint, having checked
`information_schema.table_constraints`. That view does not show uniqueness created via
`CREATE UNIQUE INDEX`. `pg_indexes` shows it. Check `pg_indexes` for this question.

## Escalation raised separately — the tenancy layer currently fails open

Not fixed here, because it is a security-posture boundary rather than an implementation
detail. `modules/tenancy/adminScopeBridge.ts` grants `crossTenant: true` to **every admin**
while `tenant_memberships` is unpopulated, by design and in writing ("Only be generous while
the system has none at all"). `tenant_memberships` is empty, so the tenant filter on the admin
organization surface is a no-op today. The ramp is self-closing — the first membership row ends
it for everyone — but until then "an admin can only see their tenant's institutions" is not
true. Written up as `CC-20261102-r7m3-ESC-002`.
