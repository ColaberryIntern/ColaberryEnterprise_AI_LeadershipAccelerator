## The three findings that refuse the exit

Two came from the independent reviewers. **Both were re-verified here against the shipped code
rather than accepted on a reviewer's word**, which is the only reason they are published as
findings rather than as claims.

### B1. No identity this system can mint holds any lifecycle permission

`lifecycleStatus.ts:253` derives the actor's rights with `deliveryPermissionsFor([req.admin.role])`.
`req.admin.role` comes from the admin JWT and is one of `super_admin`, `admin`, `sales`, `ai_staff`.
`ROLE_GRANTS` in `modules/delivery/deliveryRoles.ts` is keyed on the thirteen **delivery** roles.
The vocabularies do not overlap.

**Measured, not read.** `deliveryPermissionsFor` was called in the production bundle against both
vocabularies:

| | |
|---|---|
| The 13 delivery roles (CONTROL) | **180** permissions between them |
| `super_admin`, `admin`, `sales`, `ai_staff` | **0 each** |
| `super_admin` holds `project.read`? | **false** |
| `super_admin` holds `architecture.approve`? | **false** |

The control is what makes the zero a finding rather than a broken lookup. Consequence: every
transition and every change request is an unconditional **403** for every identity in the system,
on all thirteen stages including `discovery`, which needs only `project.read`.

It fails **closed**, so it is a dead contract rather than a safety hazard. But the stage machine,
its thirteen stages and seventeen edges, and the whole review surface are inert for every real
caller.

**Why nothing caught it.** The only test proving a transition is permitted passes `role: 'observer'`
- a delivery role the admin section guard would refuse at the door. The route test stubs the string
`'DELIVERY_OWNER'`, which is the constant's **name** rather than its value `delivery_owner`, and
mocks the service so the derivation never runs.

This also sharpens what the L8.3 pilot saw. I recorded then that the lifecycle sits at `discovery`
because the pipeline's only work hop is unreachable from that stage. True, and incomplete: the
**human** path is shut as well, by a different cause.

### B2. A governance gate is satisfied by evidence the requester supplies

`blueprintPersistence.ts:139` builds the persisted ref set from `input.project`, which is the HTTP
body. `composeBody` types that field as `anyObject` and validates nothing deeper. An explicitly
empty `source_blocks` array is **honoured** as genuine emptiness, so a caller can satisfy the
`source_block_uncited` prerequisite at `requirements_ready` for a project whose stored document
holds requirement blocks that no task cites. Nothing compares the posted blocks against
`contract_process_documents`.

The caller must already be a trusted program-section admin, so this is control integrity rather
than privilege escalation. It is still a gate that measures what it was handed.

### B3. One production project has no lifecycle row, and nothing can ever register it

Of the 29 student projects created since registration went live, one has none: project
`50a24430`, created **2026-11-11**, tenant `colaberry`.

| | |

**The detectors were validated in both directions before being trusted.** A zero or a one from a

**It is permanent.** The only writer of `project_lifecycle_states` anywhere in the codebase is the

re-registration on next touch. The health check reports the condition at `severity: 'warning'` and
deliberately never `critical`, which is why five weeks of it went unremarked.

## Two things I had wrong, and an independent reviewer caught both

Recording these because this ticket is about evidence, and a review that hides its own corrections
is not one.

**1. I called the mechanism settled. It is not uniquely determined.** The tenant-resolution chain
exists limb by limb: `resolveStudentTenantId` returns `null` on a transient read failure, the
`beforeCreate` hook leaves the row unattributed, the `afterCreate` hook logs
`error_class: ContractViolation` with `reason: tenant_unresolved` and declines, and
`ensureProjectTenantSchema` later backfills `tenant_id` at boot. But **two other mechanisms produce
the identical end state** - a hook that never ran, and an `INSERT` that threw - and only a log line
discriminates them. That line is not retained. A single occurrence rather than a systemic one does
favour the transient branch, since a missing configured tenant would have stranded all 29.

**2. The backfill launders the diagnosis, so the detector now points the wrong way.** The detector
returns `tenant_id` specifically so an operator can tell an unattributable project from a bypass,
and the health check's wording calls a hit "an LC-01 bypass: something created a project outside
the models the hooks sit on". Once the boot backfill sets `tenant_id`, the one genuine
tenant-resolution failure reports a non-null tenant and therefore **reads as a bypass**.

**3. I wrote that the project "is refused authorized stories". That overstated it.**
`ENABLE_PROJECT_LIFECYCLE` is `true` on production, but `ENABLE_SBP_STORY_GATE_ENFORCE` is **not
set**, so the story gate observes rather than refuses. The exposure is **latent, not live**. Under
the enforcing branch that project returns `no_lifecycle`, decompose throws
`StoryNotAuthorizedError`, and nothing in the system can repair the row - so turning that flag on
would strand this student permanently. I checked both flags by name rather than argue the point.

not my conclusion:

- **No `it.skip`, `xit`, `xdescribe` or `test.todo` anywhere in the lifecycle tree.** All fifteen

## Security and recovery: no unresolved critical

Worth stating plainly rather than leaving as an absence.

All six lifecycle routes enforce session, role **and** resource ownership, through an audited
tenancy guard that records the decision either way and whose 404-not-403 choice is preserved, so
refusals are not a cross-tenant existence oracle. Every `params`/`query`/`body` is schema-parsed
before any service import. Of **232** `sequelize.query` call sites in the lifecycle tree, none
interpolates request data; the only interpolated fragments are a closed two-value column enum and
fixed constant lists. No secret in source or logs, free text redacted before logging, generic 500s.

Recovery: registration joins the caller's transaction and deliberately does not catch, with
idempotency from partial unique indexes plus `ON CONFLICT DO NOTHING`; transitions use a
stage-scoped compare-and-set; `autoAdvance` adds `condition IS DISTINCT FROM 'needs_reapproval'`
and distinguishes `stage_moved` from `needs_reapproval` with a post-write read; readiness writes
are idempotent on (lifecycle, stage, evidence hash) with "satisfied with gaps" unwritable by CHECK
constraint; approval is read-compare-write in a transaction behind a unique index; `manifestWriter`
retries bounded at 3; `executeStage` has 3 attempts, a 5-minute lease and a dead-letter table. No
swallowed catch: every catch on the path logs class and message.

Named, not blocking: no `statement_timeout` anywhere on this path (a pool-exhaustion scenario
exists via an index tuple lock); a malformed `plan_json` with `stories: [null]` throws out of
`readLifecycleEvidence` and 500s a status read whose declared contract is "null on any failure,
never thrown"; and one tenancy guard is permissive while `tenant_memberships` is empty, which
self-closes on the first membership row.
