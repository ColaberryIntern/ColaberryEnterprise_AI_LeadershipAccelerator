### `.colaberry/plan.json`: drift guard + ownership reclassification (2026-08-23)

- [x] **Refuse to overwrite a `plan.json` the platform cannot prove it wrote**
  - Date: 2026-08-23
  - Session: CC-20260823-9k4d
  - What changed: `repoWriter.writeDocsToRepo` gains a guard after the progress
    merge. It reads the repo's `.colaberry/plan.json` once and compares its
    sha256 against the hash `.colaberry/manifest.json` records; on any mismatch
    the file is dropped from the change set and the refusal is logged as
    `sbp_repo_plan_write_skipped` with a machine-readable reason. The decision
    itself is `planWriteDecision()`, pure and exported, so all five branches are
    testable without a network. The root defect: `changedFiles` compares a fresh
    render against the MANIFEST — a record of what the platform last wrote — and
    never against what is actually in the repo, so a hand-edit was invisible to
    it and the next differing render replaced the file wholesale.
  - Verification: `repoWriter.planDrift.test.ts`, 17 tests, watched failing
    against unmodified `origin/main` first. The headline case fails on main with
    `Expected value: not ".colaberry/plan.json" / Received array: [".colaberry/plan.json"]`.
    Full `src/services/sbp` suite: 71 suites, 1224 passed. Pinned tsc 5.7.3
    output byte-identical to the pristine-main baseline (2 pre-existing
    `@anthropic-ai/sdk` module-resolution errors, unrelated).
  - Notes: No field-level merge — `planDocument` guarantees byte-identical
    output and the idempotency story rests on it, so a merge would produce bytes
    no renderer can reproduce and every later sync would see drift. A student who
    edits their plan keeps it, and stops receiving platform plan updates; that
    trade is now stated in the `CLAUDE.md` block they actually read.

- [x] **Treat an unknown provenance as "do not overwrite"**
  - Date: 2026-08-23
  - Session: CC-20260823-9k4d
  - What changed: when the manifest carries no `plan.json` entry — nine live
    repos — or there is no manifest at all (Martin2100-AI), there is no recorded
    hash to compare against, so the guard refuses (`skip_unknown_provenance`).
    Same reasoning that made unknown write-access mean not-writable. The single
    exception is a genuinely ABSENT file, which writes: there is nothing there to
    destroy, and a first publish must still deliver the plan.
  - Verification: `refuses to overwrite when the manifest is a stub with no
    plan.json entry` and `refuses to overwrite when there is no manifest at all`,
    both red on main with `Received array: ["docs/REQUIREMENTS.md", ".colaberry/plan.json"]`.
    `writes the plan on a first publish, when the repo has no plan.json yet`
    passes on BOTH main and the fix, which is what proves the guard did not buy
    safety by breaking new students.
  - Notes: A read that FAILED is not an absent file. `readRepoFile` collapsed
    404 and "GitHub returned 500" to a bare `null`; split into a `RepoFileState`
    discriminated union so a transient blip refuses instead of clobbering. The
    module already held that "a read failure must never be treated as 'they had
    nothing'" — this applies it to the plan.

- [x] **Close the zip path, which clobbers outside `repoWriter` entirely**
  - Date: 2026-08-23
  - Session: CC-20260823-9k4d
  - What changed: `fileOwnership` gains a fourth class,
    `platform_unless_edited`, and `plan.json` is classified into it.
    `isSafeToOverwrite` therefore returns false, so `docsBundle` routes the file
    to `.colaberry/plan.seed.json` — the same treatment `progress.json` and
    `profile.json` already get. The workspace tells students to unzip the bundle
    over their repo, so fixing only the writer would have left an identical data
    loss reachable through the download.
  - Verification: `carries no file at the live .colaberry/plan.json path` and
    `leaves a hand-edited plan exactly where it was`, both red on main — the
    latter showing a student's 5-line plan replaced by a 602-line platform
    render (`- Expected - 5 / + Received + 602`).
  - Notes: Not `student` (seeded once, never replaced) and not `co_owned` (only
    ever applied by merge). Neither describes this file: it is platform-generated
    and SHOULD keep updating while untouched. Mislabelling it would have made the
    module's own documentation false and invited a future seed-once treatment
    that silently froze every student's plan.

- [x] **Fix a dead 404 check corrupted by literal backspace bytes**
  - Date: 2026-08-23
  - Session: CC-20260823-9k4d
  - What changed: `readRepoFile`'s not-found test read `/<BS>404<BS>/` — two
    0x08 bytes where `\b` word boundaries were intended, from a heredoc that ate
    the escapes. It could never match. Replaced with `isNotFound()`, matching the
    exact ` failed (404)` message `gh` throws, so a response BODY mentioning 404
    cannot be misread as an absent file.
  - Verification: `file backend/src/services/sbp/repoWriter.ts` no longer reports
    "with overstriking"; byte scan confirms 0 control characters across all
    touched files. Covered behaviourally by `writes the plan on a first publish`
    and `refuses to overwrite when GitHub fails on a non-404`.
  - Notes: Harmless while both branches returned `null` — it only produced a
    spurious `sbp_repo_read_failed` log on every legitimate 404. It stopped being
    harmless the moment absent and unreadable came to mean different things: a
    new student's absent plan would have read as unreadable and never been
    delivered. Found by reading the file's bytes, not its rendering.
