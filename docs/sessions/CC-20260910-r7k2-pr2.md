- [x] A one-word reply no longer earns points
  - Date: 2026-09-10
  - Session: CC-20260910-r7k2
  - What changed: Both `CreatePostSchema.body` and `CreateCommentSchema.body` were `min(1)`. New pure module `backend/src/services/community/contributionQuality.ts` sets the bar in WORDS (5 per reply, 15 per post) because a character floor is trivially padded. It ignores bare punctuation and short list markers, so `"1. ok 2. ok"` counts as two words. Enforced at the route boundary via Zod refine AND mirrored in the composer (`frontend/src/components/timeline/contributionQuality.ts`) for a live counter and a disabled Send — a client-only gate is decoration. Ritual posts are gated on the student's OWN answers, not `composeBody`'s output, whose heading and field labels would pad a one-word answer past the bar.
  - Verification: `contributionQuality.test.ts` 17/17 — boundary cases either side of both thresholds, the junk-reply set ("ok", "nice", "thanks", "👍", "great post"), punctuation-only input, and that the hint never scolds. Frontend tests assert Send flips from disabled to enabled exactly at the fifth word.
  - Notes: Deliberately low. The goal is to stop point farming, not to make people work for permission to be helpful.
