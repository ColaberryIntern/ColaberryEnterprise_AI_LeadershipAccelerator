## Findings

### 1. The contract could not reach the platform at all, so A2's premise was missing a step.

A2's instruction was to match the contract against the tree the sync already reads. Measured,
there was no contract to match: **no story in any published plan carried an `artifacts` block.**
A1 authored contracts in the story config beside the publisher, and the platform never reads that
file. `getPublishedPlan` returns a `BuildPlan`, and `PlanStory` had no such field.

So A2 adds it. `PlanStory.artifacts?: unknown`, which follows the file's own house pattern for
additive optional fields (`workspace?`, `blocked_by?`, `references?`), each documented as absent
on older plans. It is typed `unknown` rather than as a resolved type on purpose: nothing
re-validates a stored plan on read, so the block may be malformed, and declaring it as resolved
would be a claim that file cannot keep. Every reader puts it through A0's
`validateArtifactContract`, which takes `unknown` by design.

**Nothing populates it yet**, and A2 does not pretend otherwise. The generator that produces plan
JSON lives in another repository, and retrofitting the live boards is A5. So in production today
this check will find no contract on any story and report nothing, which is the honest state: the
mechanism ships before the data, and the flag is off anyway.

### 2. The content hash the phase asked for was being thrown away, one line from where it was needed.

The instruction said each row should carry "the commit and a content hash". There was no content
identity available: `readTreePaths` reduced GitHub's tree response to a `Set<string>` of paths and
discarded the `sha` and `size` that every blob entry already carries. Fetching content per
artifact would have added one GitHub call per artifact to a path that currently makes none.

Keeping them costs nothing. The reader now also returns `treeEntries`, as a SEPARATE field rather
than by enriching `treePaths`, because `criterionPaths` consumes `treePaths` to decide whether a
student keeps a criterion, and changing the type it reads to add a field nothing there needs would
have put that path inside this phase's blast radius for no benefit.

### 3. `gov_build_artifacts` could not be generalized, and the reason is structural.

The instruction was to generalize that table. It does not fit, three ways:

- it is **UNIQUE on (story_id, commit_sha)**, so it physically cannot hold more than ONE artifact
  per story per commit, and a contract routinely declares several;
- its `delivery_project_id` is a **NOT NULL FK to `delivery_projects`**, while the stories this
  phase verifies belong to `projects`;
- it means something else: a screenshot captured from a verified gov build demo, for insertion
  into a proposal as a numbered figure.

Generalizing it in place would mean dropping a unique index and loosening an FK on a live table
under the running Proposal Studio. What carried over is the SHAPE, which was right: key on the
story and the commit, store the path and a content identity, make the insert idempotent per key.
Raised with Ali as a question rather than decided quietly, because it is a schema change on a live
system; he chose the new table, with converging the two left as its own ticket rather than assumed
away. The integration suite includes the case that proves the limitation is really fixed: three
artifacts for one story at one commit.

### 4. A dead branch, found because its test could not be made to pass.

The matcher's first draft returned a `wrong_file_type` verdict for a file at the declared path
whose extension the contract does not allow. Two tests for it failed, and the reason was not a
bug in the matcher: **A0 already refuses that contract at authoring time**
(`repo_path_extension_not_declared`), narrowing included, and the tree lookup is an exact path
match, so a file found at the declared path has the declared path's extension by definition. The
branch was unreachable.

It was deleted rather than left in as defensive cover. An unreachable branch is a verdict no row
can ever carry and no test can ever exercise, and leaving it in would have implied the matcher
checks something it does not. The check is real and lives one phase earlier, where an author can
still fix it, instead of being re-run against a student on every push. The test now asserts the
invariant that makes it unreachable, so if A0 ever stops refusing the mismatch, a test fails here.

### 5. Four type errors, two of them in a file this branch never touched.

The test typecheck gate reported 403 errors across 142 files against a 399/140 baseline. Two were
in the new integration suite and two in `ensurePublishingSchema.integration.test.ts`, which this
branch does not modify. The cause: a TypeScript file with no top-level `import` or `export` is a
SCRIPT, and its top-level `const`s are globals. Both files declare `HAS_DB` and `describeIfDb`
exactly that way, so adding the second one collided with the first. Fixed with an `export {}`
marker in the new file, and the baseline then matched exactly in both directions.

Worth keeping because the error pointed at a file that was not at fault, which is the kind of
report that gets dismissed as noise.

## What A2 does not claim

- **Nothing was deployed, and no row was written to any production database.** The only database
  touched was `accelerator_dev1`, inside a transaction that was rolled back.
- **It cannot change a verdict, and there is no mode in which it can.** The flag is `off` or
  `report_only`. No enforcing mode exists in this phase: making a missing artifact withhold a
  story's completion changes what a student is told they owe and what they are paid, and should be
  switched on against a week of real measurements rather than on the day the measuring is written.
  Nothing here touches `student_tasks`, awards or withholds XP, or reaches
  `markTaskVerifiedComplete`.
- **No story in production has a contract**, so with the flag on today the check would find
  nothing. See finding 1.
- **`must_contain` is not checked.** The tree gives paths, shas and sizes, not content. An
  artifact whose contract names phrases a reader must find is recorded as
  `present_content_unchecked`, never as `satisfied`, so the row says what was and was not read
  rather than carrying a verdict that silently means less than it reads.
- **An outstanding key is not a row.** Absence of a row is what "not handed over yet" means. A
  `missing` row per push would read as activity and measure nothing.
- Quality is still a human judgement. This proves a document of the right kind exists at the right
  place at a known commit.
