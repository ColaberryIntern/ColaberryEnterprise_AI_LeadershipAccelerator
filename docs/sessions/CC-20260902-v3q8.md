Backend `RestartCount=0`, `OOMKilled=false`, site 200.
  - Notes: **This is the rare deploy whose success criterion is that nothing happened.** Wiring the sync without routing would have created ~490 contacts in the Agent Cory AI sub-account, in front of an outbound dialer, against a population nobody had reviewed. The deployed behaviour is now structurally incapable of that: a source routed to an account with no key resolves to `unconfigured` and the caller refuses to sync, rather than falling back to the default. **Zero `GHL Sync Withheld` activity rows so far**, which is correct rather than a failure - those are written when a lead is actually captured, and none had come in during the minute after deploy. **Still not done:** the key itself is not set, so no lead has yet reached School of Data Analytics; the `open house` tag Kes asked for is not built; and the key that was pasted into a chat transcript four times should be rotated once it is in the field. **Unrelated finding worth recording:** prod's `git pull` is configured to **rebase**, which is why the unpushed Session 10 curriculum commit has appeared under four different SHAs (`ad69dae5`, `ead1d15a`, `d6fd1bbb`, `51c098ec`). Nobody is recommitting it - every pull rewrites it. It is stable content with an unstable identity, which also means PR #1854 preserves a valid copy under a now-superseded SHA. The durable fix is getting it off that box, not preserving it again.
