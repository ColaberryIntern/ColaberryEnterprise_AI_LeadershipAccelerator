## T001 — The candidate record

**What it is.** One table and one pure stage enum for a capability candidate's life, before any
request exists.

| File | Role |
|---|---|
| `backend/src/db/ensureAgentDomainCandidateSchema.ts` | `agent_domain_candidates`, the ensure/assert/guarded trio |
| `backend/src/models/AgentDomainCandidate.ts` | The model, registered in `models/index.ts` |
| `backend/src/services/agentDomain/candidateStages.ts` | Eight stages, frozen, and a total `derive()` |
| `backend/src/db/__tests__/ensureAgentDomainCandidateSchema.test.ts` | 26 tests |
| `backend/src/services/agentDomain/__tests__/candidateStages.test.ts` | 22 tests |

**The decision this encodes.** A candidate is not a request. Most candidates never become one, and
one candidate can produce two: a screen request while the product cannot do the thing, and a tool
request once the builder has done it by hand. So the table carries **no status, no approver, no
decided_at, no declined_reason** — `docs/AGENT_TOOL_REQUEST_HANDOFF.md`: *"There is already an
approval spine. Do not build a second one."* It reaches a decision by pointing at the spine with
two nullable foreign keys, and its stage is derived from those rows rather than stored.

**The eight stages**, in path order: `proposed`, `scope_sheet_owed`, `platform_owed`,
`screen_built`, `by_hand_pending`, `proven_by_hand`, `tool_requested`, `agent_watched`. The fork
Ali named is the reason `platform_owed` and `scope_sheet_owed` are two stages and not one: an
`api_only` gap is Ali's to close, a `not_built` candidate is the builder's to scope, and a stage
with two possible owners cannot tell anybody whose turn it is.

**Two places the plan's own numbers were wrong, corrected here rather than copied.**

1. The plan said the cross-product is 5 x 4 x 4 = 80. `AgentChangeRequestStatus` is
   `submitted | approved | declined | withdrawn` — four values — and *absent* is a fifth state, so
   the honest grid is 5 x 2 x 5 x 5 = **250**. Enumerating fewer than the real set is how a
   totality test certifies totality it never checked.
2. The plan said idempotence should be *"asserted by counting statements executed on the second
   call"*. Counting is the wrong instrument and the count is not zero: the statements are sent
   again, because `IF NOT EXISTS` is evaluated by Postgres, not by this module. A test expecting
   zero would fail against correct code. What is proven instead is stronger — the second call sends
   the identical list, and **no statement in it can write on any run** (every one is
   `CREATE TABLE/INDEX IF NOT EXISTS`; there is no `ALTER`, `UPDATE`, `INSERT` or `DELETE`).

**One addition beyond the plan's column list**, stated rather than slipped in:
`uniq_adcand_domain_title`, a unique index on `(domain_key, title)`. The candidate list is seeded
repeatedly — four per builder, regenerated as rungs advance — and without it the second seed
silently doubles the list.

## T003 — The flow controller: whose turn is it

**What it is.** One pure function both sides read. The builder's entry point calls it to say what
to do next; the Command Center calls it to build Ali's queue. They cannot disagree, because there
is nothing to disagree about: same input, same function, same sentence.

| File | Role |
|---|---|
| `backend/src/services/agentDomain/candidateFlow.ts` | `nextStep()`, `slugFor()`, `TURN_BY_STAGE` |
| `backend/src/services/agentDomain/__tests__/candidateFlow.test.ts` | 39 tests |

**The action is a SENTENCE, not a status.** A status says where something is and never what to do.
The old ladder's 964 identical story bodies are what that produces. Every branch returns a sentence
naming an action and the file it writes, and a test walks all eight branches asserting none is
empty, short, or a placeholder.

**`blocked_reason` beside `turn`.** `turn: 'owner'` tells a builder to stop pushing but not why,
and a builder who cannot see why reads it as being ignored. `blocked_reason` is the sentence they
can paste to their manager, and a test asserts it is non-null exactly when the turn is not theirs.

**The fork, asserted four ways.** `api_only` returns the owner's turn with an action naming the
**screen**, and the test asserts the action and the blocked reason both contain no "scope sheet" —
sending that builder to argue for something that mostly exists is the exact mistake the front door
was rebuilt to stop. `not_built` is the contrast and does say scope sheet. `partly` asks for a
**ruling**, because whether the half the app does is enough is Ali's call.

**`turn: 'nobody'` is reachable, which is why `gateSize` is a real argument and not decoration.**
Once a domain has cleared its option C target the last stage owes nobody anything; below it, the
action counts down ("3 more capabilities needed to clear the gate for R3"), in the singular when
one remains.

**One test caught the copy, not the logic.** The by-hand action said "do it yourself first" and
the only "by hand" in the string was inside the hyphenated file name. The assertion was right and
the sentence was weaker than it should have been, so the sentence changed.

## T003 fix — two defects the verifier found

T003 passed at 11/12. Both findings were real and both are fixed.

**1. The countdown rendered "3 more capabilityies".** The plural was built by appending `ies` to
`capability` instead of to the stem. It fired for every count except one, which is the common case,
in the one sentence a builder reads every day. The test asserted `toContain('3 more')` and so
passed with the thing it claimed to check broken — the only place in the suite where that was true.
Fixed to `capabilit${n === 1 ? 'y' : 'ies'}`, the assertions tightened to the whole phrase
(`'3 more capabilities needed'`), and a new test sweeps every remaining count from 9 down to 1
asserting no malformed plural at any of them.

**2. `const owned = stageFor(stage).owned_by` was assigned and never read.** `noUnusedLocals` is
off and the repo has no working ESLint config, so nothing caught it. It was the vestige of an
intended derivation: every branch restated its turn as a literal, so agreement with
`BUILDER_STAGES` was enforced only by a test, never structurally. Rather than delete it, the eight
branches now read `turn: owned`. The single remaining hardcoded turn is the gate-met `'nobody'`,
which genuinely cannot come from a per-stage table because it depends on the gate rather than the
stage, and a test asserts that it is the only one left.

## T004 — Candidate endpoints and the snapshot section

**What it is.** The candidate list on the platform, so the gap board can see across builders
instead of waiting for somebody to open seven repositories.

| File | Role |
|---|---|
| `backend/src/services/agentDomain/candidateService.ts` | list / create / set product state / mark proven, plus `candidatesSection()` |
| `backend/src/routes/admin/agentDomainCandidateRoutes.ts` | four routes, all `requireSection('dashboard')`, Zod on every body |
| `backend/src/middlewares/mgmtSectionGate.ts` | one `PATH_SECTION` row |
| `backend/src/services/agentDomain/agentDomainSnapshot.ts` | the fifth source and the `candidates` key |
| `backend/src/routes/adminRoutes.ts` | mounts the router |
| 3 new test files | 47 tests |

**The stage comes from a JOIN and never from a column.** Every read resolves the two change
requests a candidate points at and asks `nextStep()` where it is. That costs one extra query per
page and buys the thing a status column cannot: when Ali approves a request through the governance
console, every candidate view changes on the next read, with nothing to sync and nothing stale.

**Scoping lives in the query, not in the route's good intentions.** An empty list of owned domains
returns nothing and does not touch the table — a test asserts `findAll` was never called. Treating
"no filter" as "no restriction" is how a scoping bug becomes a disclosure. Writes are scoped the
same way: `findOne({ where: { id, domain_key: IN(owned) } })`, so another builder's row is never
read into memory before a decision is made about it.

**`dashboard`, not `program`, and it needs its own gate row.** `matchesPrefix` requires an exact
match or a `/` boundary, so `/api/admin/agent-domain-candidates-mine` cannot inherit the
`agent-domains-mine` row and would fall through to a deny-by-default 403 with nothing explaining
why. That is AF8.3's recorded failure, where six correctly-scoped interns got 403 on the page built
for them and it was only found by walking all six through production. The test proves the negative
too: an unmapped sibling really does return null.

**The gate countdown is a fact about the DOMAIN, not about one row.** Computed in one pass before
any view is built, so two watched candidates in the same domain cannot disagree about how many
remain. An unknown rung falls back to R0's gate, the smallest, because a fallback that guessed high
would make a domain look further from its gate than it is.

## T004 fix — a proven regression the narrow test run hid

T004 scored **8/12 and FAILED**. The finding was real and worth recording in full, because every
test I ran passed.

`agentDomainSnapshot.ts` imported `candidatesSection` from `candidateService.ts`. That module
imports `models/AgentDomainCandidate`, which calls `.init(..., { sequelize })` at **module scope**.
So merely importing the snapshot now constructed a Sequelize model, and because
`agentDomainRoutes.ts` imports the snapshot, **five untouched suites — 138 tests — stopped being
able to run at all**:

```
TypeError: Cannot read properties of undefined (reading 'define')
  at AgentDomainCandidate.init (src/models/AgentDomainCandidate.ts:74)
  at candidateService.ts:25
  at agentDomainSnapshot.ts:43      <- the line T004 added
  at agentDomainRoutes.ts:80
```

My own run was green because it covered the NEW suites and not the five that already existed. The
file's own header says *"Pure. No I/O, no clock, no randomness"* — true, stated, and quietly made
false by one import line.

**Fixed by splitting the pure half out.** `candidateSection.ts` holds `CandidateView`,
`CandidateListResult` and `candidatesSection` and imports no model; `candidateService.ts` keeps the
database half and re-exports the pure one so no importer breaks; the snapshot imports only
`candidateSection`.

**And enforced, so the purity claim can fail.** `agentDomainSnapshotPurity.test.ts` walks the
snapshot's transitive **value** import graph and asserts it reaches nothing under `models/`,
nothing that calls `.init` at module scope, and nothing that imports `config/database`. Type-only
imports are excluded deliberately: TypeScript erases them, so they create no runtime edge, and
counting one would have failed on an edge that does not exist.

Mutation-proved: repointing the import back at `candidateService` turns all three assertions red,
each naming the real path. The five suites are green again, 138 tests.

Also fixed the two prose/code mismatches the verifier noted: the gate comment and the router header
argued about `/api/admin/agent-domain-candidates` while the row and the routes use
`...-candidates-mine`.
