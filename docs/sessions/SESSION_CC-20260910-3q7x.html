Operator session: one durable lease, one resume cursor (T1)

2026-09-11
What changed`services/inboxCase/operatorSessionService.ts` (new). The lease REUSES `resource_leases` + `workCoordinatorService` — that table already carries the partial unique index `(resource_key) WHERE status='active'`, so "exactly one active operator" is enforced by Postgres. The only new state is the cursor, in `system_settings['inbox_zero_operator_cursor']`, matching the `inbox_cos_sync_state` precedent. `idempotency_key` is a fresh UUID per acquire (the tab id lives in `lease_owner`): `acquireLease` short-circuits on that key and returns `acquired: status==='active'`, so using the tab id would have made `/inbox-zero resume` fail forever on second use. Basecamp client: a timeout on every request, and a paginator (T6)

2026-09-11
What changed`services/ops/basecampClient.ts` rewritten around one `bcSend(method, url, send)` loop: every `fetch` (GET, POST, PUT) now carries `AbortSignal.timeout(bcTimeoutMs())` (15s default, `BC_TIMEOUT_MS` override read at call time).
