### A 58% readiness rendered as "1%" (PR #1834)

- [x] Fix: /portal/company showed a 58% architect readiness as "1%"
  - Date: 2026-08-25
  - Session: CC-20260825-9k2p
  - What changed: `student_level.architect_readiness` is a 0..1 fraction (written by `computeReadiness` via `promotionService`). Two readers rounded it without scaling to a percentage and then rendered it behind a `%` sign and as a progress-bar width: `pointsDrilldownService.ts:65` (`pct: Math.round(st.readiness)`, the primary path) and `orgService.ts:489` (`readiness: Math.round(Number(lvl?.architect_readiness ?? 0))`, the roster fallback `CompanyMemberDrilldown` uses when the drill-down degrades). `Math.round(0.58)` is `1`, so a student measured at 58% read "1% readiness" with an empty bar. Both now multiply by 100. The correct pattern already existed at `CurriculumComposerTab.tsx:373` (`(ev?.architect_readiness || 0) * 100`) and in `schoolSignals.ts:97` (`architect_readiness >= 0.7`), which is how the mis-scaling was identified as a reader bug and not a data bug. Backend-only, two lines, no schema or data change.
  - Verification: Found on a real production record, not a synthetic one: enrollment `c31ea314` (Farhat Beig) holds `architect_readiness = 0.5828096086919616` in `student_level`, and her profile renders "1% readiness". `Math.round(0.5828) = 1` reproduces the rendered value exactly. Confirmed the field is 0..1 at the write site (`promotionService.ts:111`, `current.update({ architect_readiness: readiness })` where `readiness = computeReadiness(...)`). Both edited files parse and transpile clean standalone (0 parse, 0 transpile diagnostics). Full backend `tsc --noEmit` (TypeScript 5.9.3) then ran to completion: exit 2 with exactly 2 errors, **both pre-existing and in unrelated files** (`services/interviewService.ts` and `services/runtime/anthropicClient.ts`, both `TS2307` for `@anthropic-ai/sdk`, absent from this machine's junctioned `node_modules`). **Zero errors in either edited file.** CI's Backend typecheck, Frontend typecheck and Frontend build all passed. CI's Backend unit tests initially FAILED on `orgService.test.ts`, whose fixture used `architect_readiness: 44` and asserted pass-through. That fixture was wrong, not the fix: `computeReadiness` returns `Math.min(1, Math.max(0, weighted/totalWeight))`, so it can never emit 44, and all **431 production rows sit between 0 and 0.583 with none above 1**. Corrected the fixture to `0.44` (which the old code would have rendered as `0`, so it is now a real regression guard) and added a test pinning the incident value itself: `0.5828096086919616` must render `58`, not `1`. Suite re-run locally: **10 passed, 0 failed**.
