## Deferred, with recommendations

Five of Quincy's fourteen findings are not in this change, because each needs a decision or new
storage rather than a code fix:

1. **The auto-repair agent undoes a person's decision.** Switch a prompt off deliberately while an
   active lesson still uses it and the monitor flags it within a minute, then the repair switches it
   back on at the next five-minute run. Needs a way to record "off on purpose" — a field on
   `prompt_templates`, which is a schema decision.
2. **Only one security ticket can be open at a time.** `createTicket` reuses any open ticket with
   the same entity and type and no time window, and all 8 security agents file as entity `system`,
   the security department id, type `bug`. So a newly leaked key merges into whatever security
   ticket is already open. Recommended fix is an optional `dedupe_key` narrowing the reuse match,
   which changes a function every department calls and wants verifying against a real database
   before it ships.
3. **Removing a role does not remove access until the token expires** (12 hours). The gate reads the
   role from the token, not the database. A session-invalidation design decision.
4. **The access control guardian never checks anyone's access** — it scans route source, which is
   absent in production, so it skips. Ellis's access watch is this capability, built from
   `admin_users` and staff roles rather than from source. Worth adopting rather than rebuilding.
5. **Audit gaps**: `admin_users` rows are created outside the audited routes, `old_values` is always
   null, and failed admin logins only reach the console, so the runtime threat monitor cannot see a
   burst of them. Persisting auth failures is new storage.
