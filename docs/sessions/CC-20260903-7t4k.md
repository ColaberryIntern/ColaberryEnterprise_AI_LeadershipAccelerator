Results sort worst-signal-first. `getCohortReadiness` uses a LEFT JOIN LATERAL deliberately, with a test asserting no INNER JOIN: the students an instructor most needs to see are the ones with no snapshot at all, and an inner join would hide exactly them. `getBankHealth` reports `domains_with_no_approved` — the silent cause of the short forms observed in the lifecycle run. **There is deliberately NO bulk-approve endpoint**: approving forty questions in one click is not review, and the gate's whole value is that somebody read them. The reviewer is taken from the authenticated admin, never from the request body. **Analytics is defined by what it refuses to log.** No question stems, options, rationales or answer keys — the bank is the product and an analytics table is a much weaker boundary than the serving path. No selected answers — which option a named student picked is theirs, and `cert_responses` already holds it under access control. No free-text student content. `sanitize()` enforces this rather than trusting call sites, stripping forbidden fields NESTED and inside arrays, with tests for each. What survives is shape: question key, domain, duration, correctness — enough for exposure and difficulty, useless for reconstructing the bank or profiling a student. `certEvent` never throws, with a test asserting it absorbs a rejecting event store: a failed telemetry write must never be why a student's answer does not save. Four operational signals: scoring failure, form-generation failure (usually an empty domain), duplicate award attempt (marked `blocked` not `failure` — the idempotency key did its job; there is no `partial` in `AiEventOutcome`, and `blocked` turned out to be the more precise word), and a stale-blueprint flag so nobody forgets a readiness number computed against unverified weights is a coverage estimate.
