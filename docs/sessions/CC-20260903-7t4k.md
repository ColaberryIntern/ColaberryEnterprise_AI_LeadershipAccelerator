  - Notes: **There was no server-side current-week accessor anywhere in this backend.** Program week is a URL parameter (`/portal/classroom/week/:weekNum`) that the API accepts as input, and the 1–12 range is validated client-side only. That is fine for navigating curriculum and unusable as a gate — a student could open `/portal/cert-prep?week=9` in Week 3 — so acceptance criterion 1 ("weeks 1–6 cannot access Cert Prep through UI **or direct API**") could not be met with what existed. `deriveProgramWeek` is the first server-side derivation: enrollment → cohort → `start_date`, whole-day UTC arithmetic, and `getCertAvailability` takes **no week argument at all** so no caller can supply one. Tested across a DST transition (2026-11-01) because wall-clock parsing has bitten this repo before. **The fence fails CLOSED, which is deliberately the opposite of `useEntitlement` and `timelineGatingService`** — both of those fail open so a transient error never traps a paying student. The trade differs for a content-reveal fence: failing open shows certification pressure to a Week 3 student, which is the exact product violation the fence exists to prevent; failing closed makes a Week 9 student retry. Rationale is in the file header so it does not get "fixed" later. **Unverified blueprint facts are nullable by design and the schema test enforces it**: Anthropic's official CCAR-F exam guide is behind the Partner Academy login and has not been read, so every weight and exam fact we currently believe comes from third-party community guides. `cert_domains.weight_pct` therefore carries no `NOT NULL` and no `DEFAULT`, and `weight_source`/`blueprint_source` default to `'unverified'`; readiness must degrade honestly rather than substitute a community number. **Question identity is split from question content** (`cert_questions` + `cert_question_revisions`) so editing an approved item inserts a revision instead of rewriting what a student already answered; `cert_responses` stores the revision served. A test asserts `correct_keys` appears in no table other than the revisions table. Discovery also cleared the regression risk flagged pre-build: `splitNavGroup.test.ts` asserts only that nav labels exist and that Classroom/Projects lead their group, so routing Cert Prep will not break it. Not deployed, not pushed; `ensureCertPrepSchema` is not yet wired into boot.
