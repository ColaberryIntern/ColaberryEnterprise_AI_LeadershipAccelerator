# Session CC-20260901-r3k7 — Make the automated billing messages tell the truth about auto-pay

**Date:** 2026-09-01
**Branch:** `fix/billing-messages-autopay-truth` (cut from `origin/main`)
**Scope:** On 2026-09-01, 20 members were migrated onto standing PaySimple schedules,
taking auto-pay from 1 member to 21. The renewal email was rewritten and deployed for
that in PR #1984. This session covers the rest of it: every other automated billing
message, and the documentation, still asserted "billing here is manual" as a universal
fact. That premise is now false for 21 people, and one automated message was acting on
it in a way that could have caused a double charge.

**DEPLOYED AND VERIFIED IN PRODUCTION 2026-09-01.** PR #1989, merged as `9979cd01`.
See the deploy entry at the bottom.

- [x] Stop the billing watch chasing members whose schedule is about to collect
  - Date: 2026-09-01
  - Session: CC-20260901-r3k7
  - What changed: `checkLapsedWithoutFollowup` in
    `backend/src/services/billing/billingHealthCheck.ts` reads "period end is in the
    past" as "nobody is collecting". That was true while every term was a manual
    checkout. It stopped being true on 2026-09-01, because migrated members were

    genuinely manual and awaiting ACH consent. 17 tests pass across both billing suites.
  - Notes: this is a money bug, not a noisy-email bug. It is the same class as the
