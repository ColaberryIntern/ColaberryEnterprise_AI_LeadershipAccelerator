## The count was not a thin answer, it was no answer

Measured against production on 2026-11-05, across all 416 asset entries ever written in three
Governor runs: **no decision has ever carried more than one asset.** So `asset_count` reads `1` on
every row that has anything, 130 times on the latest run. The cell said "1 selected" and resolved
nothing a reviewer opened it to learn.

The titles were already in the row the panel had fetched. `selected_content_assets` is a snapshot
the Governor's resolver writes, and all 416 entries carry `id`, `title`, `asset_type`, `url`,
`source_id` and `source_system`, none of them blank. No join, no new endpoint, no new query.

## Reading them exposes what the count was hiding, and it is not a UI finding

Those 130 decisions all selected **the same asset**, and only **two distinct assets** have ever
been chosen, out of a registry of 1,454. A journey engine that picks one piece of content for
everybody is now visible at a glance on this panel and was invisible before.

That is a finding about the Governor, not about this panel, and it is **not** claimed on the
screen. The panel holds 10 rows of 130; computing "distinct assets" from a page and labelling it
as the run's diversity would be a statistic manufactured from a tenth of the data. If it is worth
stating on screen it belongs in `explorerOverviewService` beside `with_content`, as one more
summary field, which is a different service and a separate decision. **Flagged, not built.**

## Why the title comes from the decision and not from the content library

The stored title is a snapshot, and it has drifted. Of 416 entries, 392 now name a title the
registry has since changed: the asset was renamed on 2026-11-05 02:50 UTC to drop a word the copy
rules ban. A control proves the comparison was real rather than a join that silently failed — the
other asset ever selected, 24 entries, still matches the registry exactly.

So joining `explorer_content_assets` for the current title would caption a two-month-old decision
with copy that decision never chose. It would also have cost a sequential scan of the registry per
row (measured: `EXPLAIN ANALYZE` showed 1,454-row seq scans on 130 loops, 70 ms at 153 rows,
because `c.id::text = a->>'id'` cannot use the primary key index), and the resulting "renamed
since" badge would have fired on **100% of rows**, which is the same failure as the count: a true
statement that carries no signal.

The drift is stated once, in the type's docblock, where the next person deciding which title to
show will read it.

## Three deliberate choices in the projection

1. **An allowlist, not a pass-through.** `url`, `source_id` and `source_system` stay server-side:
   they are internal addressing, no surface renders them, and a key the resolver gains tomorrow
   should not reach a browser by default. Asserted on the row, not only on the projector — the
   test greps the serialised row for `timeline_cards` and `/portal/runtime/`.
2. **Length-preserving.** `asset_count` is `jsonb_array_length` of the same column and the panel
   renders both. An entry dropped for being unreadable would make the titles disagree with the
   count, which reads as "the panel lost one" rather than "one of these is unusable". A titleless
   entry therefore renders as *unnamed asset*.
3. **Reshaped in TypeScript, not in SQL.** This file's header is explicit that every test in it
   mocks `sequelize.query` and asserts on the SQL template, so no test there can tell whether the
   SQL runs at all. Moving the part that can actually be wrong into a pure function puts it under
   test coverage that exists. The one-line SQL change was still executed against production
   first.

## The failure path that was found by looking for it

`row.assets` is typed as an array; a response from an older backend behind a newer bundle is not
bound by the type. Before the guard, `undefined.length` threw inside the table and took the whole
panel down. A gap badge would have been worse than the crash — it would report content as missing
when it exists — so the cell reports `N selected — titles unavailable` and says why in its title
attribute. The test casts `undefined` through the type deliberately, and the cast is the test.

## Not changed, on purpose

`explorerGrowth/DecisionsTable.tsx` renders the same `asset_count` in its own narrow numeric
column and keeps it. That table already carries a **Draft subject** column showing the copy the
learner would read, so the asset title beside it would be redundant, and its asset cell is a
health indicator with a gap rule tied to `WAIT`. The Email tab panel has no draft column, which is
why the asset title is the only content signal there and why the ticket asked for it there.
