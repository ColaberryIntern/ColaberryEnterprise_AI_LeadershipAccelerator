Notes**The most valuable finding was in the defence, not the code.** All sixteen Story Studio routes really did carry `requireAdmin`, and always had; nothing could have noticed if one stopped. `caseStudyAdminGuardProof.test.ts` imports `caseStudyAdminRoutes` and only that, the other three authorization suites are scoped to the same sibling router, and the CI backstop `scripts/lint-route-auth.js:31` is `src.includes('requireAdmin')` at FILE granularity — one surviving occurrence in a 451-line file satisfies it. Proved by mutation: `requireAdmin` deleted from one route left the lint printing "all 94 admin route files are auth-guarded" while the new suite went red on four assertions. A property that is true, unproven and undefended is the condition CLAUDE.md's Definition of Done calls incomplete. **The V-29 fix deliberately does NOT scrub the projection.** `caseStudyPrivateRepoLeakProof.test.ts` still asserts `expect(summary.standfirst).toContain(S.url)`, unchanged — scrubbing at projection time would silently rewrite what a human approved, which is the one thing the snapshot model exists to prevent. The projection stays a FIELD allowlist; the gate is what stops such a record reaching it, and that assertion's meaning has changed from "the boundary leaks" to "the boundary is a field allowlist, and the gate is the control". **The first version of that rule was too aggressive and the existing suite caught it**, which is worth recording because it is the good case: `nameIsDistinctive` originally accepted any repository name of 12+ characters, and `caseStudyPublicationService.test.ts`'s fixture repository is called `reconciliation` — 14 characters, an ordinary English word — while the same record's summary legitimately reads "A batch reconciliation pipeline was rebuilt…". The gate refused a publish over a word describing the work. Length is not evidence of distinctiveness; the rule now requires a separator or a digit, and the residue (a single-word private repository is matched by its URL and its slug but not by its bare name) is stated in the rule's header rather than left to be discovered later. **Snapshot immutability was real, but narrower than the sentence people were using for it.** `case_study_snapshots.content` genuinely never mutates — one `create`, two status-only `update`s, no upsert, no raw SQL — and `caseStudyIntegration.test.ts:276-320` proves a re-sync cannot change a live page, with a positive control that stops it being vacuous. But `toCandidate` (`caseStudyPublicStore.ts:106-119`) reads **six fields off the mutable `case_studies` draft row**, and `slug` is the public URL itself and `seo.canonicalUrl`. "The approved snapshot never mutates" and "the published page never changes without a republish" are different claims; the gap between them is every field the public read takes from the live row instead of the snapshot. Only `slug` is fixed here. **Four findings deliberately left open, with reasons.** The four `?? study.x` taxonomy fallbacks at `caseStudyPublicStore.ts:112-119` feed filters and facets with a live fallback the projection does not mirror, so index and detail can disagree about the same record — but a pre-Format-V1 record may depend on exactly those columns for its facets, and removing them risks dropping existing records out of the index, which the backward-compatibility requirement forbids. V-26 (`assertCaseStudySchema` is presence-only and blind to an extra column no model declares) is a drift-detection gap rather than a safety one, and failing on extra columns would break any environment carrying a legitimate one. `emphasis` is still on the wire with zero consumers, but removing a public contract field is Checkpoint C's C-8 and a coordinated breaking change, not a hardening fix. The publication re-pin hazard — a retried publish after an interleaved approval silently ships a newly-approved version, because `resolveApprovedSnapshot` takes the highest-version approved row rather than the one the caller saw — is fixed by the caller passing `snapshotId`, which is an API change. **Two behaviour changes that will bite before they help.** An already-published record whose prose names one of its own withheld repositories can no longer be republished until the prose is edited — that refusal IS the leak being surfaced — and renaming a published record now requires unpublish, rename, republish, which is the sequence that produces the audit trail a URL change should always have had. **NOT DEPLOYED.**
