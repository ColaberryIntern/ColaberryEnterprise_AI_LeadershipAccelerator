Stop the unseeded-form guard from going silently blind

2026-09-06
What changed`appSourcesAreSeeded.test.ts` finds entry points by matching `ingest?source=…&entry=…` in page HTML. Moving the three forms onto one shared `forms.js` puts that URL in JavaScript, so the guard written to stop unseeded forms would have stopped seeing the brand it was written for. It now also reads `data-form` off each `<form>`, and walks `.js` as well as `.html`, recursively, for the wrong-path check - which was still non-recursive and reading one file per app.
Verification4/4 under `jest -c jest.ci.config.ts`. Proven to bite by breaking one seeded slug in a scratch copy of the seeder: the suite failed and named the exact page and pair, `cpn-public/support\index.html posts to source=cpn&entry=champion_interest`. Restored from the scratch copy, never via `git checkout`.
Notes**A guard that stops matching does not fail, it passes over less.** `appPairs()` would have returned fewer rows and every assertion would still have been green - the same shape as the bug the test's own header describes, where it "could not see three quarters of the pages it was guarding". So a named assertion pins that the three CPN slugs are actually found, because the aggregate assertions cannot distinguish "all correct" from "nothing looked at". Checked first that every `data-form` value across all three apps is already a real seeded slug, so widening the match could not turn an unrelated attribute into a false failure.
