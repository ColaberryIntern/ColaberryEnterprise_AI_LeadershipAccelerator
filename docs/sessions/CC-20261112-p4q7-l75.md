### Why it was needed

L7.5 asks for generation time and cost. Measured on production, read only: `ai_events` holds
340,173 rows and **not one** can price a decomposition. The two figures the ticket is judged on
did not exist anywhere in the system for either path. The prior pilot report
(`docs/project-lifecycle/pilot-results.md`) names the same two gaps as the ones it could not close.

### The regression this caused, and the fix

The first attempt used a static import. `openaiInstrumented` imports `aiEventService`, which calls
`Model.init` at module load, so a static import dragged a live Sequelize model into the graph of
everything reaching these files. That broke `factoryDecomposeRun.test.ts`, whose own header states
it mocks no database because it needs none.

Fixed by requiring the instrument lazily inside the client factory, which is existing practice in
`advisorySyncQueueService`, `agentAuthorizationService` and `agentPermissionService`. Costs nothing,
because the client is memoised on first real call. The guard test now pins the laziness too, since
it is load-bearing rather than stylistic.

## 2026-11-13 (later) - The pilot ran. The figure exists now.

PR #4003 merged as `c36dd1b4` at 17:36Z. Its own image build was **cancelled** three minutes
later by the next merge, which is the known trap; the code reached production anyway inside the
later successful build of `d7c1c224b`, and production was verified to be running it before
anything was measured: all four modules show `getInstrumentedOpenAI` and zero `new OpenAI(` in
the running container's `dist`, and all five workflow ids are present.

### Baseline, taken before spending anything

Zero rows under the five new workflow ids. Proven to be a real zero rather than a broken query:
the same query shape returned twelve other workflow ids with live row counts in the same pass.

### The pilot

Authorized by Ali on 2026-11-13. Three runs of the SBP generation journey (intake questions,
then decompose) called directly on production with real model spend. **Nothing was persisted
except the telemetry rows**: both stages are pure functions of their inputs, the only `.create(`
in either file being the model call itself. The brief is synthetic and says so in its own text.

### Result, n=3, model gpt-4o

| | cost USD | duration ms | total tokens |
|---|---|---|---|
| intake questions, avg | 0.012743 | 7,847 | 3,230 |
| intake questions, range | 0.011370 - 0.014250 | 5,985 - 9,727 | 3,093 - 3,381 |
| decompose, avg | 0.026828 | 20,836 | 4,596 |
| decompose, range | 0.025147 - 0.028378 | 19,744 - 22,955 | 4,428 - 4,751 |
| **whole journey, per run** | **0.039571** | **28,682** | **7,826** |

6 of 6 calls succeeded. Zero rows carry a null cost.

### The instrument was checked against something it does not control

Wall clock was measured independently in the pilot script, because the recorded `duration_ms` is
the figure this change exists to produce and so cannot also be the thing that proves itself.
Across six calls, wall clock totalled 86,183 ms against 86,047 ms recorded: a gap of **136 ms,
0.16%**, which is the function-call overhead outside the model call. The recorded numbers are
trustworthy.

### A real property of the table, found by the first run looking like a failure

Run 1's decompose stage succeeded and its `ai_events` row was **absent** from a SELECT taken
moments later. Two explanations fitted equally: a late write, or a runtime bypass of the
instrument. A second read minutes later, with a control confirming the table was still
receiving rows generally, settled it as the first. **The telemetry write is not awaited**, so
any cost report that queries immediately after a generation under-reports it. Re-running the
pilot would have cost money and distinguished nothing.

### What this does and does not settle

It settles the existing path's cost and time. It does not produce a rival figure for the
lifecycle arm, because `composeBlueprint` makes no model call: governance adds **no model cost**,
and its overhead is validation work that has never run on a real project. The measured figure is
also a **floor**, not an average: the synthetic brief is ~900 characters against a 200,000
character cap, and prompt tokens here are mostly the fixed prompt template.
