### Why it was needed

L7.5 asks for generation time and cost. Measured on production, read only: `ai_events` holds
340,173 rows and **not one** can price a decomposition. The two figures the ticket is judged on
did not exist anywhere in the system for either path. The prior pilot report
(`docs/project-lifecycle/pilot-results.md`) names the same two gaps as the ones it could not close.

### The regression this caused, and the fix

The first attempt used a static import. `openaiInstrumented` imports `aiEventService`, which calls
`Model.init` at module load, so a static import dragged a live Sequelize model into the graph of
everything reaching these files. That broke `factoryDecomposeRun.test.ts`, whose own header states
it mocks no database because it needs none.

Fixed by requiring the instrument lazily inside the client factory, which is existing practice in
`advisorySyncQueueService`, `agentAuthorizationService` and `agentPermissionService`. Costs nothing,
because the client is memoised on first real call. The guard test now pins the laziness too, since
it is load-bearing rather than stylistic.
