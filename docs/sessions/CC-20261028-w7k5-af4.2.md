## Why two of the tests read source instead of calling code

Door 3 of the three the timer historically got in through was **threshold acceptance**. Here there
is no threshold path to close, so the only honest assertion is that none was ever written: you
cannot test a code path that does not exist. Without it, a four-hour auto-approve gets added next
quarter and every behavioural test still passes.

The second reads the import list, because a behavioural test **cannot tell an import from a
faithful copy** — both pass today, and only one of them still passes after `promotionIdentity` is
tightened. That module's own header records an omitted roster degrading every allowlist check back
to the denylist as the **fourth** instance of absence-is-not-acceptance in this subsystem, which is
why the reuse itself is worth a test.

Both matchers carry positive controls. A regex that matches nothing passes a structural test exactly
as well as clean code does.

### The driver was wrong before it was right, and the failure is worth recording

Its first version scraped jest's console output for the U+25CF bullet to collect failing test
names. Windows console encoding mangled the character, the name list came back empty, and the
driver's verdict logic — `exit != 0 AND names found` — printed **"DECORATIVE GUARD - nothing
died"** for all three doors while the exit codes and failure counts sitting next to it said
plainly that 3, 4 and 1 tests had failed.

So the tool built to detect a worthless guard was itself reporting a worthless result, and only
reading the numbers beside its verdict caught it. It now reads `--json --outputFile` and takes
`fullName` from `assertionResults`, which is encoding-proof. **A checker that cannot fail correctly
is the same defect it exists to find**, one level up.

## Two corrections made during the build, both caught by a test or a check

### The identity columns had to hold an email, or door 2 was decorative in production

They were `requested_by_identity_id` / `approved_by_identity_id`, holding an `org_members` UUID,
copied from `DeliveryChangeRequest`. That would have **disabled the guard this whole ticket is
about.** The gate judges the stored identity with `isNonHumanIdentity`, whose denylist matches
strings like `system:auto_approve_timeout` — and **a UUID passes that denylist unconditionally.**
Every unit test would still have passed, because tests supply emails.

Renamed to `requested_by_identity` / `approved_by_identity`, holding the email. It also makes the
acceptance criterion literally true: "names the approving human" is satisfied by a value a person
can read, where a UUID names nobody without a join.

### `err.name || err.constructor.name` logs the bare `Error` CLAUDE.md forbids

A controller test failed asserting `error_class !== 'Error'`. The cause is real and not the test's
fault: `name` is **inherited** from `Error.prototype`, so it is the literal string `'Error'` for any
subclass that does not set `this.name`. Being truthy it short-circuits, and the real class never
gets a chance. One forgotten line in an error class turns every log line for it generic.

Replaced with a `classify()` that prefers the constructor and returns `'UnknownError'` for a bare
`Error` — if that word appears in the logs, the surrounding code needs a more specific catch, and a
word that says so beats one that merely looks like a classification. The same hole exists in
`agentDisplayNameController.ts`; noted, not changed here.
