- [x] Portal event feed: key visibility on the CCPP `Registration` label, not a name allowlist
  - Date: 2026-08-31
  - Session: CC-20260831-9k2f
  - What changed: `backend/src/services/publicEventsService.ts` decided which CCPP
    `EventBrite_Events` rows the portal may show using a hardcoded five-pattern name allowlist
    (`PUBLIC_EVENT_LIKE`: Open House / Competition / Talent Showcase / Financial Literacy /
    Good Life). `AI Internship Presentation Event` matches none of them, so all of its
    occurrences were dropped in the `WHERE` clause before reaching the portal — the "NEXT
    EVENT" chip and `GET /api/portal/events` both read this one function.
    Replaced the rule with the CCPP event-group label the business already maintains:
    `EventBrite_EventGroups.GroupName = 'Registration'` (row ID 1), joined through
    `EventBrite_EventAccess` on `IsActive = 1`. Matched via `EXISTS` rather than a top-level
    `INNER JOIN`, because an event carries several active group rows and a join emits one
    duplicate event per row while eating the `TOP (@lim)` budget. Group name is bound as
    `@group`, not interpolated. `PUBLIC_EVENT_LIKE` is retained, OR'd, and marked DEPRECATED —
    see Notes.
  - Verification: The shipped SQL was run verbatim against **live production CCPP** from inside
    the `accelerator-backend` container. Returns **49 rows, 49 distinct EventIds (no
    duplicates)**, under the `TOP 100` cap: 13 AI Internship Presentation, 13 AI Strategy And
    Collaboration, 12 AI Friday Trends, 4 Financial Literacy, 3 Good Life, 2 CAP Competition,
    2 Data Talent Showcase. Bootcamp/COE leakage check empty — SQL After Dark, Interview Prep,
    IPBC Saturday / Mortgage Help and the four Center of Excellence meetups carry no
    `Registration` row and stay excluded, matching the original intent. Before the change the
    same window returned 11 rows and zero internship events.
    Added four tests to `backend/src/services/__tests__/publicEventsService.test.ts` asserting
    the SQL text, not just the mocked recordset. Mutation-tested both ways: interpolating the
    group name instead of binding it fails 1 test; reverting to the name-only allowlist (the
    original bug) fails 3. The 15 pre-existing tests pass against that reverted bug, which is
    why it shipped. Suite green after restore: **28 passed, 2 suites** (`publicEventsService`,
    `openHouseService`). Backend `tsc --noEmit` on workspace-local TypeScript 5.9.3 reports no
    error in either touched file (two pre-existing `@anthropic-ai/sdk` TS2307s in
    `interviewService.ts` / `runtime/anthropicClient.ts` are unrelated and come from the older
    junctioned `node_modules`).
  - Notes: The name allowlist is kept as an OR'd fallback rather than deleted, because
    **CCPP has not applied the `Registration` label to every occurrence of an already-public
    series**. Three events visible on the portal today carry no active label row and would have
    silently disappeared under a pure label rule: The Good Life Event 2026-12-03 10:00
    (`1865423113749`), Financial Literacy Workshop 2026-12-03 19:30 (`1979752147968`), Data
    Talent Showcase 2026-11-26 16:00 (`1980635179138`). Label those three in CCPP and the
    `PUBLIC_EVENT_LIKE` block can be deleted outright.
    Separately observed and NOT addressed here: there is no live upcoming `Open House` in CCPP
    at all within 180 days, so `getNextPublicEvent()`'s Open-House preference never fires and
    the chip silently falls through to "soonest anything". Worth a look given Open House is the
    Explorer signup funnel.
