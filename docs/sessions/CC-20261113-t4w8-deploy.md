## The image-build trap fired, and was caught

My merge commit `ca1c445e8` (PR #3987) landed at 14:25:03Z. The next merge landed 55 seconds
later, and GitHub **cancelled** the `Build images` run for my SHA:

```
Build images  3baea8a6c  in_progress
Build images  c4d3bf17c  completed  success
Build images  ca1c445e8  completed  cancelled   <- mine
```

Deploying at that moment would have been a registry-mode no-op, or would have served the
previous image, and the script would still have reported success. Waited for the build at the
then-current `origin/main` head instead, polling until `headSha == origin/main` **and**
`status == completed`, which is the only pair of conditions that means the image on the
registry is the code on main.

been *run*.
