## What actually happened

AF4.2 deployed cleanly: both markers verified inside the containers, host HEAD matching
`origin/main`. Then the boot log carried:

```
{"level":"error","event":"agent_domain_change_request_schema_unavailable",
 "context":{"message":"SchemaInvariantViolation: missing table agent_domain_change_requests"}}
```

A read-only query against production says the table is **there**, with all 12 columns, correct
nullability, and all 4 indexes. Zero statement-level warnings were logged, so the DDL never
failed. **The assert was wrong, not the schema.**

Two independent mistakes, either sufficient on its own:

1. **Positional bind with a nested array.** `ANY($1)` with `bind: [[...REQUIRED_TABLES]]` matched
   nothing. The sibling uses `ANY($names)` with `bind: { names }`, and eight files under
   `backend/src/db` pass an object bind.
2. **Single-column selects return RAW ARRAYS from this driver**, so `rows.map(r => r.table_name)`
   yields `undefined` even with a correct query. `normalizeNameRows` exists for precisely this and
   is now imported rather than reimplemented — its own comment records the sibling learning it the
   same way.

## The test gave false confidence, and that is the real lesson

Eighteen tests passed against this code. They staged rows as `{ table_name: '...' }` objects —
a shape this driver **never returns here**. So the mock agreed with the bug.

**A mock that returns a shape the real driver does not produce tests the mock.** The suite now
stages raw-array rows by default, keeps one case with object rows so the normalizer is visibly
doing the work rather than a lucky shape passing, and asserts the bind is named rather than
positional.

## Severity, stated honestly

**The feature was never broken.** The table is correct, so the routes, the service and the page all
work. Nothing reads the guard's return value — `server.ts` awaits it bare by design.

What was broken is the **guard**, and a guard that cries wolf is worse than no guard: it trains
whoever reads the boot logs to scroll past the one line that would have mattered. That is why this
is a same-day fix rather than a backlog item.
