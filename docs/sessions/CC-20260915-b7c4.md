- [x] Root cause: broadcast writes were last-write-wins, so a late POST left the phone one slide behind
  - Date: 2026-09-15
  - Session: CC-20260915-b7c4
  - What changed: `kitDeckScript.ts` POSTs the deck's position on every `show()` and on every diagram toggle, fire-and-forget (`.catch(function(){})`). `setBroadcast` upserted unconditionally. Two quick advances (skipping a slide, a double key-press) put two POSTs in flight; when the earlier one landed last, `session_broadcast` held slide N-1 while the projector showed N. `getPresenterNotes` then derived the arrival notes for N-1 — correctly, from the wrong index — and nothing corrected it until the next broadcast, which is exactly the diagram click. A second, phone-side variant: `tick()` fired every 2.5 s with no in-flight guard, so a slow response (every 30 s the spec cache rebuilds on the request path) could land after a faster, newer one and repaint the older slide's notes until the next poll. Fix, four parts: (1) `BroadcastState` gains `deck_id` (minted once per Present tab) and `seq` (rising per broadcast); `setBroadcast`'s `ON CONFLICT` now carries `WHERE deck_id differs OR stored seq < incoming seq`, atomic in the upsert (`broadcastConflictClause`), unconditional for a deck that sends neither. (2) The deck stamps both, aborts the superseded request via `AbortController`, and re-sends the current view every 5 s while the tab is visible, so a POST that never arrived heals without a click. (3) The phone allows one request in flight and drops any response whose `updated_at` is older than the last one painted. (4) `handleSetBroadcast` now copies `presenter_preface` through — the deck always sent it, the controller always dropped it, so the phone's documented fallback for the arrival screen could never fire.
  - Verification: `sessionLiveStateService.test.ts` +3 (stamp recognition, unstamped stays last-write-wins with no `WHERE`, stamped clause and payload); `kitDeckScript.test.ts` +4 in the vm sandbox (one `deck_id` per tab and seq 1,2,3 across three slides; superseded requests 1 and 2 aborted when 3 fires; heartbeat re-sends slide 1 with seq+1 and the same `deck_id`; no heartbeat when live is off). `tsc --noEmit` clean with TS 5.9.3. `jest -c jest.ci.config.ts` over every class-kit and live-session suite: 14 suites, 591 tests, all passing.
  - Notes: The nginx access log for the class window is not retained (access.log → stdout, container log empty for that range), so the two overlapping POSTs from tonight could not be shown; the diagnosis is from the code path, which has no other way to produce "arrival wrong, read-after-click right" with correctly keyed content. Residual: the phone still polls every 2.5 s, so the arrival notes always land 0–3 s after the slide does. Not deployed yet — needs a backend rebuild; no class today, Thursday is Session 17.
