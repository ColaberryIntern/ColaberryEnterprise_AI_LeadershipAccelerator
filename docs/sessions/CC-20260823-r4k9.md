# GATE 10 — Client Review Room (opens Checkpoint E)

- [x] **The client visibility contract: allowlist, not blocklist**
  - Date: 2026-08-24
  - Session: CC-20260823-r4k9
  - What changed: new `modules/delivery/clientVisibility.ts` — the eight nav sections, the five forbidden categories, per-object field allowlists, and `findForbiddenFields` as a tripwire.
  - Verification: a builder project object carrying `mentor_notes`, `builder_assessment`, `agent_scratchpad`, `api_key` and `stack_trace` projects to exactly four allowlisted keys; a field invented later is dropped by default; the projection builds a new object rather than mutating the source; a test asserts no allowlist contains a field that would trip the tripwire.
  - Notes: **a blocklist protects only against the fields that exist today.** Every field added afterwards is exposed by default, and the person adding it is thinking about the builder view, not about a client reading it six months later. The allowlist inverts that: a new field is invisible until someone names it, and naming it is a reviewable line in a diff. The tripwire is deliberately redundant with the allowlist — the allowlist is the control, the tripwire catches someone adding `internal_notes` *to* an allowlist. Truncation of the walk is reported as a hit rather than returning clean, because an incomplete check that answers "clean" is worse than no check.

  - Date: 2026-08-24
  - Session: CC-20260823-r4k9
  - What changed: new `models/DeliveryClientAcceptance.ts`, `services/delivery/clientAcceptanceService.ts`, and the `delivery_client_acceptances` table.
