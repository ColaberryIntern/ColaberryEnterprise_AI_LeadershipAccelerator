**ESC-2 was investigated this session and deliberately not absorbed.** The intent was to
close it as a Gate 1 prerequisite. Reading the code changed the answer, and the finding is
worth recording rather than quietly deferring:

- `tenantScopeWhere()` exists, is correct, and has **zero callers outside the tenancy
  module**. It was built and never wired — which is what "Gate 5 PARTIAL" actually means.
- The only real caller of the org services is `controllers/adminOrgController.ts`, which
  authenticates via `req.admin` and has **no `PlatformRequestContext`**. Building one
  requires resolving an admin user to a `PlatformIdentity`. The `admin_user` link type and
  `findIdentityForEntity()` both exist, so the mechanism is there.
- **But if admin users are not actually linked in production, naive fail-closed scoping
  would return `{ tenant_id: null }` and blank the live admin Organizations page.** That
  is the trap, and it is why this needs the multi-tenancy workstream's identity wiring
  rather than a scoping patch bolted on from here.

Half-doing it would be worse than not doing it: an optional `ctx` parameter that silently
defaults to unscoped *looks* like a security control and is not one. Gate 1's own tables
are scoped correctly from birth, so nothing shipped here depends on ESC-2 — but no client
organization should be created until it closes.
