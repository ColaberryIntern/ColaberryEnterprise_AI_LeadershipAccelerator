  - Notes: **The reason this exists is the interesting part.** Ali chose to hand the key over by pasting it so I could set it on prod. The Claude Code permission classifier then blocked the shell command carrying that credential - correctly, and consistently with this repo's existing note about the classifier guarding prod secret operations. Rather than re-encoding the key to slip past the guard, the guard was taken as correct and the handover path changed: the key gets typed into an admin form by the person who owns it, over TLS, and never appears in a shell history, a process list, or a transcript. That is a better outcome than the original plan, arrived at by being stopped. **Deliberately on its own branch** rather than added to #1855: that PR is already approved, and `require_last_push_approval` is on, so pushing to it would have silently discarded Ali's approval. **Still true after this merges:** nothing routes anywhere until someone actually fills the field in, and the key already pasted into a chat transcript should be rotated regardless of which path is used.
