## The boundary that shaped this phase: two writes, two owners

Reading the existing routes before building changed the design.

**A price is revenue work.** It had nowhere to live until R16, so the control is here and
posts to this surface's own endpoint.

**An outcome is program work.** `POST /api/admin/factory/qualification/:canonicalOpportunityId/outcome`
already exists, is tested, generates the private case-study and service-capability candidates
on a win or a loss, and sits behind its own `requireSection('program')` gate — a *different*
section from revenue.

So this panel **links** to the qualification workspace for the outcome rather than
re-implementing the write. Saving a click is not worth a second write path: two paths are how
a dashboard and a subsystem start disagreeing about whether something was submitted, which is
exactly the class of problem the EXPORTED-is-not-SUBMITTED rail exists to prevent. A test
asserts the link is present and that it disappears when there is no canonical id to link with.

That also means both ids travel in the payload — `deliveryProjectId` because `gov_bid_values`
is keyed on it, `canonicalOpportunityId` because the outcome route is. The reason is recorded
on the type rather than left for someone to infer.

## The form states the rule instead of letting you fail into it

The server rejects a `valueBasis` under 25 characters and the database enforces the same floor,
so a direct insert cannot bypass it. The form shows the requirement before you type, disables
save until it is met, and gives the placeholder a real example
(*"Section 2.4 of the RFP states a not-to-exceed of $450,000 over 3 years"*). A validation rule
a user discovers by submitting and receiving a 400 is a rule the product kept from them.

A flagged row warns **before** it is priced, naming its own flags, because pricing a row is
what puts it into Ram's total — and the flagged set really did contain a row named
`Snow College Adult Learner - T8 test`, a duplicated RFP, and three rows with no delivery
project. The list sorts unpriced first, then by flag count, so the rows that need a decision
and the rows that should be left alone are both at the top.

## Two of my own errors, caught by my own checks

Worth recording, because both were silent-success shapes.

**A scripted edit reported success while half-failing.** I applied six substitutions to the
page in one script; two missed because git had checked the file out with CRLF endings and my
patterns used `\n`. The script printed "patched" because the *first* replacement had matched,
so `s !== b` was true. It only surfaced because I had the script count its own substitutions
and compare against the expected total. That counter is the difference between noticing and
shipping a half-wired page — and it is the same failure mode I wrote into Phase 1's commit
message about mutation testing.

**A test claimed more than it checked.** `states the length requirement and what a basis is
not` asserted hint text that only renders once a row's form is open, which
`renderToStaticMarkup` cannot reach, and its substring embedded JSX source newlines that React
renders as a single space. It failed, correctly. Rewritten and renamed to assert only what
static markup can see, with a scope note saying so and pointing at the backend tests where the
rejection rules are actually enforced.
