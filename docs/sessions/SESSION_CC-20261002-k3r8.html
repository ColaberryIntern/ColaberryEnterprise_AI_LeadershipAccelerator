Case studies are linked to the services they evidence, as suggestions a person confirms

2026-10-02
What changedA new additive join table `case_study_service_links` plus the advisory pass, API and admin UI that fill and review it. Nothing connected the two before: `service_offerings` carried a free-text `past_performance` field, which is prose rather than a link, and no table joined a record to an offering in either direction. Many-to-many, because both directions are real questions (a bid asks a service what proves it; a record asks which offerings it supports), and it carries a STATE because a proposal is not a claim: a link is born `suggested` with the overlap that produced it recorded in `rationale`, and only a person moves it to `confirmed`. A `rejected` row is kept rather than deleted, so the same weak match is not proposed again. New files: `backend/src/db/ensureCaseStudyServiceLinkSchema.ts`, `backend/src/models/CaseStudyServiceLink.ts`, `backend/src/services/caseStudy/caseStudyServiceLinkSuggestor.ts` (pure), `.../caseStudyServiceLinkStore.ts`, `backend/src/routes/admin/caseStudyServiceLinkRoutes.ts`, `frontend/src/services/caseStudyServiceLinkApi.ts`, `frontend/src/components/admin/ServiceEvidencePanel.tsx`, `frontend/src/components/admin/caseStudy/CaseStudyServiceLinksPanel.tsx`, plus their three test suites. Wired into `server.ts` (boot, after both parents), `adminRoutes.ts` (mount), the Story Studio's TRUTH tab and the Our Services table.
