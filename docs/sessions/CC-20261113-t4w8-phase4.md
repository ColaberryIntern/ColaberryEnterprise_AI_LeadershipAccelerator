## What Ali said, and why a link was the wrong fix

He opened the deployed dashboard: **"looks good - just not connected to Revenue Room."**

The literal gap was real and one-directional: the Flow page linked to the Room and to each
card's drill-down, and the Room linked back to nothing. But the fix was not a link.

Two sidebar entries covering overlapping initiatives is the **same duplication he had already
made me collapse once** — when Commercialization and the Revenue Room each reported the same
annualized figure under a different name, which turned out to be one function printed twice on
one page. Adding a link would have left both doors open and recreated the problem in a new
shape.

And his original ask had said it plainly, which I read past at the time:

> "**The Revenue room**, I want to be able to create some type of Power BI / mermaid / Visual
> that helps explain the revenue… We want that and dashboard **at the top** so we can see the
> big picture and all the pieces that went into it."

Dashboard at the top **of the Revenue Room**. I built a sibling when asked for an upgrade.

## The redirect is not politeness

`/admin/revenue-flow` was **live in production** before it moved — Ali had it open. Somebody
may have bookmarked it or pasted it into a message. A moved page that 404s is a worse outcome
than the duplication this fixes, so the old URL resolves and a test asserts it.

## The guard, and why it reads the source

`oneDoorIntoRevenue.test.ts` asserts three structural facts: the Room renders the dashboard,
it renders it ABOVE the cards, and the sidebar has no second revenue entry.

It reads the source rather than rendering, deliberately. The regression here is a **deletion**
— someone removing the `<RevenueFlowDashboard />` line, or re-adding a sidebar entry "so it's
easier to find". A deleted render fails no behavioural test; the page just quietly looks fine
with less on it. Mutation-tested: unhooking the dashboard fails two of the eight.
