# CC-20261102-r7m3 — C5.12: one source of truth for the CTA, and a lint that can see it

## What this change does, and what it deliberately does not

C5.12 has two halves. One is structural and nobody's decision; the other is a copy decision
reserved for Ali. This change is the first half only, and it is sequenced that way on purpose
so that the second becomes a one-line edit instead of an audit.

**Shipped here:**

1. **The primary CTA now has exactly one declaration**, in the new
   `frontend/src/config/primaryCta.ts`. `frontend/src/constants/index.ts` re-exports it, so
   every existing importer is untouched.
2. **The collision is gone.** `components/membership/personaContent.ts` declared a *different*
   constant also called `PRIMARY_CTA` (`'Join The Challenge'`). It is now `MEMBERSHIP_CTA`.
   Two unrelated constants sharing that name is what made "change the call to action" a hunt
   through three files.
3. **`frontend/src/config` and `frontend/src/constants` are now inside the copy lint's scope.**
   This is the gap the ticket names: the single most-rendered instance of the banned word on
   the whole site was the CTA label, and it sat outside the thing that counts the word.
4. **The baseline records the 21 occurrences that widening scope revealed**, each annotated with
   what it actually is — advertising, a published claim owned by C0.6, or a legitimate verb
   sense.

**Not shipped here, deliberately:** no user-visible copy changed. The label still reads
`Start free`.

Two reasons, and the ticket states both. The replacement wording is Ali's call — "No card
needed" is a reassurance, not a verb, so a button cannot simply be relabelled with it. And
C10.1 is mid-measurement on checkout conversion (October 2 of 14 against July 19 of 37);
changing the primary CTA site-wide right now would make that movement unattributable and the
series would have to be marked broken at this date.

## The number went UP, and that is the interesting part

`FRONTEND_COPY_BASELINE_TOTAL` goes **264 → 285**. The file previously said the total "may only
ever go DOWN", so this needs saying plainly: **not one line of copy was added.** Scope grew from
two directories to four, and 21 occurrences that were always in the tree became countable for
the first time.

So the invariant was stated slightly too strongly. It is "may only go down **at a fixed
scope**", not "may only go down". Those are different claims, and conflating them has a real
cost: it makes widening scope look like a regression, which is a reason not to widen it, which
is how a lint keeps reporting a number better than the truth indefinitely. The header now says
this, and says the total is re-based whenever `BASELINE_SCOPE.roots` changes. Within a scope it
still only shrinks, and every per-file number is still exact in both directions.

Where the 21 live: `v2Pricing.ts` 9 · `v2Platform.ts` 5 · `claimsRegistry.ts` 2 ·
`primaryCta.ts` 1 · `v2Content.ts` 1 · `v2Services.ts` 1 · `v2Signup.ts` 1 ·
`utilityDemoScenarios.ts` 1.

Two of those are routed rather than fixed. `claimsRegistry.ts` holds `publicWording`, which is
the registry's own approved text — editing it changes a published claim, which belongs to C0.6,
not to this lint. And `utilityDemoScenarios.ts`'s single hit is "Free Up Staff", the verb sense
meaning release capacity, kept with that reason per the ticket's documented categories.

## The new test, and why it is in the backend suite

`primaryCtaContract.test.ts` enforces the thing a refactor cannot: that there is still only one
declaration. Its load-bearing assertion walks every `.ts`/`.tsx` file under `frontend/src` and
requires that `primaryCta.ts` is the only one declaring a `PRIMARY_CTA` const. That is the
regression it blocks — someone adding a second rather than importing the one that exists, which
is exactly how the first collision arrived.

It lives in the backend suite because it has to compare a frontend constant against
`FREE_WORD_RULE`, which is in the backend tree. A frontend test cannot reach across `rootDir`
to import it, so the assertion would have to be a hardcoded copy of the list it is meant to be
checking — which checks nothing. `frontendCopyLint.test.ts` reads `frontend/src` off disk for
the same reason, so the precedent is already there.

It also asserts its own floors first — the file exists, declares the constant, and the walk
found more than 300 files — because a moved file would otherwise make every "no second
declaration" assertion trivially true. That failure is not hypothetical here: the copy lint's
own first draft scanned 1 value instead of 77 and reported clean.

## What is left on the ticket

One decision, and it is the one the ticket says it cannot start without: **what the primary call
to action says.** The ticket's own proposal is a verb plus the reassurance carried separately —
button "Start now", with "no card needed" as supporting text. `CallToAction.supportingText`
exists for exactly that and is currently empty.

When that lands, the edit is `label` in `primaryCta.ts` and nothing else, then the baseline
entry for that file is deleted (not lowered — a zeroed entry must be deleted outright). The
other advertising uses in `v2Pricing.ts`, `v2Platform.ts`, `v2Content.ts`, `v2Services.ts` and
`v2Signup.ts` are a copy pass that should follow the same decision, and after C10.1 has its
reading.
