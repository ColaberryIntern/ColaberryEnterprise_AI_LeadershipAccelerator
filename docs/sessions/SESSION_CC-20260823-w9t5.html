**Make "absent from the API response" a failure, never a pass**

2026-08-23
What changed`videos.list` omits ids it cannot return rather than erroring on them, so 47 items back from 50 ids means three videos are broken. `observeBatch` iterates the REQUEST, not the response, and every missing id goes through `classifyAbsent()`, which has no code path to `HEALTHY`. An oEmbed follow-up (quota-free, and a different service from the challenged watch page) refines absence into PRIVATE / REMOVED / UPLOADER_CLOSED; when it cannot answer, the verdict stays actionable as `UNAVAILABLE` rather than silently downgrading to "unknown".
