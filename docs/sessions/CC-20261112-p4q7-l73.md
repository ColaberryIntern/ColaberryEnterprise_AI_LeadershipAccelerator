## Changes

- [x] L7.3 — recovery names why it recovered, and stops merging two different outcomes
  - Date: 2026-11-12
  - Session: CC-20261112-p4q7
  - What changed: `RecoveryOutcome.ids` (one merged array) became `requeuedIds` and
    `exhaustedIds`. Added `recoveryLogLines`, a pure function building the structured lines for a
    recovery, and `schedulerService` now writes what it returns instead of one hand-built string.
  - Verification: `claimLease.test.ts` grew from 14 to 20 tests, all passing. Two mutations run,
    each caught by exactly one test: re-merging the ids fails "without mixing the ids"; dropping
    the `reason` field fails "names a reason and a stable error class". Backend `tsc --noEmit`
    exit 0 after a planted control error proved the compiler was live. Test-file typecheck matched
    the frozen baseline in both directions.
  - Notes: the old line logged counts plus `ids: [...exhaustedIds, ...requeuedIds]`. Its own
    comment said the ids were there because "the first question asked when a lead reports a
    duplicate" is which rows were recycled, and the merged array could not answer that: a recycled
    row and a killed row were indistinguishable in it. It also never said WHY, only what happened
    to the rows. The reason is specific and now recorded: no lease renewal for longer than
    `STALE_AFTER_MS`, so the owner is presumed dead. `error_class` is `LeaseExpired`, since a
    generic Error is not a classification anything can be counted by. Two lines rather than one,
    because a requeue will be retried and an exhaustion is terminal.

- [x] L7.3 — a circuit breaker closing says so
  - Date: 2026-11-12
  - Session: CC-20261112-p4q7
  - What changed: added `circuitRecoveryLine`, a pure line builder, and logged it where the
    breaker moves to CLOSED, both from HALF_OPEN and from a tracked OPEN platform.
  - Verification: new suite `circuitRecoveryLine.test.ts`, 5 tests passing, including a control
    that the line does not imply successes it never counted.
  - Notes: HALF a defect, stated precisely. The TRIP was already handled under BC #10099862873:
    it raises a deduped `emitAlert` and logs if alerting itself fails, and this change does not
    touch it. The RECOVERY emitted nothing at all. So an operator was paged when distribution to a
    platform stopped and told nothing when it resumed, and the only way to learn posting was
    working again was to open a dashboard. An untracked platform closing is NOT logged, because
    that happens on every check of a healthy platform and would bury the real event.

## Left open deliberately

- **L7.5** and **L8.3** need production runs with model spend and production writes.
- **Known gaps recorded, not fixed**, each outside this change's blast radius: circuit-breaker
  state is process-local and a restart silently closes every breaker; `roomOutboxService` writes
  its crash-recovery reasons to a column and never logs them; `governanceCenterRoutes` PATCH
  bumps a version without comparing it, so two concurrent admins lose an update; the Mandrill,
  Synthflow and GHL webhooks have no event-id dedup although the repo has mature idempotency
  machinery elsewhere.
- **There is no shared structured logger.** A local `log()` is reimplemented across roughly 187
  files in at least five incompatible shapes, writing to `process.stdout`, `console.log`,
  `console.warn` and `console.error`. Extracting one is a real piece of work and a bigger blast
  radius than this ticket; it is named here so the next person does not rediscover it.
