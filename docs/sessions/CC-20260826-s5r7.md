prohibitions — quotes, charts, external-reference-shaped evidence — now have
shapes, and the shape is what enforces the rule.

### The seven-tab Story Studio (2026-08-26)

- [x] **AI drafting added to a system whose publish gate exists because it once shipped invented client quotations — with the quarantine, not the scanner, as the load-bearing control.**
  - Date: 2026-08-26
  - Session: CC-20260826-s5r7
  - What changed: **NOT DEPLOYED — local only.**

    **(1) The tabs, and the invariant they had to preserve.**
    `AdminCaseStudyDetailPage.tsx` opened with a documented refusal: *"The whole
    record is on one page rather than behind tabs... Splitting that into tabs
    would let a reviewer approve a record having seen a third of it."* That
    reasoning was correct, and it is reversed here because the surface acquired
    a second job — authoring — and the five steps (storyline, sources, analyze,
    draft, edit) have an order a flat scroll cannot express. **So the invariant
    is preserved by a different mechanism rather than abandoned:**
    `CaseStudyGateBand` renders the publish gate's named refusals ABOVE the tab
    strip, on every tab. Approving without having read every panel is still
    possible; approving without having seen what the gate refuses is not, which
    is the half the original comment was protecting. The browser run measures
    the band's `y` against the strip's on all seven tabs.

    **(2) The choice the brief asked to be stated: quarantine primary, scan
    secondary.** `collectNarrative` reads 15 prose paths with a closed
    five-token vocabulary, and finding A-8 recorded that several structured
    free-text fields — metric labels, `measurement.methodology`,
    `identity.programLabel`, contributor roles, `architecture.dataStores` — were
    never scanned at all. **Both responses were implemented, and the ordering is
    the decision.** QUARANTINE is primary because it is structural and
    unbounded: an AI value lives in `case_study_ai_drafts` and is not in
    `case_study_snapshots.content`, so it cannot be projected, published or
    scanned — because it is not there — and that holds for every sentence a
    model can produce, including the ones no scanner could recognise. EXTENDING
    THE SCAN is secondary because it is deterministic but bounded; it widens a
    net whose mesh is fixed. It earns its place at the point quarantine ends —
    after a human promotes a value — which is exactly when a figure in
    `measurement.methodology` becomes reachable. Relying on the scan alone would
    have been the comfortable wrong answer: a longer path list looks like more
    safety while leaving the unbounded case untouched.

    **(3) Promotion writes `human_override`, and that is not laundering.** A
    promoted draft reaches content through the existing `applyHumanOverride`
    carrying tier `human_override` and the NAME OF THE HUMAN, never the model's.
    `promoteDraft` requires an actor, has no service-account fallback, and the
    guard runs before any row is loaded. The human is not inheriting the model's
    credibility — the model never had any, which is why `ai_draft` is the
    weakest of the seven precedence tiers. The machine's part stays visible
    forever in `generated_by` and in the override note.

    **(4) Charts reference metric keys and cannot carry numbers — enforced four
    times, independently.** `CaseStudyChartSpec` has no values field (compile
    error); `chartBody` is `.strict()` (400 naming the key); `case_study_charts`
    has no values column (the write throws); and a contract test greps the DDL,
    the model and the type with non-vacuity checks. Remove any one and the
    invariant stands. **This deviates from `STORY_ASSET_MODEL.md`'s Class-B
    recommendation and the reason is stated in-source:** the constraint that
    matters is "no values", and a column that does not exist is a stronger,
    machine-checkable guarantee than a JSONB shape governed only by a TypeScript
    type — JSONB accepts whatever a runtime hands it; a missing column throws.

    **(5) Quotes, built last.** `case_study_quotes` carries the
    `CaseStudyContributor` consent union, and the union is expressed a second
    time as a SQL CHECK (`cs_quotes_named_requires_consent`) so it holds against
    the direct SQL that promoted this record's artifacts in the first place —
    a real path, not a theoretical one. There is **no generate control on the
    quote panel and no `generateQuote` in any client or route**, asserted by
    both the suite and the browser run. `suggestQuoteSlots` returns positions
    and reasons and never words. If nothing is approved, the block does not
    render, and the panel says so — because an author filling an empty band to
    avoid a gap is the exact pressure that produced the original incident.

    **(6) Storyline is structurally unpublishable, not merely forbidden.** It
    lives in `case_study_storylines`, which is neither `case_studies` nor
    `case_study_snapshots.content`. The public projection reads snapshot content
    plus a typed allowlist and never loads that table; `collectNarrative` walks
    snapshot content and so never scans it. There is no expression in either
    module that could evaluate to a storyline. Publishing one is not refused; it
    is unreachable. The generator reads it and is proved by mutation never to
    emit it as a proposed value.

    **(7) D-0, the artifact promotion path.** The complete set of application
    writes to `case_study_artifacts` was two `findAll` and one `create`
    hardcoding `status: 'candidate'`. There was no `update` and no route, so
    **the entire hero, carousel and figure surface could not populate through
    the application at all** — this record's three approved artifacts were
    promoted by direct SQL. `setArtifactStatus` closes it, is idempotent
    (`outcome: 'unchanged'` on a repeat), refuses the approved-but-private
    contradiction, and exposes `status`/`visibility` but **never `presentation`
    or `artifact_type`** — evidence-vs-atmosphere is derived and must not become
    an editorial field.

    **(8) The analyze step reuses `analyzeRepository` unchanged** and adds the
    half it does not carry: `cannotProve` is required by the type and non-empty
    by construction on every path including failure, because an analyze step
    that lists twenty findings and no limits reads as a completed investigation.

  - Notes:
    - **The frontend baseline was already red.** Before any change: 6 suites /
      10 tests failing (`linkIntegrity`, `claimsRegistry`, `AgentDetailPage.smoke`,
      `intersectionObserverMock`, `HomeV2`, `PlatformV2`). None is a Case Study
      suite and none was touched. That is the bar this session had to not make
      worse, and it is recorded so a future reader does not read "green" into it.
    - **Two real bugs were found by the two harnesses, not by the code.**
      (a) The browser run caught that the dashed frame marking AI prose **was
      not rendering**: Bootstrap 5.3's `.border` utility is
      `border: ... !important`, which outranks an inline declaration, so the one
      visual signal separating generated text from verified fact was a plain 1px
      solid line. Every unit test passed, because jsdom applies no stylesheet.
      This is the third failure class in `STORY_STUDIO_TEST_PLAN.md` §1.3, on
      the surface that has already shipped three invisible-text contrast bugs.
      (b) Mutation testing caught an assertion that **could not fail**:
      `toContain('updatedAt: false')` over the raw model file was matching a doc
      comment reading *"`updatedAt: false` is therefore load bearing"*, and
      passed with the option deleted. It now strips comments first and carries a
      non-vacuity check proving the stripping removed that sentence.
    - **The first mutation harness was itself broken and did damage.** It
      restored with `git checkout -- <file>`, which (i) silently refuses
      untracked files — so mutations to the 27 new files stayed applied while
      `git diff --quiet` on an untracked path returned 0 and printed
      "byte-exact" over a mutated tree — and (ii) for the one tracked file
      edited this session, reverted it to HEAD, deleting the `collectNarrative`
      extension rather than the mutation. All five affected files were repaired
      and re-verified. The harness now captures original BYTES before mutating
      and compares buffers afterwards.
    - **`published-vs-draft diff` is mapped to the SOURCES tab, not PUBLISH.**
      Conceptually it belongs beside publish; mechanically it is rendered by
      `CaseStudySyncPanel`, which also owns `sync history`. Rendering that panel
      on both tabs would put duplicate `data-testid`s on one page. The map
      records where the control IS, never where it ideally belongs, and the
      PUBLISH tab carries a note. Splitting that component is deferred.
    - **The draft generator is deterministic, behind a model-shaped seam.** No
      LLM is called, no provider SDK is imported, and `generatedBy` reports
      `deterministic` on screen. Every safety property belongs to the STORE and
      the SEAM rather than the engine, so the governance is proved by tests that
      cannot flake and a model drops in at `DraftEngine` without changing a rule.
