- [x] C127: on an iPhone, tapping any typing box zoomed the page in and left it zoomed
  - Date: 2026-11-15
  - Session: CC-20261029-f4w2
  - What changed:
    - **Found:** this continues the C126 phone audit, going past page width into tapping and typing.
      - Measured on production at iPhone width (390px), as a real Explorer learner through read-only View as member.
      - Every typing box in the funnel used text under 16px:
        - sign-up, sign-in and Open House: 15px;
        - the campus "Where to?" search on every portal page: 13.5px;
        - the Settings dropdown: 14.5px.
      - iPhone Safari zooms the page in when a box under 16px is tapped, and it does not zoom back out.
      - Result: 16 of 17 pages failed.
    - **Fix (`frontend/src/styles/responsive.css`):**
      - One site-wide rule: below 768px, every input, select and textarea is `16px !important`.
      - Checkbox, radio, range, color and file inputs are excluded.
      - Desktop sizes are unchanged.
      - The viewport meta is unchanged. `maximum-scale=1` would also block pinch zoom, which low-vision users need.
    - **View-as banner (`ReadOnlyBanner.tsx` + `responsive.css`), admin-only:**
      - On a phone it showed the full sentence on 4 lines (96px) and covered all 10 top-bar buttons.
      - Below 768px it now shows `READ ONLY · <email> · employee tools hidden` on one line.
      - That line still says employee tools are hidden, which keeps the AF2.7 explanation on screen.
    - **`scripts/auditPhoneView.js`:**
      - It also reports typing boxes under 16px.
      - It exits 1 on them.
