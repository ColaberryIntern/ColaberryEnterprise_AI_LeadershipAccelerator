## To post for real, when you choose to

1. **Deploy first** only if you want the scheduled version later; the script itself needs no
   deploy. The plain-JS scripts are **not in the container image** (it ships `/app/dist` and no
   `/app/src`), so they are copied in:

       scp backend/src/scripts/postInternArtifacts.js backend/src/scripts/lib/internArtifacts.js \
           backend/src/scripts/lib/internArtifactComment.js backend/src/scripts/lib/internArtifactSync.js \
           backend/src/scripts/lib/agentRoster.js root@95.216.199.47:/tmp/

   then `docker cp` each into `/tmp/af107/` and `/tmp/af107/lib/` (one `cp` per file — a shell
   loop gets mangled on the PowerShell-to-ssh path).

2. **Dry run again** and read it:

       docker exec accelerator-backend node /tmp/af107/postInternArtifacts.js

3. **One agent first.** Do not start with all seven:

       docker exec accelerator-backend node /tmp/af107/postInternArtifacts.js --only platform --send

   Open Ellis's ticket and look at the comment.

4. **Then the rest**, if that looked right:

       docker exec accelerator-backend node /tmp/af107/postInternArtifacts.js --send

5. **Confirm acceptance 2, the update-not-duplicate rule.** Run `--send` a second time
   immediately: it must post **nothing**, because every fingerprint matches. Then have one intern
   change one document, and run again: that one document posts an update and the other five stay
   silent.

## Telling the three outcomes apart

| On the ticket | What it means |
|---|---|
| A document excerpt | That document is in the repository now |
| "This document is no longer in the repository" | It was posted before and has since been deleted. The earlier excerpt is history |
| "could not be read" plus a reason code | The platform could not reach the repo. **Nothing from the document was posted** |

The third row is the ticket's third acceptance line. An unreadable repository and an absent file
are never reported as the same thing, because one means "push your work" and the other means
"we have a problem at our end".

## Rollback, and why the order above matters

**A posted comment cannot be retracted by this code.** Nothing in this repository edits or deletes
a Basecamp comment, and this change does not add that. So recovery from a bad run is you deleting
comments by hand across up to seven tickets.

That is the whole reason `--send` is opt-in, the dry run comes first, and step 3 does one agent
before seven. A **wrong-but-posted** comment self-corrects on the next run, because the content
changed and an update posts. The unrecoverable case is a comment that should never have been
posted at all, and the sequence above is designed so you see one before you get seven.

There is no schedule to disable, by design.

## Known limitations

- Only the six `RESEARCH_DELIVERABLES` paths are read. A document an intern puts anywhere else is
  invisible to this.
- A document over 100KB is excerpted and says so; the repository keeps the whole thing.
- The comment body is forced to ASCII, because this route has corrupted UTF-8 before. Accented
  characters in an intern's document are dropped from the excerpt, not from their file.
- Nothing is scheduled. Each run is a decision someone makes.
