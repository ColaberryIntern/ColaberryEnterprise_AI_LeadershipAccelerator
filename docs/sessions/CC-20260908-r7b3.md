  - Notes:
    - **Ali reported the Colaberry copy had no diagram. Measured before fixing:** Enterprise draws a
      1646px mermaid SVG; Training and AI Flotation drew **zero**. The API served `diagramSource` on
      all three the whole time, so this was a renderer gap, not missing data.
    - **Two different root causes.** The training site's `architecture()` normaliser dropped
      `diagramSource` at the boundary and had no field for it. The AI Flotation shell is
      dependency-free vanilla JavaScript and had no diagram handling at all.
    - **Why an image and not mermaid on each site.** Enterprise draws mermaid by importing it from
      `cdn.jsdelivr.net` at runtime. `training.colaberry.com` serves `script-src 'self' ...` with no
      CDN in it, so the same import is refused there. The alternatives were to add `cdn.jsdelivr.net`
      to a public site's CSP for a formatting fix, or to bundle mermaid into that repo — a new
      dependency and about a megabyte for one chart. Its `img-src` is `'self' data: blob: https:`, so
      an image needs neither. Enterprise keeps its live interactive chart.
    - A flowchart renders tall and narrow (776 x 1434 here), so both new stylesheets cap the width,
      centre it and let it scroll inside its own box rather than pushing the page sideways.
    - **The rendered image is deliberately NOT an artifact row.** It would land in the artifacts
      carousel at screenshot aspect ratio, which is the failure the build-case-study skill warns
      about, and it would compete for the cover.
