## The fourth occurrence of the same trap

The contract test's own header records three prior instances: content-media (2026-09-15), the gov
qualification ZIPs (2026-10-02, and again 2026-10-05 when `attest-zip` was added after the block
and missed the list), and the build-lab artifact upload (2026-10-12), which reached students.
This is the fourth.

## Ten upload routes are still capped at 1 MB

Removing this entry leaves **ten** routes in `KNOWN_UNRAISED`, each with a multer cap well above
1 MB and therefore unable to accept a real file today. They are listed in the test as a deliberate
decision list, not a suppression list. Seven are learner-facing:

| Route | Multer cap |
|---|---|
| `/api/portal/submissions/:id/upload` | 50 MB |
| `/api/portal/curriculum/lessons/:lessonId/notebooklm-upload` | 50 MB |
| `/api/portal/internship/documents/:documentType/signed` | 25 MB |
| `/api/portal/runtime/cards/:cardId/certificate` | 15 MB |
| `/api/portal/certifications` | 15 MB |
| `/api/portal/community/upload` | 8 MB |
| `/api/portal/runtime/cards/:cardId/field-guide` | 5 MB |
| `/api/strategy-prep/:token/upload` | 50 MB (public token flow) |
| `/api/admin/accelerator/submissions/:id/upload` | 50 MB (staff) |
| `/api/admin/flotation/intake/document` | 15 MB (staff) |

This PR deliberately does **not** raise them. `nginx/` is escalation territory under `CLAUDE.md`,
and the authorisation here covered the reported route. Each of the others wants its own decision,
particularly the two 50 MB learner upload paths, where a student submitting anything real will hit
the same wall with the same uninterpretable error.
