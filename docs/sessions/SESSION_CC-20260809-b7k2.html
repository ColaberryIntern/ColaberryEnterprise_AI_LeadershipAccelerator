**Dropped an invalid unique index that had been silently truncating every student build to 3 tasks, made the import transactional, and stopped the frontend swallowing the failure**

2026-08-09
What changedAudited the live "Projects → Start a new build" pipeline for concurrent-cohort load (Ali's question: "can this run 20+ times around the same time and still perform successfully?") and found a live 100%-failure defect. `student_tasks` carried `student_tasks_unique_req_key`, a **non-partial** `UNIQUE (project_id, requirement_key)`. But `generateSkeleton` (frontend `projectsStore.ts`) legitimately emits three tasks citing `R2` and two citing `R3` — one requirement is fulfilled by many stories, by design. So `importProject` raised a unique violation on the 4th task, the route 500'd, and `projectSync.mirrorToBackend`'s bare `catch {}` made a 500 indistinguishable from "feature flag off". Fix, three parts: (1) `DROP INDEX IF EXISTS student_tasks_unique_req_key` added to the existing `ensureStudentTaskMergeSchema()` boot path in `server.ts` (the convention here — there is no global `sequelize.sync`), with a comment stating why it was never valid; the model's index list drops the unique and keeps a plain index on `requirement_key`. Task identity is `(project_id, story_id)`, already enforced by the partial unique `student_tasks_unique_story` created two lines above it. (2) `importProject` now wraps the whole plan in one `sequelize.transaction` with the transaction threaded through every `findOrCreate`/`update`, and reads the resulting tree only after commit — previously a throw left a half-written project (exactly the 3 tasks + 2 lists sitting in prod) that a retry could not repair. (3) `projectSync.ts`'s three bare `catch {}` blocks now distinguish 404 (API flag-gated off — still quiet) from anything else, emit a structured JSON error line with `error_class`, and notify an `onSyncFailure` subscriber so the UI can surface a retry (the surface itself is r0/STORY-003, not in this PR). Also shipped three planning docs: `docs/BUILD_PIPELINE_AUDIT.md` (F-1..F-6), `docs/BUILD_PIPELINE_REQUIREMENTS.md` (SBP-REQ-v1: 22 FR / 5 NFR / 3 SAFE / 5 REL / 4 OBS), `docs/BUILD_PIPELINE_RELEASES_AND_STORIES.md` (5 releases, 20 stories, each with a ten-section Claude Code prompt that names the requirement docs by resolvable repo path + signed URL; traceability gate PASS).
