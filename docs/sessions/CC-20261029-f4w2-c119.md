# CC-20261029-f4w2: C119, record exactly where a learner leaves a video

Basecamp: https://app.basecamp.com/3945211/buckets/7463955/todos/10493820271

- [ ] C119: Send a final watch beat when the learner leaves the page, so the exact exit point is recorded
  - Date: 2026-11-10
  - Session: CC-20261029-f4w2
  - What changed:
    - `VideoEmbed.tsx`: while a video plays, `pagehide` and `visibilitychange` to hidden flush the buffered watch time at once, passing `{ exiting: true }` as `onWatchBeat`'s second argument.
      - A pause that arrives after the page is already hidden is an exit too.
      - Ordinary beats stay one-argument, unchanged.
    - `portalApi.ts`: new `keepaliveConfig(exiting)` returns axios `{ adapter: 'fetch', fetchOptions: { keepalive: true } }` for an exit, so the request survives unload and still carries the Authorization header (`sendBeacon` cannot set headers). It returns `undefined` otherwise.
    - `runtimeApi.watch` / `mediaWatch` take an optional `exiting`. `CardDetailBody` (the drawer) and `TimelineCard` (the Today tile inline player and the ambient media beat) pass it through.
  - Verification:
    - New `VideoEmbedExitBeat.test.tsx`, 9 tests. They cover:
      - an exit under 15 s, which was never sent before;
      - visibility hidden as an exit;
      - no double-send when both events fire;
      - ordinary beats staying one-argument;
      - a pause while hidden counting as an exit, and a pause while visible staying ordinary;
      - listeners being removed on unmount;
      - `keepaliveConfig`.
    - Together with `useMediaBeats` and `VideoWinCelebration`, the run is 20 of 20 passing.
    - Mutation check: removing the `pagehide` listener and the hidden-pause rule fails 2 tests.
    - Frontend `tsc --noEmit` (TS 5.9.3; CI uses ^5.7.3) is clean, and a planted control error was reported.
    - ESLint (CRA rules) on the changed files: the same 8 problems as on main, none new.
  - Notes:
    - Why: the C118 re-analysis on 10 Nov showed all 6 quitters left in the first 30 s, but the player reported only every 15 s of play, or on pause or end. React cleanup does not run on unload, and axios XHRs are cancelled, so exits went unrecorded.
    - No server, database, nginx or compose change. The extra beat is at most 1 per exit, well under the 30 per minute rate limit.
    - Failure modes:
      - A browser without keepalive fetch support (Firefox before 133) loses only that exit beat, as before.
      - An app killed outright with no visibility event still sends nothing; that is not catchable in the page.
    - Not covered: the Today tile's podcast `<audio>` (`useMediaBeats`) keeps its pause/end flush only.
