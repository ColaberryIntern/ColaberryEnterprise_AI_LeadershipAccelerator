# Handoff — AF10.6, let an intern name their own agent

Ticket: https://app.basecamp.com/3945211/buckets/7463955/todos/10424325597

**Nothing here is live.** This was built on `workstream/af10.6-agent-display-name` and stops at an
open PR. It is not merged, not deployed, and not production-verified, and no claim below says
otherwise. The steps are what to exercise **after** you deploy.

## What changed, in one sentence

An intern can now give their own agent a name from My Domain, where that slot used to render a
raw UUID, and the name is refused if another agent already answers to it.

## Deploy note, before anything else

**Deploy backend and frontend together.** The frontend calls a route that only exists in this
same change, so a frontend-only deploy leaves the rename control calling a missing endpoint: it
**404s**, and the name cannot render because the field is absent from the response. (This is not
the `.strict()` 400 trap from the memory file — that one bites when an already-deployed strict
route receives an unknown field. Different failure, named here because this page is what gets
read while diagnosing.)

No migration. Nothing to run. The name lives in a JSONB key that already exists.

## Test it in six steps

1. **Open `/admin/my-domain`** signed in as one of the seven builders. A full admin sees only
   their own domains on this page, which is the page's existing behaviour and not something this
   change touched. If you want to watch it as an intern, use view-as.

2. **Find the "Agent" row** in the domain card. Before this change it showed a long UUID. Now it
   shows either the agent's name or **"not named yet"**, with a link beside it reading
   *name your agent* (or *rename* once there is a name). The UUID is still there, on hover.

3. **Set a name.** Click *name your agent*, type something, Save. The name replaces
   "not named yet" immediately. Reload the page and it is still there.

4. **Try "Maya" on the admissions domain, and expect to be refused.** You should get, in these
   words: *"Maya" is already taken by another agent.* This is the case the whole ticket turns on.
   An agent called **Maya already exists in production and is disabled** — measured 2026-10-28 —
   and Kalkidan chose that name. A disabled agent still owns its name, so this must refuse. The
   box stays open with "Maya" still in it so the intern can adjust it rather than start again.

5. **Try "Dara" on the curriculum domain, and expect it to be ACCEPTED.** Same shape as step 4,
   opposite answer, and that is correct: Ruth's agent row *is* the Dara row, so the collision is
   with itself. If step 4 refuses and step 5 accepts, the uniqueness rule is behaving.

6. **Try a name on somebody else's domain.** You cannot do this through the page, which only ever
   shows your own, so it is a check for later if anyone wires another caller: the API answers
   **403**, not a silent success.

## Telling a refusal from a failure

This matters because the two used to be indistinguishable on other surfaces here.

| What you see | What it means |
|---|---|
| *"X" is already taken by another agent.* | A refusal. The name is in use. Pick another. |
| *That agent is not one of yours.* | A refusal. Authorization, not an error. |
| *Could not save that name.* | A real failure. The server did not answer, or answered 500. Check the logs for `agent_display_name_set` with `outcome: "failure"`. |

Every attempt writes one structured line with event `agent_display_name_set`, the actor's email,
the outcome and, on failure, an `error_class`. The name itself is never logged, because it is user
input.

## Known limitations, stated plainly

- **The name shows on My Domain only.** The org chart and agent detail still read
  "Product Experience Agent" and the like, because they resolve names through
  `admin_users.display_name` and `agent_name`. Making this name win platform-wide reaches every
  actor-name render, which is a cross-module change this ticket does not authorize. It is the
  obvious follow-up and worth its own ticket.
- **Two interns choosing the same new name in the same instant can both succeed.** A JSONB key
  cannot carry a unique constraint, so the check is re-run inside the transaction to narrow the
  window rather than close it. With seven people naming once each, this is accepted rather than
  solved.
- **None of the seven names is stored by this change, by design.** The intern sets it; nothing
  backfills. Which means **somebody still has to tell the seven that the control exists** — that
  is **AF8.1**, it is a send, and it needs you. Flagged so a correctly-scoped-out item stays
  tracked instead of being quietly forgotten.
- The name is capped at 60 characters and must contain at least one letter, so `***` cannot become
  an agent's identity.

## Rollback

Set the name again, or clear the `display_name` key from that agent's `config`. There is no
migration to reverse and no other state involved. A boot reseed cannot clear a stored name:
`agentRegistrySeed.ts:3299` only writes `config` when it is empty, and the domain agents' registry
entries carry no `config` at all.
