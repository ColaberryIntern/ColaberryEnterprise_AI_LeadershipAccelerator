## AF12.7 - record who owns the vendored design system, and correct a directory that lies about being synced

- **Date:** 2026-11-10
- **Session:** CC-20261110-mr4a
- **Ticket:** AF12.7, https://app.basecamp.com/3945211/buckets/7463955/todos/10493692157
- **What changed:** added `frontend/src/colaberry/PROVENANCE.md` (ownership, upstream, the four
  local edits, and the R0 audit-scope consequence), and corrected the header of
  `apps/hire-refactored-public/src/assets/tokens.css`, which claimed to be vendored and kept
  current by the design-system sync when it is neither.
- **Verification:** every factual claim in `PROVENANCE.md` traces to an object read from the
  GitHub API on 2026-11-10 and is cited in the file itself: the five upstream repositories and
  their targets against the registry in `backend/src/scripts/lib/designSystemSync.js`; the
  import commit `03e3c22e` (25 Jun 2026, `amuwwakkil25`, 92 files); the four local edits
  `55d89de5`, `6da36b03`, `b53dba81`, `a61cb00a` with their files and diffs; the absence of any
  design path in `.github/CODEOWNERS`; the absence of any design-ownership clause in all seven
  `CLAUDE.md` files; and `GET /repos/.../collaborators/aleemcolaberry` returning **404**, which
  is why no `CODEOWNERS` entry was added. The `hire-refactored` correction is verified by the
  registry containing five brands and no `hire-refactored` entry, by the absence of
  `.design-sync-manifest.json` in that directory, and by `./design` being byte-identical to
  `apps/refactored-public/src/assets/design`. No automated test covers either file: both are
  documentation, one of them a CSS comment, and neither changes a rendered value.
- **Notes:** the ownership answer is Ali's ruling of 10 Nov 2026 - **Aleem owns the designs
  across all Colaberry brands, and the per-brand sources of truth are his own repositories** -
  recorded in response to the question Aleem raised on Mihret's PR #2 as the last item blocking
  his R0 sign-off.

  Three things were deliberately NOT done:

  1. **No `CODEOWNERS` entry.** `aleemcolaberry` is not a collaborator on this repository
     (404), and GitHub silently ignores a code owner without write access. The entry would have
     looked like governance and enforced nothing. Granting access is a DRI decision.
  2. **The four local edits were not reverted.** Ali's ruling settles *ownership*, not whether
     the platform may fork. Three of the four have a stated platform reason (two removed
     third-party font and icon requests that fired before consent; one added a z-index stop),
     and none changes a brand colour, type scale or spacing ramp. Reverting on my own reading
     would have reintroduced a privacy defect.
  3. **The repository lineage was left open rather than guessed.** This directory's recorded
     upstream is `github.com/colaberry/colaberry-design-system`, while the five per-brand
     systems are under `github.com/aleemcolaberry`. Design ownership is settled; how those two
     repository sets relate is recorded nowhere, so `PROVENANCE.md` states that explicitly
     instead of inferring it.

  **The finding worth carrying forward:** the pristine copy at
  `frontend/public/knowledge/design/tokens/fonts.css` still contains both `@import` statements
  that were deleted here in August, so upstream still has the privacy defect this fork fixed
  three months ago. An unowned divergence meant the fix never travelled. That is the argument
  for this file existing, and it is the one item on the page that wants action rather than a
  record.

### Failure-first notes (CLAUDE.md requires these in writing)

1. **What happens if this fails?** Nothing at runtime. One new markdown file and one CSS
   comment; no selector, property or value changes, so no page can render differently.
2. **Will it retry?** Not applicable.
3. **Recovery path:** revert the commit. Neither file is read by any code path.
4. **Failure modes handled vs not handled:** handled - a reader who needs to know who owns this
   directory, what diverges from upstream and why, and a reader who would otherwise trust the
   `hire-refactored` sync claim. **Not** handled - nothing enforces that the four-edit list
   stays current. A fifth local edit to `frontend/src/colaberry/` would make this file stale and
   no test would notice. The durable version of that guard is a test asserting the set of files
   in this directory that differ from the pristine copy at `frontend/public/knowledge/design/`,
   which is a larger piece of work and is recorded on AF12.7 rather than smuggled in here.
