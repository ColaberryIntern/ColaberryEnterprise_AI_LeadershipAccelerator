### The finding that matters more than the fix, and it is NOT in this change

**Every one of the 114 memory rows has `conversation_count = 0`, and the cause is not
identity.** All 144 chat conversations are `status = 'active'` with `ended_at` NULL. Nothing
in the frontend calls `/api/chat/close`: the endpoint exists
(`trackingRoutes.ts:101`), the controller calls `closeConversation`
(`chatController.ts:103`), and `saveConversationToMemory` hangs off it — but no client ever
invokes it, so the memory write path has never run in production.

The consequence is visible in the data: `visitor_type` across all 114 rows is 84 `new`,
26 `high_intent`, 4 `ceo`, and **zero `returning` and zero `engaged`**, because both of those
branches require a conversation count that is never incremented.

So the identity fix is correct and necessary, and it is **not sufficient**: Maya will keep
remembering nothing until conversations close. That is a frontend change outside this
ticket's stated scope, so it is reported rather than silently bundled. It is the single
highest-value follow-up on this list.
