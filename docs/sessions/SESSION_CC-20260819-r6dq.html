**Eventbrite URLs in event announcements and inboxes on AI Internship announcements render as real anchors instead of inert text students had to copy by hand.**

2026-08-19
What changedReported by Jackie Chalk (Community Organizer) by email on 2026-08-18. Community post and comment bodies were rendered as raw escaped text — `<p className="cm-post-body">{post.body}</p>` and `<div className="cm-comment-text">{comment.body}</div>` in `PostCard.tsx` — so every URL and email address in an announcement arrived as characters a student had to select and copy. Added `linkify()` to `communityUtils.ts`: a pure function returning a typed `BodySegment[]` (`text` | `url` | `email`), kept JSX-free so it stays in the module's existing dependency-free, unit-testable shape. New `RichText.tsx` maps those segments to React elements. Wired into **both** render sites, so comments get the same treatment as posts. Deliberately **not** `dangerouslySetInnerHTML`: bodies are member-authored input, so the only markup that can reach the DOM is the anchor the component constructs. External links carry `target="_blank" rel="noopener noreferrer"`; email links are `mailto:` in the same tab so the mail-client hand-off does not orphan a blank tab. Styling in `community.css`: `.cm-link` uses the file's existing `--berry` accent (#367895, 4.9:1 on the card surface, clears AA for normal text) and `.cm-link-email` adds a tinted chip so an internship inbox reads as an action rather than as prose — that chip is the "highlighted" half of Jackie's second request. Files: `communityUtils.ts`, `RichText.tsx` (new), `PostCard.tsx`, `community.css`, `communityUtils.test.ts`.
Verification`tsc` 5.9.3 clean (exit 0, zero errors) over all three changed TS/TSX files with real `@types/react` resolved. Jest: **22/22 passing, 12 of them new**, the 10 pre-existing formatter tests unchanged. The emitted DOM was verified rather than assumed — the real `RichText` component was rendered through `react-dom/server`, confirming `<a class="cm-link" href="https://www.eventbrite.com/e/..." target="_blank" rel="noopener noreferrer">` for Jackie's Eventbrite case and `<a class="cm-link cm-link-email" href="mailto:internships@colaberry.com">` for her AI Internship case. BREAK pass over 20 hostile/awkward bodies (bare scheme, `data:` URI, `<script>` payload, CRLF, unicode host, plus-alias email, 4,000-word body, whitespace-only) asserting three invariants: segments always reconstruct the original body exactly (no content can be dropped), every href is structurally `http(s):`/`mailto:` and nothing else, and no input takes over 250ms. All held.
Notes**Not merged, not deployed** — PR opened off `origin/main` for review. Naked domains (`colaberry.com` with neither scheme nor `www.`) are deliberately left unlinked: linkifying them would false-positive on ordinary prose like "Node.js" and on filenames. Jackie's workflow pastes full Eventbrite URLs, so this does not affect her cases. Trailing sentence punctuation is split off the href, so "register at https://evt.br/x." does not link the full stop, and a wrapping `)` is excluded by the matcher's character class rather than by post-hoc trimming. The matcher is a module-level `/g` regex whose `lastIndex` is reset per call, with a regression test pinning stability across repeated calls — without it the second render of the same body would silently drop links. The work was done in an external worktree because the OneDrive checkout is 2,453 commits behind `origin/main` and contains no Community code at all, and because three other sessions have uncommitted work in that shared tree.
