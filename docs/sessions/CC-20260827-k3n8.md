    **NEW DEFECT: a 403 was reported as an expired session.** `describeApiError` in
    `frontend/src/services/adminOrgApi.ts` collapsed 401 and 403 into one branch reading "Your
    session is not authorized… **Sign in again**." The surface lab and PREVIEW both answer 403
    because `CASE_STUDY_SURFACE_LAB_USER_IDS` is unset — an allowlist, not an authentication state
    — so an admin following that instruction signs out, signs back in, and gets the identical
    error. 401 and 403 are different facts: one means "we do not know who you are" (sign in again
    is the fix), the other means "we know exactly who you are and the answer is still no" (it never
    is). Split into two branches; 404 and the generic branch untouched; **no call site changed**.
    **Why nothing caught it:** the two suites that appear to cover this helper
    (`AdminCaseStudies.states.test.tsx`, `AdminBusinessAccounts.test.tsx`) both `jest.mock` the
    module and assert against a string they supply themselves, so they prove the page renders what
    it is handed and say nothing about what the function returns. The real function had no test at
    all. It has one now.

    **Also found: PREVIEW cannot choose its own surface.** SURFACES and PREVIEW share one
    `desk.lensSurface`, so leaving a gated lens selected on SURFACES makes PREVIEW preview that
    gated surface and fail. Recorded as a finding and checked on every run; the harness now
    restores the default lens after probing a gated one, for the same reason it detaches every
    repository it attaches.

    **Deliberately NOT fixed, with the remedy named.** The same helper describes every failure as a
    load failure, including writes — the forced consent-save failure read "Could not **load** this
    consent change (HTTP 500). This is a **load** failure." Fixing it properly means threading a
    read/write distinction through **24 call sites** across four modules, which is a refactor, not
    a bug fix, and CLAUDE.md's scope-lock rule says log the proposal and continue. Remedy recorded
    in the walkthrough: an optional `action: 'read' | 'write'` defaulting to `'read'`, so existing
    callers are unchanged.
