### Extraction no longer shatters a requirement on every newline, plus a deterministic requirement-item taxonomy (2026-10-15)
- [x] **`proposalExtractor` joined soft-wrapped lines so a requirement that wraps across two lines stays one sentence (the Herriman symptom), and a new `govRequirementItems` module groups each extracted obligation into one of four categories (submit / rule / scope / after_award) with its source citation, surfaced from the extract route.**
  - Date: 2026-10-15
  - Session: CC-20261015-g4w7
  - What changed: **`backend/src/services/factory/proposal/proposalExtractor.ts`** — `sentences()` took a `joinWraps` flag; for plain text and PDF (where a newline is a soft render wrap) it now rejoins a line to the previous one unless the previous line ends a sentence (`. ; :`), the line is blank, or the next line starts a list marker or heading (`isHardStart`), so a wrapped obligation is one requirement and a "...the following elements:" intro keeps its list. For `.docx`/`.xlsx` the flag stays OFF so ooxmlText's row/cell boundaries are untouched (cells never re-fuse). **`backend/src/services/factory/proposal/govRequirementItems.ts`** (new) — pure `classifyRequirementCategory` (precedence submit > after_award > rule > scope, default rule), `buildRequirementItems` (one cited item per extracted requirement; never fabricates), and `tracksForCategory`/`dueStageForCategory` (only `scope` carries `solution_build`, so `deriveGovBuildPlan` is unchanged). **`backend/src/routes/admin/govQualificationRoutes.ts`** — the read-only `/extract-requirements` route now also returns `items` (persists nothing; `candidates` stays the Raw view).
  - Verification: **Jest 53/53** on `proposalExtractor` (34, incl. 5 new Herriman tests) + `govRequirementItems` (19). **Mutation-proven**: forcing `joinWraps=false` fails 2 of the 5 Herriman tests; restoring passes all 5. No existing extraction/dossier/office-doc test changed. tsc: CI is the authoritative backend typecheck (local tsc OOMs/slow per CLAUDE.md).
  - Notes: Additive and gate-safe by construction — no migration, no change to `evaluateRequirements`, `evaluateEvidenceCoverage`, `approveGovQualification`, `classifyRequirementTracks`, or `deriveGovBuildPlan`. The taxonomy is DETERMINISTIC (the repo's "deterministic backbone, AI advisory" rule); an AI pass could later enrich titles / fill `inferred` gaps without touching gates. The map UI and the confirm-establishes path (which will add an optional `tracks` field to the establishedRequirement zod so a confirmed `scope` item reliably becomes a build story) are the next slice. Herriman has no code fixture today; the test builds one with the existing `makeZip` helper reproducing the wrap symptom. SHIPPED: PR #3128, merged + deployed to prod (marker `buildRequirementItems` verified in the running backend container).
