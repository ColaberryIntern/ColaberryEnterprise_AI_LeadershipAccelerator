## Root cause

Two independent contract mismatches on the same screen, both silent:

| Surface | Server sent | Page read | Result |
|---|---|---|---|
| `GET /api/admin/visitors/stats` | `visitors_today`, `total_visitors`, … | `todayVisitors`, `visitors30d`, … | every card `undefined ?? 0` → **0** |
| `GET /api/admin/visitors/stats` | *(nothing)* | `liveCount` | no server-side source at all |
| `GET /api/admin/visitors/live` | bare `[…]` | `res.data.visitors` | `undefined \|\| []` → **empty table** |

Neither is reachable by the type checker: the payload crosses the wire as `any`, and `?? 0` converts a missing field into a plausible number. The dashboard did not error, warn, or blank — it rendered a confident zero, which is why it survived so long.

Three smaller defects fell out of the same drift: live rows carried `visitor_id`/`duration_seconds` while the table read `id`/`session_duration`, so every row had an undefined React key and clicking one requested `/api/admin/visitors/undefined/sessions`; and the header cards were only ever fetched on three of seven tabs, so landing on the default Navigation Flow tab showed no cards at all.

- [x] Engaged visitors: separating a hit from a read, after the bot rule failed its own test
  - Date: 2026-09-04
  - Session: CC-20260903-w3k8
  - What changed: Investigating why `ai-flotation` converts at 0.23% showed the traffic is not real — 448 of 454 sessions (98.7%) under ten seconds, 431 fingerprints that never returned, five days, 110 rotating IPs, almost no user-agent variety. The obvious response was a third bot rule. **It was tested against the only ground truth available — visitors who became leads — and it caught one of them.** So it ships as an ENGAGEMENT measure rather than a bot claim: `engagedVisitorSql` marks a visitor engaged if any session exceeded ten seconds or one page, **or if they ever converted**. Both counts are reported and always reconcile to the headline.
  - Verification: 14 tests; both `tsc --noEmit` clean. Measured on production with the carve-out in place: 1,045 visitors → **337 engaged**, 24 converted, and **0 converted visitors excluded** — the false positive is gone.
  - Notes: **The finding changes the advice.** "ai-flotation converts at 0.23%" reads as a landing-page problem, and acting on it would have meant redesigning a page for traffic that was never human. Roughly 68% of all "visitors" viewed one page for under ten seconds and never came back. Conversion against people who actually looked is **~7%**, not 2.3%. **Why this is not called a bot rule:** one false positive against 24 known-real visitors is enough to say the signal does not support the word, and asserting it anyway would repeat the exact over-claim this dashboard was full of. Naming it "engaged" claims only what the data shows — that a five-second single-page visit is a hit, not a read.
