## The four decisions

**1. One narrative spine: the night shift.**
Week 5 built a helper that works while you watch. Tonight it works while you sleep.
The four protocol upgrades stop being a list and become the four things any night-shift
worker needs:

| Night shift | Protocol |
|---|---|
| 🔑 No keys of their own | sampling |
| 📞 They call in | progress + log notifications |
| 🚪 They stay on their floor | roots |
| 📋 Somebody signed the posting | transport + state |

Restated in the roadmap slide, in every architecture eyebrow (`Upgrade 1 of 4` …
`4 of 4`), and at the close. The existing "2 AM — loud or quiet?" device is kept as
the exam question and written on the whiteboard for the whole night.

**2. Prose cut 41%, slides 21 → 16.** Merged progress + log notifications into one
slide, merged demo-shaped/loud-or-quiet, folded the trust ladder into the roadmap as a
spoken line rather than its own slide, and dropped the sampling-trace autopsy (the most
abstract of the three, and the only one nothing later depends on).

**3. Four live builds → two, and the other two became teaching prompts.**
Built live: progress notifications (fast, visible, the highest-satisfaction moment of
the night) and the graded transport decision record. Logging and roots became
`kind: 'review'` prompts — the full prompt is on screen and taught line by line, with
the *reasoning written into the prompt itself as comments* (`# WHY: without the
declaration the client drops every log message on the floor…`), and the room runs them
before Thursday. This is the single biggest time saving, and it is the mechanism Ali
asked for: teaching survives on steps where building does not.

**4. The theater poll moved from minute 95 to minute 45.** The transport decision is
the best moment of the night. Authored, it sat in the `challenge` segment at minute 95
— exactly where the overrun lands, so it kept getting cut. It now fires inside
`architecture`, directly after the transport slide that briefs it. The `challenge` and
`trivia` tail is now deliberately expendable: a self-diagnosis poll and a short
knowledge check, either of which can be dropped without losing anything load-bearing.

Questions were **not** reduced (8, same as authored). They cost 1-2 minutes each and
they are what holds the room. The time came out of prose and live builds.

## The three problems, and the one cause

All three came from the same place: **the instructor's phone was reading the
deck tab's broadcast instead of the session's own content.** A deck is a static
snapshot taken when Present is pressed, so a tab opened before a change shipped
broadcasts the old shape forever.

**1. "No set-up notes for this slide."** The stored broadcast carried
`presenter_tip` and no `presenter_preface` key at all, while a freshly rendered
deck carried `data-setup` on all 41 slides. The server was right; the tab was
old. The set-up paragraph read as deleted rather than stale.

**2. Both screens showed the same text.** The fix for (1) — falling back to
`presenter_tip` — guaranteed it, because that field is what the read screen
shows. `splitScript` was also copying SAY lines and the slide's own `body` into
`setup`, so even a fresh tab echoed itself.

**3. 22 of 38 slides had no real commentary.** Teach slides carry an authored
script. Everything else is generated — segment openers, story beats, question
slides, cover, break, trailer — and each shipped one hardcoded tip reused
identically every week. Nothing in `KitConfig` could reach them.

## What was built

| Change | Effect |
|---|---|
| `KitConfig.slideNotes` | Slide id → commentary, applied last in `applyKitConfig`. Reaches every generated slide. Any week can author real commentary with a DB write, no deploy. |
| Keyed `kind:id` or `id` | Slide ids are **not unique** — the cover and the cold-open segment slide are both `cold-open-0`. Ids were left alone deliberately: **the live poll key IS the slide id**, so renumbering would orphan votes mid-class. |
| `splitScript` split | `setup` = SITUATION / ROOM / MOOD / OPEN / DO / NOTE. Every SAY line and the body move to the read screen. `OPEN` stays on arrival — it starts the slide without a pause. |
| Server-side derivation | `getPresenterNotes` rebuilds the slide from the session's `KitSpec`, located by slide **index** (not id). The broadcast is used only for *where* the instructor is. Any tab, any age, works. Cached 30s — the endpoint polls every ~2.5s and `buildSessionKit` renders a QR. |
| Four arrival colours | SITUATION violet · ROOM blue · MOOD green · OPEN gold. OPEN shares SAY's gold because they never share a screen and both mean "words you speak". |

## Two CI failures worth recording

Both were real, both caught before merge:

1. **`promptBrief.test.ts`** — three assertions encoded the old contract (setup
   carries SAY and echoes the body). That is the behaviour deliberately
   changed, so the assertions moved to the new contract rather than the
   behaviour moving back. Added the property that was actually missing: for
   every script/body shape, the arrival text never contains the read text.
2. **`sessionLiveStateService.test.ts`** — the suite stopped loading because
   importing `buildSessionKit` at module scope pulls the Sequelize models in,
   and the test mocks the DB, so `Cohort.init` ran against an undefined
   connection. The deck builder is now required lazily inside the lookup.

## Roots slide rewritten

It taught one idea — stop the server opening files outside the approved folder —
but opened in security-engineering language before explaining it. Now it defines
ROOT before using it, says plainly that naming the folder locks nothing, shows
the escape concretely (`/work/project/reports/../../../.ssh/id_rsa`), and adds
definitions for root, path traversal and symlink. The script leads with the
badge analogy and reaches the vocabulary second.

Also dropped "there is exactly one way to write it correctly" as too absolute.
Resolve-then-compare is the core rule; production also handles files that do not
exist yet, writes, links that change between the check and the open, and OS path
behaviour. The script tells the instructor to say so if asked.

## Ram was right, and the correction improves the lesson

> "In production load balancer should always send the user to the same instance…
> It will get routed to a new instance when the previously selected instance
> fails or session times out."

The deck was wrong twice. It presented **round-robin-per-request as production
behaviour** when that is the *default* setting, and it said *"the load balancer
is behaving perfectly; the assumption underneath it is the bug"* — too generous
to the infrastructure. If a stateful service needs affinity and nobody
configured it, the deployment is misconfigured too. **Two things were wrong.**

His last clause is what makes the new version better: affinity holds until the
instance fails or the session times out — so it also holds only until the next
scale-in and the next **rolling deploy**. The teaching is now:

- sticky sessions **are** the correct production fix for a stateful service
- and they make every session depend on one instance staying alive
- stateless needs no affinity — *that* is the argument, not that affinity is wrong

The diagnose poll's correct answer is now explicitly **both** causes. Its
presenter note tells the instructor to agree out loud when someone says "sticky
sessions", then ask what happens to those sessions on the next rolling deploy.

## The audit tool is the hardening

`auditClassDecks.js` grades every session by building the **rendered** KitSpec
from `getKitConfig` — the database — not by grepping source. That distinction is
the whole point: a week file can be correct while a session override supersedes
it, which is exactly how a corrected load-balancer claim survived a merge and a
deploy on 2026-09-01. Exit 1 on any hard failure, so it can gate a deploy.

## Week 8 needed a judgement call

Its subject is Claude Code automation, and four of its blocks were `claude -p`
headless invocations. **That CLI is the week's content** — converting it to "a
Claude Code prompt" would have deleted the lesson. Resolution:

- Blocks the room **builds** with: the prompt directs Claude Code to *compose*
  the headless command, justify every `--allowedTools` entry, explain what each
  flag protects against, then run it. The student sees the CLI assembled and
  never types it.
- Blocks the room only **reads**: `kind:'review'`. The anti-pattern block gained
  inline comments naming its three gaps — no tool scope, no verification, it
  ships — so it teaches while nobody runs it.

This forced an audit fix too: shell inside a review block is no longer a
violation (it renders as do-not-paste), or week 8 would have been permanently
red and the tool would have become noise.
