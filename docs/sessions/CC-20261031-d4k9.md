## Environment notes for whoever builds here next

- **This repo is an npm workspace** (`workspaces: ["frontend", "backend"]`). `npm install` run
  inside `backend/` or `frontend/` hoists to the ROOT `node_modules`; the per-stack directories
  end up with 2-3 entries. Looking for `react-scripts` under `frontend/node_modules` and
  concluding the install failed is the trap.
- **The OneDrive working tree is 4,766 commits behind `origin/main`** with 74 files of real
  uncommitted changes. Building there would silently revert other sessions' work. This work was
  done in a fresh worktree off `origin/main` at `6e790874`.
- **Its `frontend/node_modules` and `backend/node_modules` are gutted** - one entry each
  (typescript 5.9.3 in frontend, nothing useful in backend). Junctioning them into a worktree
  produces a typecheck full of false module-resolution errors that says nothing about CI. Removing
  such a junction must use a non-recursive delete (`[System.IO.Directory]::Delete($p, $false)`);
  `rm -rf` would follow the link and destroy the main tree's dependencies.
- **`playwright` is declared in the root manifest but is not installed by a plain `npm install`**,
  so a local backend `tsc --noEmit` reports 4 `TS2307` errors in files nobody touched. CI installs
  root deps and does not see them.
