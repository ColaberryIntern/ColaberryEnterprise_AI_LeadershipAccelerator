### Why the suite was failing, and what is still unexplained

`src/services/__tests__/signupWelcomes.test.ts` failed 2 tests on main (CI runs 42662920396 and
42663193985) and **passed on a byte-identical backend tree** on the branch (run 42639241242).

That identity is measured, not assumed: `git rev-parse <sha>:backend` is
`257f623538631ff417caf22583d96a8337505e05` for **both** the green branch commit `82ec77e04` and the
red main merge `70b6bf7b9`. The only difference anywhere in the two trees is 5 lines of
`frontend/.../studio.css`. So the failure is non-deterministic.

**What the failure was.** The real `reeseWelcomeService` ran despite a `jest.mock` of it. Two
independent tells, both from the CI log:

1. `order` came back `["maya"]` — the injected-by-mock reese never recorded itself, while maya did.
2. The only warning captured was `welcome_failed`, which is `reeseWelcomeService.ts:438`, in a test
   whose mock was set to **reject**. A rejecting mock would have produced
   `signup_reese_welcome_failed` from `signupWelcomes.ts` instead.

So one module mock applied and the other did not, in the same file, on the same run.

**What is NOT the cause**, each checked rather than assumed: path casing (git records both services
with the identical casing a case-exact filesystem needs); a semantic conflict with other merges (only
#3781 touches any of these files; #3783 is CSS and #3777 is video); a `__mocks__` directory (none
exist under `src/services`); and jest configuration (`jest.config.ts` has no setup files, no
`resetModules`, no `automock`, and `jest.ci.config.ts` only adds an ignore list).

**The mechanism is still unexplained, and this change does not claim to explain it.** What it does is
remove the module registry from the path the assertions depend on, so the behavior is now asserted
through an explicit argument. That is a real fix for the test's reliability, not a diagnosis of jest.
The cost is stated plainly in the suite's own docblock: nothing now exercises the default uninjected
wiring, because that is the flaky part, so two static guards cover it instead — the defaults must
still name the two real modules, and those modules must still export the functions named.

### A false clean typecheck, worth recording

`npx tsc --noEmit` in this worktree prints `'"node"' is not recognized as an internal or external
command` and matches nothing, so `grep -cE '^src/'` over its output returns 0 and reads as a clean
typecheck. It is not one — it is a typecheck that never ran. A planted control error caught it: the
error did not appear. The real invocation is the one `scripts/checkTestTypecheck.js` uses,
`node --max-old-space-size=8192 backend/node_modules/typescript/bin/tsc` (backend pins 5.9.3; the
repo root resolves 4.9.5). With that, the planted control WAS reported and the clean run is exit 0
with no output.
