## Why `kind` and not a second table

A tool request is the same governance with a different payload: a named proposer, a named human
approver, a timestamp, and no machine identity anywhere near the decision. All of that already
exists and is mutation-proven. Splitting it would mean maintaining two spines and keeping both
honest.

`DEFAULT 'change'` means every row written before this column existed keeps its original meaning
with **no backfill and no migration window** — Postgres applies the default to existing rows
without rewriting the table.

## The self-imposed obstacle, and why I narrowed the test rather than deleting it

This file's own suite asserted the DDL **contains no `ALTER`**. That was right while it only ever
created a table. Adding `kind` to a table that already exists in production makes an ALTER
unavoidable.

Deleting the assertion was the easy move and would have thrown the guarantee away. Instead it now
bans the ALTERs that can destroy or lock — `DROP COLUMN`, `ALTER COLUMN`, `SET NOT NULL`, plus
`DROP`/`UPDATE`/`DELETE`/`TRUNCATE` outright — and permits **exactly one** additive shape, asserting
that every ALTER present matches `ADD COLUMN IF NOT EXISTS`. A positive control proves there is one
to check, so the loop cannot pass vacuously.

## Two test defects this surfaced, both the same shape as earlier ones

**The assertion matched its own explanation.** The comment above the ALTER names the banned forms
in order to explain them, so an un-stripped regex matched the prose and failed on correct code.
Fixed by stripping comments first — the same trap `agentChangeRequestNoTrigger.test.ts` already
documents, met again one file over.

**Call-order mocking broke the moment a statement was added.** `stageAssert` queued three
`mockResolvedValueOnce` answers in sequence; the two new DDL statements ate the first one, so the
assert read columns where it expected tables and the guard reported a schema failure that did not
exist. Replaced with dispatch on the SQL text — a query asking `information_schema.tables` gets
tables regardless of how many statements ran before it. **A mock keyed on call order is a mock that
breaks when the code gets longer**, which is not a property worth having.
