## The two defects, precisely

| Symptom | Cause |
|---|---|
| Drawer showed "Couldn't load this week's ritual — try again shortly." | `adapt()` used `item.card_id ?? item.ref`, so a post's `community:<uuid>` ref reached `/api/portal/runtime/cards/:cardId/peer-wins`. Postgres rejected the uuid cast → 500. |
| Breadcrumb and tile chip read "COMMUNITY DISCUSSION" | `adapt()` derived the label locally with `labelFor(item.type)`, title-casing the curriculum type slug. The backend already resolves the week's ritual name (`ritualStudentLabel`); the client was not using it. |

## Deliberately not done

- **`week` is NOT stamped onto a community feed item**, though a ritual post knows its week. `isPrecedenceImpression()` reads `item.week` to sort a placed impression into the anchored vs. variety cadence tier, so setting it would silently re-tier every community post in every student's feed — a feed-scheduling change disguised as a display fix. The week reaches the student through the ritual label and the parsed post body instead. A test pins this.
