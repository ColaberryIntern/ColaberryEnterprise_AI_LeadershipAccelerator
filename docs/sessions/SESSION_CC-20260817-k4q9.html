**`POST /api/portal/sbp/builds` refused any single interview answer over 2,000 characters, on a field the student never filled in, and the portal narrated that refusal as "we could not reach the requirements service ... once you are back online"**

2026-08-17
What changedTaiwo Oludimimu (taiwo@colaberry.com) reported that running the build wizard from the start produced a starter-template banner ending `(Invalid input)`. `Invalid input` is this repo's generic Zod 400 (`sbpRoutes.ts` `fail()`), so the server was reached and REFUSED the payload; the banner reported a refusal as an outage and told him to retry once back online, which is the one action that could not help. Root cause is an internal contract mismatch, not an outage: `frontend/src/pages/portal/projects/deriveLegacyScope.ts` copies ONE whole interview answer verbatim into `users` / `data_sources` / `done_definition`, and `startSchema` capped those three at `2_000` while the `answers[].answer` field they are copied FROM is capped at `4_000`. So the real ceiling on a single interview reply was 2,000 characters, enforced on a derived field with no UI, on a wizard whose own copy says "Tell us everything ... Don't hold back". Four fixes, in two groups. **(1) The payload defect:** introduced an exported `ANSWER_MAX = 4_000` in `sbpRoutes.ts` and pointed all four fields at it so the derived fields can no longer be tighter than their own source; `deriveLegacyScope` now clamps each derived field to the same ceiling (lossless, since the full text always travels in `answers`); `ProjectWizard.tsx` gained `maxLength` on the idea, name and answer inputs plus a `Counter` that appears at 80% so the boundary is met while typing rather than after Confirm; `intakeQuestionsService.ts`'s `isQuestionShaped()` gained the missing UPPER bounds (`id` 80, `question` 500) that `startSchema` already enforced on the way back in, closing a second latent 400 where a long model-written question would have refused a build on text the student never wrote. **(2) The lie:** extracted failure classification into a new dependency-free `frontend/src/services/sbpFailure.ts` with `classifyError()` (returns a `kind` of `unreachable` / `rejected` / `server_error` / `not_enabled` / `unavailable` / `timeout`) and `describeFailure()` (title, body, action per kind). `classifyError` also salvages the server's `issues` array, which was already on the wire and which the old `toError` discarded, so the banner can name the field instead of printing the word `Invalid input`. `PipelineState`'s `local` variant now carries the whole classified `SbpError` rather than a bare message string, and the banner renders per-kind copy; only a genuine `unreachable` still mentions the network. Also closed the observability gap that hid all of this: `fail()`'s ZodError branch returns without calling `next(err)`, so no global handler ever saw a rejected build and NOTHING recorded which field failed; it now emits a structured `sbp_request_rejected` log carrying field paths and limits only, never the student's own text.
Verification**Reproduced against the deployed production artifact**, read-only, no writes and no student data: a script run inside `accelerator-backend` using prod's own zod `4.3.6` and the caps as shipped in `/app/dist/routes/sbpRoutes.js` accepts a 2,000-character answer and returns `400 Invalid input -> users(too_big)` at 2,001, while the fixed caps accept all of 500/2,000/2,001/2,500/4,000. Tests confirmed FAILING FIRST for both halves before the fix: `sbpRoutes.startSchema.derivedScope.test.ts` 2 of 3 failed with the rejected path reported as exactly `"users"`; `sbpFailureHonesty.test.ts` 8 of 11 failed against a restored copy of the original `toError` + single-banner behaviour; `deriveLegacyScopeLength.test.ts` 2 of 4 failed with the clamp removed. All 19 pass with the fix. One assertion was tightened after the failing-first run exposed it as weak: "does not tell a 400 to come back once they are online" passed against the ORIGINAL code because "back online" lived in the action line, not the body, so it now asserts on `copy.action`. Regression: `jest src/routes/__tests__ src/services/sbp/__tests__` 770 passed / 772; the 2 failures (`projectRoutes.test.ts`, `enrollmentRoutes.test.ts`) are unrelated to every changed file and were proven to be full-run resource contention by re-running each in isolation immediately after (5/5 and 4/4 passed). `tsc --noEmit`: frontend clean, exit 0, zero output; backend clean for both changed files (the 15 backend errors are all pre-existing `Cannot find module 'axios'/'playwright'` junction artifacts in unrelated openclaw/inbox files).
