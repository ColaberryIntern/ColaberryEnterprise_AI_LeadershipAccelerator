## Findings

### 1. The plan said to seed the catalog into `artifact_definitions`. Measured, that is unsafe today.

The reasoning in the plan was sound on its face: the table already holds `file_types`,
`validation_rule` and `evaluation_criteria`, so no new vocabulary table was needed. What the
plan could not have known is how that table is read.

**Twelve** call sites read `artifact_definitions` with no `where` clause at all, and **eight**
more pass a `where` that cannot be read from the source. Every one treats a row there as a
curriculum artifact a student owes. Eleven catalog rows inserted today would therefore make
every active student appear to be missing eleven artifacts, would drop every completion
percentage the platform reports, and would move a bare `count()` on the health report with no
visible cause.

So the catalog ships as reviewed data in git, which is the better home for a vocabulary anyway:
eleven rows in production can be changed by anyone with a psql prompt and leave no diff. The
seeder exists, is idempotent, is dry run by default, and **refuses** to write while
`CURRICULUM_READERS_SCOPED` is false. That constant is not a promise: the reader-scope test
re-derives the answer from the source tree on every run and fails if the constant and the tree
disagree in either direction, so the only way to open the latch is to actually scope the
readers.

Scoping twenty readers is a change with real behavior risk on curriculum and analytics
surfaces, and A0's premise is that it changes no behavior. It is therefore named, not folded
in. Nothing needs those rows until a consumer has to resolve a type from the database.

### 2. My own first count of those readers was wrong, in the flattering direction.

The first inventory said eight, taken from `grep | head -30`. The real figure is twenty.
Among the sites the short list missed were `deepReconciliationService` and a bare
`ArtifactDefinition.count()` on the health report, which is exactly the kind of reader whose
number moves with nothing to point at. The inventory is now derived from the source on every
test run and the comment in the module is explicitly a copy for a reader, not the authority.

### 3. The schema has two implementations, on purpose, with the drift tested rather than promised.

The publisher is plain CommonJS run from `.claude/skills/story-build/scripts`; the platform is
TypeScript. The single-implementation options were both rejected: a comment asking people to
keep two files in step fails silently, and reaching the TypeScript from the publisher needs
`ts-node`, which **is not a declared dependency of either workspace** and exists in this tree
only hoisted from somewhere else. (Worth noting separately: `backend`'s own `seed:*` scripts
already depend on that accident.)

So both implementations run over one shared fixture corpus in
`contractValidatorParity.test.ts`, which compares refusal codes, refusal detail and what each
resolves, and fails by name on the case that disagrees. The *data* is not duplicated at all:
both read the same catalog file.

### 4. The plan generator lives in another repository, so A0 could only meet part of that line.

"Add the artifacts block to the plan generator's output" cannot be done here:
`gen_story_plan.py` runs the six-stage pipeline out of the AI Project Architect repo. What A0
does instead is give the contract a home that works today, `artifacts.by_story` in the story
config, which the publisher merges onto the plan's stories, with the story's own block winning
if the generator ever emits one. A contract can be authored and enforced now without waiting
on the other repository.

### 5. Two refusals that exist because of specific past failures, recorded so they are not relaxed later.

`"artifacts": []` is refused, separately from an absent block. Absent is not empty: a story
with no contract has not declared one, while a story declaring zero artifacts is claiming
everything is handed over and handing over nothing. That is the same hole closed in the
lifecycle coverage gate the week before, where an empty list posted by the caller satisfied a
governance check.

An unrecognised field is refused rather than ignored. The block ends up in a ticket a person is
judged against, so a misspelled `repo_paths` that every reader quietly skips would publish a
contract that does not say what its author meant, with no way for the author to find out.

## What A0 does not claim

- No row was written to any database, and nothing was deployed.
- Nothing consumes the contract to decide completion. A1 renders it into the Basecamp ticket;
  A2 verifies it from the repository. A0 is schema and vocabulary only.
- No story on any live board has a contract yet. A0 makes one possible, not present.
- Quality is still a human judgement. The gate's job is to prove a document of the right kind
  exists at the right place; `evaluation_criteria` is the sentence a person judges it by and is
  deliberately not scored by a machine.
