# Session CC-20260831-9k2f — Events v2: registration, counts, nav collapse

**Date:** 2026-09-01

**Scope:** Five follow-ups on the Events page — registered events marked on the calendar,

**NOT DEPLOYED.**

---

- [x] Per-viewer registration + real signup counts on the public events feed
  - Date: 2026-09-01
  - Session: CC-20260831-9k2f
  - What changed: `OpenHouseView` gained `signup_count: number | null` and
    `is_registered: boolean`. The CCPP query now carries a correlated
    `COUNT(DISTINCT a2.Email)` subquery against `EventBrite_EventAttendees`;
    `annotateRegistration()` + `getRegisteredEventIds()` layer the viewer's own
    registrations on per request, and `handleGetPublicEvents` resolves the learner's
    email from `Enrollment` to call it.
  - Verification: Ran the shipped SQL against **live production CCPP**: 48 rows, 48
    distinct ids (the subquery does not duplicate events), 2.3s cold. 4 events carry a
    badge; the other 44 render nothing. **Cross-checked against the legacy training site:
    Financial Literacy returns 14, exactly the blue badge the old page shows** — the raw
    attendee-row count is 30, so `COUNT(*)` would have shown an inflated number. The
    parameterised registration lookup was exercised against a real attendee email and
    marked 1 of 40 events. Backend suites green at **41 passed** (was 32). Backend and
    frontend `tsc --noEmit` clean.
  - Notes: `is_registered` is deliberately NOT folded into the module's shared 10-minute
    event cache — that array is served to every viewer, so a per-person flag written into
    it would leak one learner's registrations to the next request.
    `annotateRegistration` therefore copies rather than mutates, and a test asserts the
    caller's objects are untouched. `signup_count` is a real count or `null`; `null` means
    "not known" and renders no badge, while `0` survives as `0`. Nothing here fabricates a
    number — the same rule the dead `todayFeed.ts` builder records after its hardcoded
    `likes:` values were removed.

- [x] Sidebar: two destinations per group, rest behind "More"
  - Date: 2026-09-01
  - Session: CC-20260831-9k2f
  - What changed: `NAV_PRIMARY_COUNT = 2` and a pure `splitNavGroup()` in `PortalShell.tsx`,
    with a `.te-navmore` toggle per group and per-group expansion persisted to
    `localStorage`. Groups reordered so the first two are the requested defaults: Your day
    = Today, Schedule; Build and learn = Classroom, Projects; Belong = Community, Rooms.
  - Verification: 10 new tests in `__tests__/splitNavGroup.test.ts`, all passing, including
    assertions that pin the three requested default pairs and that no destination was
    dropped from the overflow.
  - Notes: Two behaviours that are easy to get wrong and are covered by tests. First, when
    the ACTIVE page lives in the overflow the group force-opens — otherwise a learner on
    Path or Portfolio sees no highlighted item anywhere and cannot tell where they are.
    Second, when the whole rail is icon-collapsed every item renders and the "More" control
    is hidden by CSS; without that the overflow items would be unreachable in that mode.

- [x] Upcoming events strip on Today
  - Date: 2026-09-01
  - Session: CC-20260831-9k2f
  - What changed: New `UpcomingEventsStrip.tsx` + `.css`, rendered in `TodayShell.tsx`
    directly above the timeline feed. Shows the next 3 events with their date, title, a
    "Registered" tag where it applies, and a "See all" link.
  - Verification: Frontend `tsc --noEmit` clean; reuses the already-tested
    `formatEventWhen` helper.
  - Notes: Deliberately a self-contained strip rather than event cards injected into the
    cursor-paginated `/api/portal/runtime/today` engine. That engine owns curriculum
    ordering, dedupe and Feed Control / CAPE governance, and events are neither curriculum
    nor ambient content; injecting a new card type there is a much larger, governed change.
    Operator chose the strip. It renders NOTHING on empty or on fetch failure rather than
    showing an apologetic box on the main page.
