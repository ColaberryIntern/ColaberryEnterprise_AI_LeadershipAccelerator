How the Growth Journey OS works

One person arrives. The system reads them, decides what should happen next, and records that decision. Only the last gate can cause anyone to be contacted — and it is closed.

1 · The whole system, left to right

A person enters on the left. Each box is a thing that happens; each padlock is a switch that has to be open for the next box to run. Today every padlock is shut, so nothing moves past the first one.

a person thinking, records only a human's queue can contact someone 🔒 a switch that is off

Five switches sit in series. The one on the far right is the only one that can reach a person.

2 · What has to be true before anyone is contacted

Nine checks in order, every time, for every person. The first one that says no stops it — and names itself in the record, so you can always find out which.

Every refusal is recorded by name. "It did nothing" is never the answer you get — you get which check said no.

3 · The five settings, least to most active

Each brand × programme × channel sits at one of these. There are twelve such combinations and all twelve are at the far left.

Ali's own outreach is pinned at review permanently — it can be stopped from the screen and cannot be started from it.

4 · The twelve switches, as they are right now

Four brands, three channels each. Read live from production on 4 October 2026 — this is not an illustration.

This grid comes from the same code the sender asks. It is what the next run would do, not a guess.

5 · What is actually standing in the way

The system scores its own readiness at 13%. The useful part is which items are blocked — because they are not all switches.

Two conditions already pass: the emergency stop row exists, and the database indexes are present and valid.

6 · The rule that must never break

Each brand sells different things. The system refuses to offer one brand's product inside another brand's journey, and a refusal always beats a permission.

If an AI Flotation lead asks about business training, the system refuses the offer and refers them to Colaberry Business rather than selling what that brand does not have.

7 · How it chooses what to send

Two separate choices, and they are easy to confuse. First which action, decided by a sort. Then which message, decided by what is approved for that brand.

The fourth sort key looks like pedantry and is not: without it two equal candidates would order arbitrarily, the same input would stop giving the same output, and the idempotency everything else depends on would break silently.

8 · And here is what the screens look like

Real components with realistic data, so the shapes above have faces. Production is empty, so these states cannot be photographed live.

The one thing worth staring at. Near the top: acceptance rate 0.0% — 0 of 12, and directly beneath it expiry rate — with "no handoff was created in this window". 0% means every handoff was refused: a crisis. The dash means none existed: a quiet week. A screen that printed 0% for both would tell you the opposite of the truth.

The queue your staff would live in. The first row has no ticket and says why — the queue is at capacity. The second row's reason reads "redacted", because it held an email address and was masked before it reached the screen.
