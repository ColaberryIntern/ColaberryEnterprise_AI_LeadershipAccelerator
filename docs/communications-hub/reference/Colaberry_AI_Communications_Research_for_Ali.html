Executive recommendation

  • Build the AI Communications Manager page inside enterprise.colaberry.ai now, independently of the WhatsApp provider. Start with AI drafting, group/audience selection, approval, event assets, community publishing, and a reliable scheduler.
  • Pilot WhatsApp sending using a separate company-controlled mobile number and internal test group. Whapi.Cloud is the simplest hosted provider to evaluate for existing ordinary WhatsApp groups, but it is unofficial and carries account-restriction risk.
  • Do not connect the critical Colaberry office landline to an unofficial integration until a controlled test succeeds and Ali explicitly accepts the risk. Nothing is sent or published without Jackie's approval.

WhatsApp API options

  • Meta official Groups API: officially supported, but as of November 19, 2026 its reported requirements include an Official Business Account, API-created invite-only groups and a maximum of eight participants. It does not provide a practical way to automate Colaberry's existing large ordinary student groups. Business-app numbers cannot simply be used with this Groups API.
  • Whapi.Cloud: hosted linked-device API; group discovery, group IDs, text/media and webhooks. Advertised price approximately $29 per connected number per month ($348 for twelve months at that rate). Trial and sandbox restrictions apply. Unofficial integration.
  • WAHA: self-hosted, open-source WhatsApp HTTP API with group and media functionality. More control, but Colaberry maintains hosting, updates and session reliability. Unofficial WhatsApp Web-based integration.
  • Evolution API and WPPConnect: open-source options with group messaging functionality; require more technical ownership and, for WhatsApp Web-based operation, carry similar unofficial-integration risk.
  • Decision: test Whapi.Cloud first for speed, retain a provider-neutral backend interface, and reassess Meta's official capabilities as its eligibility and limits change.

Page specification and user workflow

  • 1. Jackie creates an event or announcement: title, audience, topic, date/time, registration URL, optional flyer and message type.
  • 2. AI drafts one or more messages using approved Colaberry tone. Drafts remain editable and cannot trigger sending.
  • 3. The system proposes destinations: Enterprise community audiences and/or WhatsApp groups synchronized from the connected provider. Show human-readable group names while storing provider group IDs.
  • 4. Jackie reviews exact message, media, destinations and delivery time; edits or rejects; explicitly approves the final plan.
  • 5. An approved item is published immediately or stored as a scheduled job. Scheduled delivery runs on the server even when the browser is closed.
  • 6. The dashboard displays Draft, Approved, Scheduled, Sending, Sent, Partially Failed, Failed and Cancelled states, plus a searchable history and emergency pause.
  • 7. If an event changes or is cancelled, pending messages can be cancelled or revised and must be reapproved if content or recipients change.

Technical architecture for Enterprise

  • Frontend: authenticated staff page within the existing Enterprise application; do not assume its framework until the repository is inspected.
  • Backend: API endpoints for campaigns, event assets, AI drafts, audience/group sync, approval, schedules, delivery status and audit records. Never expose provider tokens in browser JavaScript.
  • Data: campaigns, event details, draft versions, groups and IDs, destinations, approval records, scheduled deliveries, delivery attempts, provider message IDs, audit logs and media references.
  • Scheduler: durable database-backed queue/worker using America/Chicago timezone with daylight-saving awareness; per-group delivery IDs, idempotency protections, bounded retries, rate limits and failure alerts.
  • Connector abstraction: listGroups(), sendText(), sendMedia(), getMessageStatus(); mock implementation first, Whapi.Cloud second. Keep the Enterprise community publishing integration separate.
  • Security: existing Enterprise login, role-based permissions, server-side secrets, encrypted credentials, audit trail, destination allowlists, duplicate-send prevention, global pause, and clear access revocation.
  • Policy: send only relevant messages to appropriate groups, respect opt-outs and group rules, and obtain explicit management approval for the unofficial-provider risk.

Delivery roadmap

  • Release 1 — Dashboard and mock mode: event entry, AI message drafts, approval, audience placeholders, audit trail.
  • Release 2 — Enterprise community: integrate approved posts and flyers with the existing community, subject to authorized API access.
  • Release 3 — WhatsApp pilot: separate company-controlled number, test group, Whapi.Cloud account, group sync, text/media test sends and logs.
  • Release 4 — Scheduling and controls: durable scheduling, recurring reminders, cancellation, retries, emergency pause, delivery status and alerts.
  • Release 5 — Production decision: security review, consent/communications policy, pricing confirmation, provider risk acceptance, landline verification if desired, and phased rollout.

Pilot acceptance checklist

  • Group names and IDs synchronize correctly from the company test account.
  • An AI draft can be edited, rejected and approved; unapproved messages never send.
  • Approved text and flyer reach only the selected test group.
  • A scheduled message sends while the browser is closed; timezone is correct.
  • Duplicate attempts do not cause unintended repeat sends; errors are visible.
  • Cancelled campaigns do not send; global pause stops pending delivery.
  • All approvals, recipients, message versions and delivery outcomes are auditable.
