The scope, in one line

Ship the engagement engine first (infinite scroll + rotation + interact-to-hide), on top of a Surface structure that makes adding future content types — external AI feeds, community, groups — a drop-in, not a re-architecture.

1The one idea that makes it all work

Give every card two axes instead of one:

Type = what it is (blog, lesson, project task). You already have this — the 36-type registry.

Surface = where it belongs todayclassprojectcommunitygroup — the new dimension, declared at the curriculum-type level so new types inherit it automatically.

2The one-way valve

This enforces your "not the other way around" rule structurally:

                 ┌───────────────────────────────────────────────┐
   TODAY  ◄───────┤  Class    Project    Community    Group          │   anchored, today_eligible=true
   (aggregator)   └───────────────────────────────────────────────┘    → mirrored INTO Today

   TODAY  ◄─────────  Blog   Podcast   Testimonial   (future: Article)     ambient, home = today
                                                                            → Today-ONLY, rotated

   Class / Project / Community / Group  ◄──  only their OWN cards.
                                             Never ambient. Never each other's.
  • Today aggregates everything eligible: all ambient cards (rotated) plus anchored cards flagged today_eligible.
  • Anchored surfaces stay pure — a Class shows only class cards; a Project shows only its tasks. Enforced in typed code, not convention.
  • Ambient is Today-only — blog / podcast / testimonial can only live in a timeline. Structurally impossible elsewhere.

5The engagement engine (ships first)

A new Today Feed Composer produces a bottomless, per-user stream.

Cursor pagination → infinite scroll

Anchored cards are finite and exhaust; ambient cards are bottomless. When class work runs out, the feed goes pure-ambient and never ends. A per-user feed seed + cursor makes every page reproducible — scroll up/down or refresh gives the same feed, no dupes (also satisfies the repo idempotency gate).

Rotation, alternation & cadence

Reuse the existing pickers (unseen → least-recently-seen → tag-match). No two same-type ambient cards in a row; round-robin blog → podcast → testimonial, weighted by pool depth. Ambient injected every N slots between anchored cards; pure ambient once anchored is spent.

Interact-to-hide + card-level dedup (the missing piece)

Open / click / dismiss a card → it's retired and a fresh one takes its slot; it won't reappear until the whole pool is exhausted. This is the "show/hide so no duplicates" behavior you described — the one part genuinely absent today.

The extension point (why "structure first" pays off)

Standardize blog/podcast/testimonial behind one AmbientProvider interface. Adding your external AI feed later = ingest a pool + implement that interface + set home_surface=today, feed_mode=ambient. The composer picks it up automatically — no re-architecture.

// new ambient types plug in without touching the composer
interface AmbientProvider {
  slug: string;                                  // 'blog' | 'podcast' | 'article' ...
  pickNext(enrollmentId, ctx): AmbientItem | null;  // exists today
  recordSeen(enrollmentId, item, cardId): void;     // *_views UPSERT (exists)
  recordInteraction(enrollmentId, item, action): void; // interact-to-hide (new)
  poolDepth(enrollmentId): number;                  // alternation weighting
}

6Data model changes — additive, low-risk

  • curriculum_type_definitions + registry: add home_surface, feed_mode, today_eligible. Seeded idempotently from the registry.
  • timeline_cards: generic home_kind + home_id (locates project/community/group homes — the stub for those surfaces) and surface_override for per-card exceptions.
  • New today_feed_impressions: powers card-level interact-to-hide + stable pagination.
  • Add a dismiss action + generic "interacted" signal for ambient cards.

All additive columns/tables with defaults → no migration risk. Each new table gets an ensure*Schema() hook.
