Build Spec — Presence / Peer Chat

BUILD_SPEC §9 #8 · Engineer: Kes Delele · Design: Aleem (approved) · Approval: Ali (pending) · P2 — post 7/13 launch

Overview

Adds real-time presence awareness and 1:1 peer chat to the Community page. Gated P2: does not block the 7/13 P0 launch. The existing poll-based Member.presence field stays for launch; this WebSocket layer replaces it afterward.

WhatDetail
Online indicatorsWho's-online roster on Community page + compact count badge on portal topbar (all pages)
Peer chat1:1 direct messaging between cohort members — no group chat in v1
TransportWebSocket — Socket.IO recommended (handles reconnect, rooms, heartbeat). Raw WS acceptable if reconnect logic is hand-rolled.
Scale target v1One cohort (~20–30 concurrent connections). No sharding, no Redis adapter needed at launch.

Presence thresholds (server-derived)

Heartbeat: client pings every 30s. Server marks socket offline after 65s without ping (5s grace above the threshold).

StateConditionDot color / token
OnlineHeartbeat received within last 60s● Leaf green — --leaf #77BB4A
Away61s – 5 min since last heartbeat◐ Amber — --amber #E8920C
Offline>5 min, or appear-offline set○ Neutral — --n400 #B4B4B4

Activity context is coarse + opt-in: page-level labels only ("In Week 7 lab", "Reviewing feedback", "Watching a lesson") — never exact URLs. Students can hide activity via the appear-offline toggle.

Presence state machine

// Server-side record per active connection type PresenceSession = { enrollment_id: string; // UUID socket_id: string; status: 'online' | 'away' | 'offline' | 'invisible'; last_heartbeat: Date; activity: string | null; // coarse label, opt-in }; // Client emits every 30s socket.emit('presence:heartbeat', { activity: 'In Week 7 lab' }); // Server broadcasts to cohort room on state change io.to(`cohort:${cohort_id}`).emit('presence:update', { enrollment_id, status, activity }); // Client-side status derived from last_heartbeat delta function deriveStatus(lastSeen: Date): 'online' | 'away' | 'offline' { const delta = Date.now() - lastSeen.getTime(); if (delta <= 60_000) return 'online'; if (delta <= 300_000) return 'away'; return 'offline'; }

Message delivery states

StateUICondition
Queued⏳ clock iconClient offline — stored in IndexedDB, auto-replayed on reconnect in send order
Sent✓ single grey tickServer received — peer client not yet confirmed
Delivered✓✓ double leaf-green tickServer confirmed peer client received

Failed messages show "Couldn't send · Retry" inline. No read receipts in v1.

Idempotency: client generates a UUID per message before sending. Server does INSERT ... ON CONFLICT (id) DO NOTHING — replayed messages on reconnect are safe to re-emit.

Disconnection & failsafe

Fail-soft on disconnect: UI shows last-known presence state (not "everyone offline"). A "Reconnecting…" banner appears. Outbound messages are queued in IndexedDB and replayed in send order on reconnect. Socket.IO's built-in exponential backoff handles reconnect (max 5 attempts, cap 30s delay). After 5 failed attempts, show "Couldn't send · Retry" per queued message.

// Auto-queue messages while disconnected socket.on('disconnect', () => { store.dispatch(setConnectionState('reconnecting')); // Subsequent sends go to IndexedDB queue instead of socket.emit }); socket.on('reconnect', async () => { const queued = await idb.getQueuedMessages(); // ordered by created_at for (const msg of queued) { socket.emit('chat:send', msg); // idempotency key: msg.id (UUID) await idb.removeQueued(msg.id); } store.dispatch(setConnectionState('connected')); });

Data model (PostgreSQL)

-- Presence sessions (ephemeral; could move to Redis in future) CREATE TABLE presence_sessions ( id UUID PRIMARY KEY DEFAULT gen_random_uuid(), enrollment_id UUID NOT NULL REFERENCES enrollments(id) ON DELETE CASCADE, socket_id TEXT NOT NULL, status TEXT NOT NULL CHECK (status IN ('online','away','offline','invisible')), activity TEXT, -- coarse opt-in label; NULL when hidden last_heartbeat TIMESTAMPTZ NOT NULL DEFAULT now(), UNIQUE (enrollment_id, socket_id) ); CREATE INDEX ON presence_sessions (enrollment_id); -- Chat messages (persistent) CREATE TABLE chat_messages ( id UUID PRIMARY KEY, -- client-generated for idempotency sender_id UUID NOT NULL REFERENCES enrollments(id), recipient_id UUID NOT NULL REFERENCES enrollments(id), body TEXT NOT NULL CHECK (char_length(body) BETWEEN 1 AND 4000), delivered_at TIMESTAMPTZ, -- set when peer socket confirms receipt created_at TIMESTAMPTZ NOT NULL DEFAULT now() ); -- INSERT ... ON CONFLICT (id) DO NOTHING → idempotent replays CREATE INDEX ON chat_messages (sender_id, recipient_id, created_at);
