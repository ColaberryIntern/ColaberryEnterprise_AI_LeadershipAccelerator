The Basecamp shape (from your last five builds)

Where it lands: one setting

  • Default: a new list in Ali Personal.
  • When you say so: its own project (public like Colaberry Live, or with a team like MAPLOCA or Comms Hub). Same build, same shape.
  • Or a new group added to an existing list, for a new round of the same product (as Campus did).
  • Docs & Files: a folder per build with "01 - Build kit" and "02 - Screenshots", plus the Build Contract. A project also gets READ FIRST and MASTER INDEX documents.

The list

  • Groups: XX0 Control (stage the kit, contract and plan audit, standing log), then the releases, then MILESTONE APPROVALS (Ali).
  • Tickets: VS1.3 🤖 [AI] outcome or 🧑 [Human]. Every one dated and assigned.
  • 🤖 ticket sections: run line, What, Why, Inputs, Repository facts, In scope, Out of scope, Acceptance, Tests (happy, failure, boundary, repeat), Verification commands, shared contract, Close-out.
  • 🧑 milestone tickets: lettered questions, a default for each, only you tick them.

How the three gaps close

Gap 1: one name, on every tab

  • kit-to-ladder becomes the one engine, with a target setting: Ali Personal list (default), own project, or a group on an existing list.
  • It is installed where every tab can see it, not only on the main branch.
  • The button starts it, so nobody has to remember its name.

Gap 2 and 3: close-out and keep going

  • One shared close-out step: build the visual and document HTML, turn both into PDFs, post them with the HTML and a TAKEAWAY comment, close through the hook.
  • The loop picks the next ticket by date on its own after each close, and after each release, until the list is empty or a real blocker appears.
